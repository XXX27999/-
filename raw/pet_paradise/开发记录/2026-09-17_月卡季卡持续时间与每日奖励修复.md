1. 打工月卡持续时间错误
2. 打工月卡每日领取奖励不到账
3. 打工季卡持续时间错误
4. 打工季卡每日领取奖励不到账

`ISSUE_LOG.md` 2026-09-16 条目已记录「打工月卡持续时间错误、每日奖励不到账」，当时的处理是把月卡每日逻辑从 `MonthlyCardAndSeasonCard` 移到 `PlayerGetMSCard`。**本轮日志证明该修复只覆盖了月卡，季卡四项症状全部仍在，且月卡仍有两处缺陷。**

## 二、根因（2 组，均有一手日志证据）

### 根因 A（月卡 + 季卡共有）：购买当天被当作「已消耗日」，并用礼品顶替当日每日奖励

`Script/gamemode/PlayerGetMSCard.lua` → `OnBuyMonthOrSeasonCard`：

- 月卡分支在 `SavedMonthlyDateStr ~= NowDateStr` 时执行 `NewMonthlyCard = NewMonthlyCard - 1`（30 → 29），
  同时发放 `8310012 打工翻倍卡 + 8310005 基础托管卡`（**每月1日礼包**）作为「当日奖励」，
  并把 `MonthlyCardGetTime` 置为今天 → 当日真正的每日奖励 `8310009 全能营养剂` 从此不再发放。
- 季卡分支同样执行 `NewSeasonalCard = NewSeasonalCard - 1`（90 → 89），
  当日只调用 `SeasonCardBenefitHelper.GrantDailyOfflineIncomeHours`（离线托管 8 小时），
  **漏发当日每日奖励 `8310013 完美打工卡`**，并把 `SeasonalCardGetTime` 置为今天。

结果：买完立刻少 1 天（29 / 89，与 GM 菜单与商品口径的 30 天 / 90 天不符）；且当天的每日奖励被顶替/漏发。

### 根因 B（仅季卡）：季卡每日逻辑所在的 Action 脚本从未被加载

`Script/gamemode/MonthlyCardAndSeasonCard.lua` 是唯一实现「季卡天数按天递减 + 每日完美打工卡 + 离线托管时长」的地方，
但该模块**不在运行时加载的 battle 模块清单内**：

- `battlemodulerequire` 加载成功清单（2026-09-17-16.54.11 客户端会话，共 149 个去重模块）中，
  `gamemode` 系列只有 `ControllerExitGame / ExpLevelUp / PetActorDic / PlayerExitGame / PlayerGetMSCard / PlayerLogin / StatusChange`，
  **没有 `MonthlyCardAndSeasonCard`**。
- 全量日志（08-28 与 09-17 所有会话）中 `【MonthlyCardAndSeasonCard+Execute】` 打印 **0 次**。

结果：季卡天数永不按天递减（永远停在 89，卡不会到期）；每日完美打工卡与每日离线托管时长永不发放。

## 四、修改（`Script/gamemode/PlayerGetMSCard.lua`，5 处；`MonthlyCardAndSeasonCard.lua` 1 处注释）

| # | 位置 | 修改 |
| --- | --- | --- |
| 1 | `OnBuyMonthOrSeasonCard` 月卡分支 | 购买当天改为发放**当日每日奖励** `MONTHLY_CARD_DAILY_ITEM_ID(8310009) × Count`，并补 `月卡购买当日每日奖励发放` 日志 |
| 2 | 同上 | 移除 `NewMonthlyCard = NewMonthlyCard - 1`，只保留 `MonthlyCardGetTime = NowDateInfo`（标记今日已领取但不扣天），保证 30 天完整 |
| 3 | 同上 | 每月礼包 `8310012/8310005` 由「无条件发放」改为「仅当购买当天为每月1日且自然月去重键未命中时发放」，与 `Execute` 每月1日逻辑同口径 |
| 4 | 季卡分支 | `GrantDailyOfflineIncomeHours` → `GrantDailyBenefits`（补发当日 `8310013 完美打工卡` + 离线托管）；移除 `NewSeasonalCard = NewSeasonalCard - 1`，保证 90 天完整 |
| 5 | `Execute` 末尾 | 新增**季卡每日分支**：`SeasonalCardGetTime` 跨日判定 → 天数 -1 → `SaveCardArchivePatch("DailySeasonalCard")` → `GrantDailyBenefits` → `OnSeasonalCardChanged`（带 `GameState` 空值保护与 `pcall`）。与 `MonthlyCardAndSeasonCard` 通过 `SeasonalCardGetTime` 日期互斥，将来启用该 Action 也不会重复发放 |
| 6 | `MonthlyCardAndSeasonCard.lua` 页首 | 写入迁移说明，标注该 Action 当前未挂入动作表、保留仅为兼容 |

### 修改后的口径（可核对的期望行为）

| 场景 | 期望 |
| --- | --- |
| 购买月卡 ×1 | 天数 0+30 = **30**（不再变 29）；当日发 `8310009 ×1`；当日不发每月礼包（除非恰为每月1日） |
| 购买季卡 ×1 | 天数 0+90 = **90**（不再变 89）；当日发 `8310015 ×1 + 8310003 ×1`（购买礼包）+ `8310013 ×1 + 离线托管 8h`（当日每日权益） |
| 次日起登录 | 月卡：`-1` 天 + `8310009 ×1`；季卡：`-1` 天 + `8310013 ×1 + 离线托管 8h` |
| 每月1日（有有效月卡） | 额外发 `8310012 ×1 + 8310005 ×1`，按 `YYYY-MM` 去重 |

## 六、待确认 / 需决策

1. **月卡购买当天不再发每月礼包**：依据 `UGCObject` 行 1020 `ItemDesc`（仅承诺「每日可免费领取 1 次全能营养剂」，未承诺购买即送每月礼包）
   与商业化测试用例「每月1日自动发放」口径收紧。若需求方希望「购买即得当月礼包 + 1 日再发」，需回退本项（补丁 3）。
2. **购买当天不扣天数**：口径为「30 天 = 购买日 + 后续 29 天，共 30 次每日奖励」。若需求方要求「购买当天算第 1 天且显示 29」，
   需回退补丁 2 / 4。
3. `MonthlyCardAndSeasonCard` 是否应正式挂入关卡动作表（若挂入，本轮的 `Execute` 季卡分支与之互斥、不重复；但保留两份实现属重复代码，建议二选一）。
4. `MonthlyCardAndSeasonCard` 是否应正式挂入关卡动作表：**本轮判定为「不需要」** —— 季卡每日逻辑已迁移到已加载的 `PlayerGetMSCard:Execute`，
   两者通过 `SeasonalCardGetTime` 日期互斥；原脚本保留仅为兼容。若将来挂入，则属重复实现，建议届时删掉其中一份而非并存。

### 已核对、无需改动的项（含一次被过期 JSON 误导的更正）

- **`UGCObject` 行 1021（打工季卡）`ItemDesc` 已经是含每日权益的新文案**，无需再改。MCP 实测回读：
  `ItemDesc = "打工收益卡+高级托管卡各1；收益永久+50%、经验+60%；每日送完美打工卡1张+离线托管8小时"`（48 字符）。
- **更正**：本文档初稿曾依据工程内 `_JsonOutput\Asset\Data\Table\UGCObject.json` 判定「1021 ItemDesc 未含每日权益」——该 JSON 是**过期快照**
  （旧值 `"打工收益卡 1 张 + 高级托管卡 1 张；所有打工区域基础收益永久 + 50%，打工经验永久 + 60%"`）。
  此即项目规则「`_JsonOutput` 不得作为确定性依据」的又一次实证：资产表内容必须用 MCP 回读确认。
- 行 1020（打工月卡）`ItemDesc = "所有打工区域基础收益永久 + 20%，打工经验永久 + 30%每日可免费领取 1 次全能营养剂"`（47 字符）：
