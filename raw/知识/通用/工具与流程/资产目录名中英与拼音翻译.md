## 一、为什么需要翻译

绿洲工程的资产目录与文件名是**英文、拼音、缩写三种风格混用**的实际状态，例如：

| 实际命名 | 风格 | 含义 |
| --- | --- | --- |
| `AuctionPropSelectUI` | 英文驼峰 | 竞拍道具选择界面 |
| `UGCTemplateRowStruct_AuctionPropTable` | 前缀 + 英文 | 表格行结构模板：竞拍道具配置表 |
| `ZhuJieMian` | 全拼音 | 主界面 |
| `JiaGe_JingBi` | 拼音 + 下划线 | 价格金币 |
| `ShanDian_CWJB` | 拼音 + 缩写 | 闪电-宠物金币部 |
| `M416_Orange` | 型号 + 英文 | M416 橙色 |
| `LobbyMain_UIBP` | 英文 + 类型后缀 | 大厅主界面 |

直接看树会读不懂，尤其在资产量上百之后。翻译引擎要解决的就是把上表左列稳定映射到右列。

## 二、判定顺序（顺序错了会丢译名）

```
1. 完整名精确表 names          DressControlTable → 装扮方案表
2. 前缀表 prefixes             UGCTemplateRowStruct_ → 表格行结构模板
3. 按 _ - 空格 切分成段，每段依次走：
     3.1 整段精确表 segs
     3.2 英文词表 words（原样 / 全大写 / 首字母大写 / 全小写 四种变体）
     3.3 拼音词级表 PY_WORDS（原大小写优先，再全小写）
     3.4 型号 / 专有代号判定 → 保留原文
     3.5 驼峰分词后的窗口匹配：
           英文最长窗口（4~2 词） → 拼音最长窗口（3~2 词） → 单词表 → 拼音
4. 拼接后叠词合并 + 中英交界补空格
```

**关键约束：3.2 与 3.3 必须排在 3.4 之前。**

反例（实测踩到）：`FX`（特效）、`GM`、`ID`、`CWJB`（宠物金币部）都是
3~6 位全大写缩写。若先做型号判定，它们会被"保留原文"分支吞掉，
明明词表里有译名却显示成英文。

---

## 三、拼音识别必须有「不像英文」的硬约束

无约束的音节切分会把常见英文词切成合法拼音：

| 英文词 | 无约束切分结果 | 误译 |
| --- | --- | --- |
| `orange` | `o` + `ran` + `ge` | 哦让鹅 |
| `purple` | `pu` + `rp` + `le`（`rp` 不合法，偶发） | — |
| `damage` | `da` + `ma` + `ge` | 打马个 |
| `banana` | `ba` + `na` + `na` | 把那你 |

### 实测有效的三条约束

1. **原串长度 ≥ 4**
2. **音节数 ≥ 2**（单音节交给词级表处理）
3. **每个音节长度 ≥ 2 —— 禁用单字母音节 `a` / `o` / `e`**
   （它们在英文里极常见，在拼音里只出现在极少数词，禁用收益远大于损失）

### 另一条独立约束：单字母 token 不参与拼音

`M16A4` 经驼峰切分得到 `M` / `16` / `A` / `4`，其中 `A` 的小写 `a` 是合法音节，
会被译成「啊」→ 结果「M 16 啊 4」。因此**长度 < 2 的 token 一律不做拼音识别**。

### 根本解法仍是补英文词表

约束只能挡住一部分。真正有效的是把高频英文词收进词表，让它们走英文分支。
按项目实测，优先补这几类：

- **颜色**：Orange / Purple / Blue / Green / Red / Yellow / Black / White /
  Gray / Grey / Pink / Brown / Cyan / Gold / Silver
- **方位与程度**：Top / Bottom / Left / Right / Center / Inner / Outer / Front / Back
- **动作与状态**：Open / Close / Show / Hide / Enable / Disable / Lock / Unlock
- **界面与容器**：Lobby / Menu / Panel / Frame / Slot / Grid / Tabs / Popup
- **玩法通用**：Level / Stage / Phase / Round / Score / Rank / Reward / Task

## 四、型号与专有代号：保留原文，不要硬拆

枪械与装备型号在中英文里写法一致，翻译反而更难读（`M416` 译成「M 四一六」没意义）。

```python
_MODEL_RE       = re.compile(r"^(?:[A-Za-z]+[0-9]+[A-Za-z0-9]*|[0-9]+[A-Za-z]+[A-Za-z0-9]*)$")
_UPPER_TOKEN_RE = re.compile(r"^[A-Z]{3,6}$")
```

命中即 `return seg`（返回原文）。覆盖范围：

| 类型 | 实例 |
| --- | --- |
| 含数字的字母数字混排 | `M416` `M16A4` `UMP45` `M249` `MK14` `MK47` `QBZ95` |
| 3~6 位全大写缩写 | `AKM` `AWM` `SKS` `QBZ` `SCARL` `FAMAS` `UIBP` `SDK` |

**后缀类缩写建议映射为空串**（在整段表里写 `"UIBP": ""`），拼接时自动跳过，
中文名更干净：`LobbyMain_UIBP` → 「大厅主界面」，而不是「大厅主界面 UIBP」。

**例外**：`Vector`（KRISS Vector 冲锋枪）这类完整单词型号，若词表命中会优先按词表翻译；
无词表条目时自然落入型号分支保留原文。两种结果都可接受，取决于是否收录该词。

## 五、覆盖率统计不要用「中文名里还有没有字母」

型号、专有缩写保留原文是**预期行为**，用字符判会把它们计入缺口，数字虚低
（`AKM` 显示为「AKM」会被算作未翻译）。

正确做法：**在翻译过程中逐 token 计数**。给翻译函数加可选 `miss` 参数：

```python
def _translate_segment(seg, dicts, miss=None):
    ...
    parts.append(tok)                 # 落到"未识别 → 保留原文"分支
    if miss is not None:
        miss["n"] += 1

def translate_name(raw_name, dicts, miss=None):
    ...
    body = _dedupe(_join_parts([_translate_segment(s, dicts, miss) for s in segs]))

# 扫描端
miss = {"n": 0}
cn = translate_name(entry.name, dicts, miss)
if miss["n"] > 0:
    counter["untranslated"] += 1
```

这样 `AKM_Orange → AKM 橙色` 不计缺口（型号走提前返回分支，不经过计数点），
`akjsdh` 这类真正无法识别的才计入。

## 七、功能 Lua 脚本目录（`Script/Function`，v1.5.0 起）

扫描目标从 3 个扩到 4 个，新增页签与其余页签表现完全一致（总览包含、关键字筛选、
展开折叠、导出 TXT/HTML、复制到剪贴板）：

```python
SCAN_TARGETS = [
    ("表格文件夹", os.path.join("Asset", "Data"), ...),
    ("UI 文件夹",  os.path.join("Asset", "Blueprint", "Prefabs", "UI"), ...),
    ("物品文件夹", os.path.join("Asset", "Blueprint", "Prefabs", "Items"), ...),
    ("脚本文件夹", os.path.join("Script", "Function"), "功能 Lua 脚本目录（Script/Function）"),
]
```

### Lua 命名比资产命名更「长尾」

资产名多为「前缀 + 领域 + 类型」（`AuctionPropSelectUI`），脚本名则是
「领域 + 子领域 + 动作 + 层 + 服务」（`AuctionWarehouseImageMaterialService`），
**中间层的高频动词/名词最容易缺词**。v1.5.0 实测 `IslandAuctionKing` 的 47 个 Lua 文件，
补词前残留 17 个英文词，补词后 **中文名完整率 100%**。

| 补词 | 译名 | 补词 | 译名 |
| --- | --- | --- | --- |
| Feedback | 反馈 | Presentation | 展示 |
| Cell | 格子 | Continuous | 连续 |
| Loop | 循环 | Drag | 拖拽 |
| Estimated | 预估 | Filter | 筛选 |
| Grant | 发放 | Hub | 大厅 |
| Information | 信息 | Motion | 动效 |
| Navigation | 导航 | Pre | 赛前 |
| Rematch | 再战 | Replacement | 替换 |
| Usage | 使用 | Standard(s) | 规范 |
| Patch | 补丁 | Readme | 说明 |

### 专名冲突要用 `names` 精确表兜底

`Gold` 在颜色表里是「金色」，但 `AuctionGuaranteeGoldService` 在项目术语里是「保底金」。
**改通用词表会破坏颜色语义**，正确做法是往 `NAME_DICT` 加整名条目：

```python
"AuctionGuaranteeGoldService": "竞拍保底金服务",
"AuctionGuaranteeGoldUIService": "竞拍保底金界面服务",
```

判定顺序里 `names` 排第一（见第二节），因此专名优先于分词结果。

### v1.5.0 实测

`--scan` 全量扫描 `IslandAuctionKing`：10 文件夹 / 92 文件 / 4.8 MB，
**中文名完整率 98.9%**；脚本页签 47 个 `.lua` 全部译为中文（如
`AuctionWarehouseImageMaterialService → 竞拍仓库图片材质服务`），
目录内非脚本文件（`CONFIG_STANDARDS.md`、`patch1.txt`）也一并列出并翻译。
