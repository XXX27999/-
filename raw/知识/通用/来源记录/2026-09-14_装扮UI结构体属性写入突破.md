## 一、问题

`VerticalBoxSlot` 的 `Padding` 与 `Size` 在 MCP 下**无任何字符串入口可写**。

全部失败尝试：

| # | 尝试 | 报错 |
|---|---|---|
| 1 | `ue.widget_slot(wbp, n, 'Padding', '0,0,0,8')` | `widget_slot: failed to set 'Padding' on '<Name>'` |
| 2 | `slot.set_property('Padding', '0,0,0,8')` | `unable to set property Padding` |
| 3 | `slot.set_property('Padding', {...dict...})` | `unable to set property Padding` |
| 4 | `slot.SetPadding('0,0,0,8')` | `unable to convert pyobject to property InPadding (StructProperty)` |
| 5 | `slot.SetPadding(ue.FVector(0,0,8))` | 同 4 |
| 6 | `slot.SetPadding(ue.FLinearColor(0,0,0,1))` | 同 4 |
| 7 | `ue.new_object(ue.find_struct('Margin'))` | `uobject is not a UClass` |
| 8 | `ue.new_struct` / `make_struct` / `construct_struct` | 三者均 `NO_MAKER`（不存在） |

## 二、根因

`Padding` 是 **`StructProperty`**，形参类型为 `FMargin`。
字符串、`FVector`、`FLinearColor` 都无法隐式转换；`new_object` 的第一个参数要求 **`UClass`**，
而 `find_struct('Margin')` 返回的是 `UScriptStruct` 实例（不是类）。

## 三、解法

```python
import unreal_engine as ue

P = '/IslandAuctionKing/Asset/Blueprint/Prefabs/UI/AuctionDressUI.AuctionDressUI'
wbp = ue.load_object(ue.find_class('UGCWidgetBlueprint'), P)
by = {str(c.get_name()): c for c in list(wbp.WidgetTree.AllWidgets)}

# ---------- Padding（Margin 结构体）----------
sl = by['UIButton01'].Slot
ms = ue.find_struct('Margin')            # UObject，UClass = 'ScriptStruct'
m = ue.new_object(ms.get_class())        # 关键：必须 get_class()
# 注意：实例化后 m.properties() == []，只能 set_field，不能 set_property
m.set_field('Left', 0.0)
m.set_field('Top', 0.0)
m.set_field('Right', 0.0)
m.set_field('Bottom', 6.0)
assert m.as_dict() == {'Left': 0.0, 'Top': 0.0, 'Right': 0.0, 'Bottom': 6.0}
sl.call_function('SetPadding', m)        # 关键：call_function，不是 sl.SetPadding(m)
print(sl.get_property('Padding').as_dict())   # Bottom=6.0 ✅

# ---------- Size（SlateChildSize 结构体）----------
s = sl.get_property('Size').clone()      # 从现成值 clone 最省事
s.set_field('Value', 52.0)
s.set_field('SizeRule', 0)               # 0 = Automatic
sl.call_function('SetSize', s)

ue.objed_save_asset('AuctionDressUI', 'UI')
```

## 四、关键事实

1. **`UScriptStruct` 可用方法共 8 个**（`dir()` 与 `py:list uscriptstruct` 一致）：
   `as_dict` / `clone` / `fields` / `get_field` / `get_field_array_dim` / `get_struct` / `ref` / `set_field`。
   `py:guide uscriptstruct` **只给分组标题，不给方法名**，必须 `dir()` 探测。
2. **`Margin` 字段名**为 `Left` / `Top` / `Right` / `Bottom`；`SlateChildSize` 字段名为 `Value` / `SizeRule`。
3. **`ESlateSizeRule`**：`Automatic=0`（按期望尺寸）、`Fill=1`（按 Value 比例填充）、`_MAX=2`。
   固定像素高度用 `SizeRule=0`。
4. **JSON 里 `SizeRule` 可能看不到**：零值属性不序列化，UAssetGUI 导出的 `Size` 结构体只有 `Value`，
   这不是写入失败。
5. **`CanvasPanelSlot` 回读坐标的方式与写入不对称**：
   - 写入：`slot.SetPosition(ue.FVector2D(x, y))` / `slot.SetSize(ue.FVector2D(w, h))`
   - 回读：`slot.get_property('LayoutData').as_dict()['Offsets']` → `{Left, Top, Right, Bottom}`
     语义为 `(x, y, width, height)`，**`Right` 是宽不是右边界**
   - `get_property('Position')` 会报 `unable to find property Position`
6. **`FVector2D` 位于 `unreal_engine` 顶层**（`ue.FVector2D`），`unreal_engine.structs` 中不存在。
7. **`widget_inspect` 是快速验证通道**：输出形如
   `[Button] UIButton01 {VerticalBox (Padding: 0,0,0,6)}`，可直接读 Padding，无需解析结构体。

## 六、补充：适配层 ScaleBox 未铺满画布（同日第三轮修复）

### 症状与根因

首次写入后进编辑器查看：整棵控件树被压缩在画布左上角约 **105×50 px** 的小块内，其余区域全空。

根因是 `widget_add` 把 `ScaleBox` 挂到根 `CanvasPanel_0` 下时，
**Slot 继承 `CanvasPanelSlot` 默认值** —— 锚点 `Min = Max = (0,0)`、偏移 `100 × 30`。
ScaleBox 本体只有 100×30，其内部全部内容再被等比缩小到那个小方块。

### 修复

```python
V2 = ue.FVector2D
sl = by['DressScaleBox'].Slot
sl.call_function('SetMinimum', V2(0.0, 0.0))
sl.call_function('SetMaximum', V2(1.0, 1.0))
sl.call_function('SetPosition', V2(0.0, 0.0))
sl.call_function('SetSize', V2(1920.0, 1080.0))
sl.call_function('SetAlignment', V2(0.0, 0.0))
ue.objed_save_asset('AuctionDressUI', 'UI')
```

回读：`MIN=(0,0) MAX=(1,1) OFF={0,0,1920,1080}` ✅

### 关键事实

1. **`SetMinimum` / `SetMaximum` 是写锚点的可用入口**。`CanvasPanelSlot` 共 22 个 UFunction，
   含 `SetPosition` / `SetSize` / `SetOffsets` / `SetAnchors` / `SetMinimum` / `SetMaximum` /
   `SetAlignment` / `SetLayout` / `SetZOrder` / `SetAutoSize` / `SetAntiAdaptation` 及对应 getter。
2. **`SetAnchors` / `SetOffsets` 实际不可用**：它们要求完整结构体参数，而
   `ld.as_dict()['Anchors']` 返回普通 `dict`（无法 `clone()`/`set_field()`）；
   `SetOffsets` 的 `InOffset` 是 `StructProperty`，拒绝 `FVector2D` / `Margin` / 字符串全部形态
   （`unable to convert pyobject to property InOffset`）。**用 `SetPosition` + `SetSize` 间接完成**。
3. **`Margin` 构造存在上下文差异**：`ue.new_object(ue.find_struct('Margin').get_class())`
   在 `VerticalBoxSlot` 场景返回 `UScriptStruct`（有 `set_field`），
   但在 `ScaleBoxSlot` / `SizeBoxSlot` 场景返回 `UObject`（**无 `set_field`**）。
   **稳妥写法统一改用 `slot.get_property('Padding').clone()`**。
4. **`ScaleBoxSlot` / `SizeBoxSlot` 无锚点概念**，`properties()` 只有
   `Padding` / `HorizontalAlignment` / `VerticalAlignment` / `Parent` / `Content`；
   访问 `LayoutData` 报 `unable to find property LayoutData` 属正常。
5. **`FVector2D` 属性名是小写 `x` / `y`**；`as_dict()` 会把嵌套结构体内层也转成 `dict`。
6. **与既有蓝图的差异**：`AuctionTestUI` 根即 `ScaleBox`、`CollectibleCodexUI` 根为
   `CanvasPanel → ScaleBox`，均天然继承正确拉伸语义；`AuctionDressUI` 先建 `CanvasPanel_0` 当根
   再挂 ScaleBox，才踩到此坑。**新建适配层后必须立刻设四向拉伸，不要依赖默认值。**

### JSON 落盘核对（第三轮当时）

`CanvasPanelSlot_8`（宿主 `DressScaleBox`）的 `LayoutData`：
- `Offsets`：`Right = 1920.0`、`Bottom = 1080.0`（Left/Top 为 0，零值不序列化）
- `Anchors`：含 `Minimum` / `Maximum` 两个 `Vector2D` 子结构

> ⚠️ 上述 `Offsets` 值在第四轮已被证伪并修正为全 0，详见下一节。当时 JSON 体积 475,016 → 508,546 字节。

## 七、适配层三项参数定论（第四轮，截图证伪后修正）

**背景**：第三轮声称"已修复未铺满画布"，用户随即发来设计器截图，内容仍被挤在左上角一小块。

**证伪过程**：

1. 全树回读（`AllWidgets` 73 项）确认控件树、坐标、列表高度间距**全部正确**，
   `DressScaleBox [CanvasPanelSlot] MIN=(0,0) MAX=(1,1) OFF=(0,0,1920,1080)`。
2. 查找同工程 `CollectibleCodexUI` / `AuctionHouseSelectUI` / `ZhuJieMian` 做对照 ——
   `AllWidgets` 均返回 `TOTAL=0`（未在编辑器打开时无法枚举），对照失败。
3. 改读官方文档本体 `D:\oasis-skill-plus\docs\wiki\进阶内容\UI系统\20269_UI自适应屏幕.md`，
   拿到唯一权威参数集。
4. 逐项核对发现/确认**两处真实缺陷**。

**缺陷一：拉伸态下 `Offsets` 是四边留白语义，第三轮把它当成了宽高**

`CanvasPanelSlot.Offsets` 的解释随锚点模式切换：

| 锚点模式 | Offsets 语义 | `SetSize(1920,1080)` 的效果 |
|---|---|---|
| `Min == Max`（角锚点） | `(X, Y, W, H)` | 控件就是 1920×1080 ✅ |
| `Min ≠ Max`（拉伸态） | `(Left, Top, Right, Bottom)` **四边留白** | 右侧留白 1920、下侧留白 1080，宽度压成 `父宽 − 1920` → **负值** ❌ |

第三轮写下的 `SetSize(1920.0, 1080.0)` 因此把缩放框压缩到几乎为零，
内容被挤到左上角一小块 —— 与第一轮"未铺满"症状同源，属同一机理的第二次犯案。
（本库第七节第 458 行早已记录"拉伸态按 `(L,T,R,B)` 留白解释"，第三轮未回查该条。）

**修复**：`SetPosition(FVector2D(0,0))` + `SetSize(FVector2D(0,0))` → `OFF=(0,0,0,0)`。

**缺陷二：尺寸框重载从未设置（适配链断裂）**

```
修复前：WidthOverride = 0.0   HeightOverride = 0.0
        bOverride_WidthOverride = False   bOverride_HeightOverride = False
```

官方要求 `宽度重载=1920`、`高度重载=1080`。**只写数值不写位域开关无效**，
必须走 `SetWidthOverride()` / `SetHeightOverride()`（会同时置位数值与 `bOverride_*`）。
重载缺失时，缩放框只能按子控件聚合期望尺寸（很小）算缩放比 → 比例彻底失控。

**修复后三项参数（MCP 回读 + JSON 双证）**：

```
DressScaleBox [CanvasPanelSlot] MIN=(0.0,0.0) MAX=(1.0,1.0) OFF=(0.0,0.0,0.0,0.0)
DressSizeBox  WO=1920.0 HO=1080.0 OV_W=True OV_H=True
DressCanvas.Slot HAlign=0 VAlign=0（填充）
```

JSON 侧：`Anchors.Maximum = (1.0, 1.0)`、`Offsets = {"Right":"+0","Bottom":"+0"}`、
`SizeBox` 四个重载字段全部就位。uasset 46,351 → **46,571 字节**；JSON 508,546 → **510,212 字节**。

**`ScaleBox` 枚举取值**（本来就是默认值，无需改）：`Stretch = 2`（`EStretch::ScaleToFit`）、
`StretchDirection = 0`（`EStretchDirection::Both`）。

**自证公式**：`scale = min(屏宽/1920, 屏高/1080)`。16:9 屏幕恒为 1.0 等比满屏；
非 16:9 按短边等比缩放并留边，不拉伸变形。
