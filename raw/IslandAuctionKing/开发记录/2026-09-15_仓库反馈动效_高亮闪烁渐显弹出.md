## 二、实现

### 2.1 `Script/Function/AuctionUIMotionService.lua`（新增）

- `PlayWarehouseFeedbackMotion(target)`：
  - 阶段 1 弹出 + 渐显：`TweenFloatValue(PopScale → 1.0, PopDuration, QuadOut)`，同一回调内按进度插值 `RenderOpacity`（`FadeFromOpacity → 1.0`）。
  - 阶段 2 高亮闪烁：`BindCompleted` 后启动 `PlayWarehouseFeedbackFlash`，`TweenFloatValue(1.0 → FlashMinOpacity, FlashDuration, QuadOut, MakeConfig(0, FlashCount-1, true, 0))`，即 `1.0↔FlashMin` 往返 `FlashCount` 次。
  - 阶段 3 复位：闪烁完成回调把 `RenderScale` 与 `RenderOpacity` 复位为 1。
- `StopWarehouseFeedbackMotion(target)`：kill 句柄 + 令牌 +1 + 复位，供反馈清理时调用。
- 句柄仍存 Lua 侧弱键表 `MotionState`（沿用既有方案），新增 `HighlightHandle` 与 `MotionToken`；播放前先 `StopWarehouseFeedbackMotion` + `StopPress`，避免点击缩放与高亮缩放互相覆盖。

### 2.2 `Script/Function/AuctionWarehouseFeedbackService.lua`（修改）

- state 新增 `MotionPlayed` 字段。
- `ApplyClientFeedback`：pcall 内收集 `feedbackMotionCells`（成功应用的临时反馈格），pcall 后**仅当 `MotionPlayed ~= true`** 时逐个播放并置 true —— 关键：仓库每 0.25 秒重刷会重应用反馈，没有该标记会反复重播动效。
- `ClearClientFeedback`、`SyncClientQualityMarkers`（过期品质格）、两处抑制分支、被整轮廓替代的旧品质格：恢复格子时调 `StopWarehouseFeedbackMotion` 复位，避免残留半透明/放大。

## 四、新增可复用经验

1. **工程内 `luacheck.exe` 是包装版，不可用于单文件校验**：`Plugins\UGCEditor\Resources\LuaCheck\x64\luacheck.exe` 与 `SpeedupSync\luacheck\win\luacheck.exe` 都要求 `-inputDir/-outputDir/-cmd/-logflag`，直接传文件或目录都只回「inputDir is empty」，即便按参数传目录也不产出结果文件。**替代方案**：venv 装 `luaparser`，`ast.parse(src)` 做语法校验（venv：`C:\Users\Administrator\.workbuddy\binaries\python\envs\default\Scripts\python.exe`）。
2. **MCP DataTable 写入异常后的幂等补写**：`dt.data_table_add_row(name, row)` 成功后若同段代码后续抛异常，事务提示「No changes were made」，但**行实际已在内存**。补跑必须写成「已存在则跳过 + `save_package()` + 回读」，不能直接重 add。
3. **DataTable 行的字段读取**：`dt.data_table_as_dict()` 的 value 是 `UScriptStruct`，用 `row.get_field('ValueType')` / `get_field('Value')` 读取，不要当 dict 用。
4. **重刷型 UI 的动效必须带「已播放」标记**：本项目仓库每 0.25 秒 `RefreshWarehouse` 会重应用反馈，若不在 state 上记 `MotionPlayed`，动效会被无休止重播。
