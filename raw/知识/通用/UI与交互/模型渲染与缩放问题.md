## 一、骨骼网格缩放失效

### 现象

调用 `SetActorScale3D` 后碰撞胶囊体变大，但视觉模型不变；日志全在 `LogUGCServer`，客户端无输出。

### 根因

1. `AvatarDisplayProxyComp` 接管了角色可视化渲染，Actor 级缩放改不到实际显示的网格。
2. `CachedMasterPoseComponent` 上部分缩放方法会抛错。
3. 服务端执行了但客户端没执行——**服务端修改组件属性不会自动同步到客户端**。
4. `pcall` 成功标记位置写错，把失败当成成功。

### 解决方案：统一缩放函数 + 四级降级 + 客户端重试

```
ApplyPetScale(baseScale)
  ├── Step 1: SetActorScale3D             → 碰撞体生效
  ├── Step 2: CachedMasterPoseComponent
  │     ├── 方法A: SetWorldScale3D
  │     ├── 方法B: SetRelativeScale3D
  │     ├── 方法C: RelativeScale3D 属性赋值   ← 最终生效方案
  │     └── 方法D: 遍历子组件缩放
  ├── Step 3: 遍历所有 SkeletalMeshComponent 兜底
  └── Step 4: Step2 失败则 1 秒后重试，最多 5 次
```

客户端注册委托同样需要重试：`GetOwner(self)` 在客户端存在复制延迟，取不到就起 1 秒定时器直到成功。

### 概念区分

- `SetActorScale3D`：Actor 级，改根组件缩放，子组件 WorldScale = 父 Scale × 子 RelativeScale，碰撞体随之变化。
- `SetWorldScale3D`：组件级，直接设该组件世界缩放；子组件在父级未设 `bAbsoluteScale` 时仍会被父级缩放叠加。

### 其他要点

- `pcall` 内的成功标记必须写在成功分支内。
- 组件属性方法与直接属性赋值行为可能不同，需逐个尝试。
- 清理所有定时器与委托，避免残留回调。
- 属性变化回调里注意 `self` 引用来源。

## 二、3D 角色渲染为 2D 预览图

链路：

```
SceneCaptureComponent2D → TextureRenderTarget2D(RTF_RGBA32f) → MaterialInstanceDynamic → UImage:SetBrushFromMaterial
```

**核心坑**：`RTF_RGBA32f` 会写入非 1.0 的 Alpha，RenderTarget 直接绑到 `UImage` 时人物呈半透明或只见轮廓。

**解法**：用 MID（父材质采样 `MainTexture` 并强制 Alpha = 1.0）+ `SetBrushFromMaterial`，在材质层解决透明问题。

前置资源：`SceneCaptureComponent2D`、`SkeletalMeshComponent`、`TextureRenderTarget2D`（`RTF_RGBA32f` 或 `RTF_RGBA16f`）、已处理 Alpha 的父材质。
