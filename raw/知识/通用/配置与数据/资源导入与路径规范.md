## 核心结论

1. 运行时加载一律用完整路径 `/<ProjectName>/Asset/...`，禁用 `/Game/` 与以 `Asset` 开头的相对写法。
2. 图片只支持 PNG / JPG / TGA，拖入 `Asset` 指定文件夹默认导入；文件名必须先合法化为英文开头。
3. UI 贴图五项属性按官方「UI贴图设置」配置：`LODGroup=16` / `MipGenSettings=13`（不是 2）/ `CompressionSettings=0` / `CompressionQuality=5` / `SRGB=True`。导入不会自动归 UI 组，必须显式修正。
4. 资源路径登记进配置表，禁止在脚本里硬编码；写入走 MCP 并回读验证。
5. **拖拽导入出现「禁止光标」是系统权限问题，不是格式问题**：Windows UIPI 禁止低完整性级别进程向高完整性级别进程投递拖放数据。若编辑器被提权启动（如经 WeGame 启动链），资源管理器（Medium）就拖不进去，且**编辑器日志不会留下任何记录**。判定与修复见下方「拖拽导入被拒」。生产上优先改用编辑器内导入入口或 MCP `ue.import_asset`，不要为此关闭 UAC。

## 一、运行时路径必须是完整路径

`UGCObjectUtility.LoadObject` 要求完整路径，需先经 `UGCGameSystem.GetUGCResourcesFullPath` 转换：

- 正确：`/pet_paradise/Asset/Effect/xxx.xxx`
- 错误：`Asset/Effect/xxx.xxx` —— 报错 `Path starts with 'Asset', which is not longer supported`

路径格式为 `Asset/目录/文件名.文件名`（不含 `.uasset` 扩展名）；蓝图类要带 `_C` 后缀，如 `Asset/Blueprint/Prefabs/UI/Work.Work_C`。

MCP 侧写入使用 `/<ProjectName>/Asset/...`，不使用 `/Game/`。

### 拖拽导入被拒（禁止光标）的判定与修复（2026-09-14 实测）

官方口径（`raw/docs/wiki/新手入门/资源管理与编辑/277_资源导入.md`「注意事项」，**官方确认**）：拖入编辑器时出现禁止图标，属**系统权限**问题，需「用户账户改为从不通知」+ `gpedit.msc` 禁用两项策略。官方仅给截图，未给策略项名。

#### 机制

Windows **UIPI（User Interface Privilege Isolation）** 不允许低完整性级别（IL）进程向高 IL 进程投递窗口消息与 OLE 拖放数据。资源管理器通常为 Medium IL；若编辑器**被提权启动**（High IL），从资源管理器拖文件会显示禁止光标，**拖放根本不会到达编辑器进程，因此日志中无任何记录**（排查时容易误判为「编辑器没反应」）。

#### 判定步骤（无需管理员权限）

1. **排除跨用户**：`whoami /user` 确认当前会话与桌面交互用户是同一账号（不同账号也会导致进程信息读不到，属另一类原因）。
2. **用路径可读性反推 IL**：以 Medium IL 身份查 `Win32_Process.ExecutablePath` —— 同用户同 IL 可读，更高 IL 返回空字符串。
   ```powershell
   Get-CimInstance Win32_Process -Filter "Name='<编辑器exe名>'" | Select-Object ProcessId,ParentProcessId,ExecutablePath
   ```
   对照 `explorer.exe`/`conhost.exe`（应可读）与 `dwm.exe`/`lsass.exe`/`winlogon.exe`（应为空）做基线；若编辑器与 `dwm` 表现一致 → 已提权。
   > 说明：`Add-Type` 编译 P/Invoke 会被执行策略拦截，`reg.exe` 可能被程序黑名单拦截；`Format-List`/`Out-String` 直接管道到 `Add-Content` 会静默丢输出，改为组装字符串后一次性 `Out-File -Encoding utf8` 更可靠。
3. **查策略现状**：`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System` 下 `EnableLUA`、`ConsentPromptBehaviorAdmin`、`PromptOnSecureDesktop`、`EnableInstallerDetection`。
4. **查兼容层**：`HKCU/HKLM\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers`，确认不是被 `RUNASADMIN` 兼容层提权。
5. **看父进程链**：若父进程（如游戏平台启动器）本身已提权，编辑器会继承其令牌。

#### 官方两步与本机策略项的对应（推断，非官方文字）

| Wiki 步骤 | gpedit 中文项 | 注册表项 | 目标值 |
| --- | --- | --- | --- |
| ① 用户账户改从不通知 | 提示提升时切换到安全桌面 | `PromptOnSecureDesktop` | 0 |
| ① 用户账户改从不通知 | 管理员批准模式中管理员的提升提示行为 | `ConsentPromptBehaviorAdmin` | 0 |
| ② 禁用两项之一 | 以管理员批准模式运行所有管理员 | `EnableLUA` | 0 |
| ② 禁用两项之一 | 检测应用程序安装并提示提升 | `EnableInstallerDetection` | 0 |

#### 修复选项（按安全性排序）

1. **最安全（首选）**：不碰系统策略 —— 改用编辑器内导入入口，或走 MCP `ue.import_asset(<源文件绝对路径>, '<资产目录>')`；或让编辑器**不提权**启动，使之与资源管理器同为 Medium IL。
2. **其次**：让拖放两端处于**相同完整性级别**。
3. **官方方案（安全降级）**：UAC 改「从不通知」+ 禁用上述两项。会使全机长期失去 UAC 保护，须需求方明确决定后执行。

#### 落地执行要点（2026-09-14 执行 A 档时实测）

- **写入通道**：`reg.exe` 会被安全策略拦为程序黑名单（`exit=126`），且 Medium IL 写 `HKLM` 直接 `不允许所请求的注册表访问权`。可行路径只有两条：PowerShell 脚本**自我提权**（检测 `WindowsPrincipal.IsInRole(Administrator)`，否则 `Start-Process -Verb RunAs` 重新拉起自身），或生成 `.reg` 文件让用户双击导入。
- **生效条件**：`EnableLUA` 为启动期加载策略，**必须重启 Windows**，不重启完全不生效。
- **回滚必须先落盘**：改前用 `Get-ItemProperty` 把 8 项值写成快照 `.txt` 与还原用 `.reg`，否则改动只能靠记忆恢复。
- **判定生效**：重启后拖一张 PNG 到内容浏览器，再检索编辑器日志 `ImportAsset|DroppedFiles|AssetImport` —— 从「零命中」变为「有命中」即证明拖放已送达进程，比看光标可靠。

#### 内置 Administrator 场景的更优档位（推断，待重启后实测）

若登录账户是**内置 Administrator**（`whoami /user` 的 SID 以 `-500` 结尾），存在比关闭 UAC 代价更低的方案：只设 `FilterAdministratorToken = 0`、`EnableLUA` 保持 1。放开令牌过滤后资源管理器与编辑器同为 High IL，UIPI 隔离消失、拖放可用，而 **Microsoft Store / UWP 不受影响、防护不降级**。

| 档位 | 改动 | Store/UWP | 需重启 | 备注 |
| --- | --- | --- | --- | --- |
| A（官方 Wiki） | `EnableLUA=0` + 通知类 3 项 | **无法启动** | 是 | 安全降级 |
| B（替代） | `FilterAdministratorToken=0` + 通知类 3 项 | 不受影响 | 是 | 仅对 RID 500 有效；官方 Wiki 未覆盖 |

两档**不可叠加**，切换前先还原到改前快照。B 档结论属机制推断，验证后须回来订正。

### UI 贴图批量修正标准流程（2026-08-26 实测可复用）

1. **写前全量备份**（PowerShell `Remove-Item` 与含中文的多行脚本易被本机执行策略拦截，用 Python 更稳）：
   ```python
   import os, shutil
   src = r"...\UGCProjects\IslandAuctionKing\Asset\TuPian\ZhuJieMian"
   dst = r"D:\知识库\和平精英绿洲起源\备份\IslandAuctionKing\<YYYYMMDD>_<Theme>"
   os.makedirs(dst, exist_ok=True)
   for f in os.listdir(src):
       if f.endswith(".uasset"):
           shutil.copy2(os.path.join(src, f), os.path.join(dst, f))
   ```
2. **一个目录一个 plan**：`ue_plan_submit` 的 `asset_path` 只能填一个路径，跨目录批量必须分次提交（本轮 `ZhuJieMian` 与 `TuJian` 各一个 plan_id）。
3. **循环内逐张 `save_package()`**：它是对象方法，只落盘自身所在 package，不能在循环外只调一次。
4. **幂等写入**：先读 before，值已正确就跳过写入与保存，避免无意义落盘与体积抖动。
5. **跨对象回读**：写完重新 `load_object` 读五项并做布尔断言，打 `ALL_xx_COMPLIANT` 日志；再核磁盘 `mtime` 与字节数变化确认落盘。
6. **回写知识库**：更新基线表 before/after 与「待查证」，新增来源页记录 plan_id 与备份绝对路径。

## 三、粒子特效资源的加载条件

来自 `20379` 记录，三个容易被忽略的前提：

1. **`SpawnEmitterAttached` 仅客户端生效**，必须放在 `not self:HasAuthority()` 分支内。
2. **`PackageFlags` 含 `PKG_FilterEditorOnly` 时运行时会跳过加载**，需改为 `"PackageFlags": "PKG_None"`、`"IsFilterEditorOnly": false`；同时粒子导出自身的 `bNotAlwaysLoadedForEditorGame` 也要为 `false`。
3. **粒子系统不能为空**，`NumEmitters = 0` 时 `LoadObject` 返回 nil，必须至少有一个 Sprite 发射器。

生命周期：特效组件不会自动销毁，需在 `ReceiveEndPlay` 与死亡回调中手动清理；加载与挂载都用 `pcall` 保护。

排查顺序：`LoadObject` 返回 nil 先查路径格式，再查 `PackageFlags`，最后查发射器数量。
