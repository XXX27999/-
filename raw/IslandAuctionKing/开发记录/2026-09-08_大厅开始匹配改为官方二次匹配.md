## 现象

大厅点「开始匹配」且拍卖场/角色/仪器组已确认后，原逻辑只 `ShowTipsUI("三项已确认，等待全员完成选择后开局")`。`AuctionGameService.TryStartAfterSelections` 在同一 DS 人满+选完后直接 `StartPreparing`，工程内 0 处引用 `UGCMultiMode.RequestMatch`。

## 官方确认

1. `UGCMultiMode.RequestMatch(SubModeID, ResCallBack, Obj)` 仅客户端。Wiki 示例三参；API 另有第四参 `IsTeamUnfill`，官方未说明何时使用，本轮不猜、不传。
2. `RequestMatch` 与 `RequestCancelMatch` 不能同一帧，有 1 秒限频。
3. `GetModeID` 客户端/服务端；无活跃模式返回 0。
4. `NotifyMatchResponseDelegate` 客户端，`bSuccess=true` 进入匹配中，`false` 回到未匹配。本轮回调走 Wiki 示例的 `RequestMatch` 回调，不额外绑定未演示的 Delegate。
5. 启用方式：`编辑 -> 工程设置 -> Match Setting` 勾选 `Multi-mode Game` 的「使用多模式配置」，添加子模式，勾选一个默认模式。模式 ID 由编辑器自动分配。
6. Debug/PIE：调试选项勾选「子模式调试」并填写子模式 ID。任意玩家可发匹配且必定成功，匹配中无法主动取消；成功后当前 DS 全部玩家转入新对局并关闭旧 DS。真机按子模式成局条件拉人。

## 项目改动

写前备份：

`D:\知识库\和平精英绿洲起源\备份\IslandAuctionKing\20260908_HubLayoutAvatarRematch\Rematch\`

- 新建 `Script/Function/AuctionRematchService.lua`：客户端 `pcall(UGCMultiMode.RequestMatch, modeID, callback, widget)`；成功/失败 `UGCWidgetManagerSystem.ShowTipsUI`；1 秒限频；服务端用 `GetModeID` 判断是否已进入竞拍子模式。
- `AuctionHubUIService.OnMatchClicked`：三项确认后调用 `AuctionRematchService.HandleMatchButtonClicked`。`Refresh` 只改 `MatchLabel`，不改 `GoldValueText` / `PlayerNameText` / 头像。
- `AuctionGameService.TryStartAfterSelections` / `StartPreparing`：当前不是竞拍子模式时拒绝本机人满假开局。进入竞拍子模式后，本局选择确认可能未随新 DS 保留，继续用人数与拍卖场金币门槛开局。
- `AuctionConfig` 注册路径 `Data/Table/Customized/Gameplay/GameplayConfigTable`，运行时读取 `Gameplay.Rematch.*`。回退值已按截图改为 `Gameplay.Rematch.AuctionModeID=1002`（竞拍模式），不能用默认大厅 1001。

未改：`ZhuJieMian.uasset`、三个选择 UI、CollectibleCodex、头像/名称/金币加载、通用 UI 摆放知识页。MCP 未调用。工程内尚未创建 `GameplayConfigTable` 资产。
