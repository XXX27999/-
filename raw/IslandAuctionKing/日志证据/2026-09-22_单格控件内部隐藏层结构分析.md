# 单格控件内部结构分析（第五轮 · 方向二）

## 一、目的

用户选定方向二：核实「底格控件内部自带不透明层」是否遮挡覆盖层。
本轮以**只读静态分析**解剖 `CollectibleCodexItemUI_C` 的完整控件树与画刷，定位候选不透明层。

## 二、控件树与格内 ZOrder（实测）

单格控件 `CollectibleCodexItemUI_C`（33,714 B）内部结构：

```
CollectibleCodexItemUI_C
└─ WidgetTree
   ├─ CanvasPanel_0                (CanvasPanel，仅 1 slot)
   │   └─ ItemImage                (UImage)   ZOrder=2   ColorAndOpacity=(1,1,1,alpha 0) 全透明
   └─ ItemContent                  (CanvasPanel，10 slots) ← 格内容主容器
       ├─ [0] CardBackground       (UBorder)  ZOrder=3    Brush=Codex_CardFrame
       ├─ [1] NameFrameImage       (UImage)   ZOrder=1    Brush=Codex_NameFrame  ImageSize=145x50
       ├─ [2] TypeQualityText      (TextBlock) ZOrder=3
       ├─ [3] ValueText            (TextBlock) ZOrder=3
       ├─ [4] CollectionStateText  (TextBlock) ZOrder=3
       ├─ [5] ItemNameText         (TextBlock) ZOrder=3
       ├─ [6] IncomeText           (TextBlock) ZOrder=3
       ├─ [7] QualityBar           (UBorder)  ZOrder=**None**
       ├─ [8] ItemArt              (UBorder)  ZOrder=**None**
       └─ [9] ButtonSlot_0 → ItemButton (UButton) ZOrder=10
```

## 三、候选不透明层（决定性发现）

`SlateBrush` 逐字段解析结果：

| 控件 | 类 | 贴图（Import 解析） | 画刷颜色 / 关键属性 | 格内 ZOrder |
|---|---|---|---|---|
| **`ItemArt`** | `UBorder` | **无贴图** | `BrushColor = (0.16, 0.17, 0.18, **A=1.0**)`、`DrawAs=Box` | **None（未写值）** |
| **`QualityBar`** | `UBorder` | **无贴图** | `BrushColor = (0.95, 0.18, 0.25, **A=1.0**)` | **None（未写值）** |
| `CardBackground` | `UBorder` | `Codex_CardFrame` | `ImageSize=Vec2(0,0)` | 3 |
| `NameFrameImage` | `UImage` | `Codex_NameFrame` | `ImageSize=145x50` | 1 |
| `ItemImage` | `UImage` | 无 | `ColorAndOpacity=(1,1,1,**A=0**)` 全透明 | 2 |
| `ItemButton` | `UButton` | — | `BackgroundColor=(1,1,1,**A=0**)` 全透明 | 10 |

Import 表关键项：

```
[28] negRef=-29  name=Codex_CardFrame   class=Texture2D  → CardBackground
[29] negRef=-30  name=Codex_NameFrame   class=Texture2D  → NameFrameImage
```

**结论**：`ItemArt` 与 `QualityBar` 是**两个无贴图的 `UBorder`，画刷为 alpha=1.0 的不透明实色**。
若不折叠，它们会以纯色块覆盖格子 —— 与记忆中「格子变橙条+灰块」的历史现象一致
（`NameFrameImage` 橙色条 + `ItemArt` 浅灰块）。

## 四、与现有代码的对应

`AuctionWarehouseCellService.lua` 的 `CELL_CHROME_NAMES`（9 项）**已包含全部 4 个候选层**：

```lua
local CELL_CHROME_NAMES = {
    "CardBackground",   -- 图鉴卡片底板
    "ItemArt",          -- 图鉴藏品底图，泄漏时在格内显示为浅灰方块
    "NameFrameImage",   -- 图鉴名字框贴图 Codex_NameFrame，泄漏时在格顶显示为橙色圆角条
    "QualityBar",       -- 品质条
    "ValueText", "IncomeText", "TypeQualityText", "CollectionStateText",
    "ItemImage"         -- 图片层，背景格由按钮画刷承担
}
```

折叠方式为 `SetVisibility(ESlateVisibility.Collapsed)`（`Collapsed` 整控件不参与布局与绘制）。
历史日志实测每格 `collapsedByName=9 / missingByName=0`（9/9 命中）。

**因此：若这 9 项在运行态确实都被 `Collapsed`，则单格控件内部不存在残留不透明层。**
待 PIE 运行态确认。

## 附：方法备忘

- 本 dump 中 **`PropertyExport.Data` 恒为空数组**，控件默认值在 `NormalExport.Data` 里 —— 别读错位置。
- 控件会存**两份**（`outer=69` = CDO 模板 / `outer=70` = 活体树）；排障看 **69 那份的 slot 链**要与 70 对照。
- 画布子控件顺序 = `CanvasPanel.Slots` 数组顺序；每项 Slot 的 `Content` 指向子控件。
- 数值引用：正数 = 本文件 export 下标；负数 `-n` = `Imports[n-1]`。
- Import 表是识别贴图的关键：`Package` 类型给出资产包路径，紧随其后的 `Texture2D` 才是实际贴图对象。
