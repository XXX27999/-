## 二、跨局重进物品消失：V2 背包整体不持久化（用户指令 2）

### 2.1 定性更正

第二轮把「卡片不继承」归因为**单张卡缺少存档键**并补了 `WorkTimedCardHelper.ActivateWorkIncomeCard`。
第三轮用户补充「跨局重新进入游戏物品消失，上局未保存」后推翻该结论：**四张卡本身并不依赖各自存档键**——

- 完美打工卡 `8310013`、经验卡 `8310006~8310008`、打工翻倍卡、扫荡卡 `8310071` 都是 **V2 背包里的物品**；
- 其中打工翻倍卡的运行时属性 `WorkDouble` **本来就在** `PlayerAttributeNames` 名单里（第二轮 §1 已证明）；
- ⇒ 真正的缺口只有一层：**V2 背包物品表本身不随 `PlayerArchiveData` 跨局保存**。

判据：`UGCBackpackSystemV2.md` 只提供 `AddItemV2`/`GetItemCountV2`/`GetAllItemDefineIDsV2` 等**运行时**读写接口，
文档与工程代码中均无「背包内容自动进存档」的表述或实现。

### 2.2 方案：整包快照 + 差量补发（覆盖所有物品，而不是只补四张卡）

新增 `Script\Common\Utils\BackpackArchiveHelper.lua`，存档键 **`PlayerBackpack`**：

| 函数 | 职责 | 关键约束 |
| --- | --- | --- |
| `SnapshotBackpack(owner)` | `GetAllItemDefineIDsV2` + `GetItemCountV2` → `{[itemID]=count}` | owner 失效返回空表 |
| `MergeBackpackIntoArchive(PlayerData, PlayerPawn, uid, reason)` | 覆盖写入 `PlayerData["PlayerBackpack"]` | **Pawn 为 nil 时必须保留旧快照**，不能写空表把玩家物品清零 |
| `RestoreBackpackFromArchive(PlayerPawn, Controller, archiveData)` | 按「存档数 − 当前数」差量 `AddItemV2` | 幂等不叠加；`CheckInitPersistCompleted` 未就绪则 ≤5 次 ×1s 重试；满包时提示并把差额**留在存档**下次登录补 |

接入点：

- `Script\gamemode\ControllerExitGame.lua`（`SaveAllPlayerArchive`）：属性快照合并之后、提交之前；失败只记日志**不阻断存档**。
- `Script\gamemode\PetActorDic.lua`（`LoadPlayerArchive`）：属性恢复之后差量补发；失败**不影响读档**。

**为什么选整包而不是白名单**：用户明确要求「保证所有物品的持久化」；按 itemID 白名单维护会随新物品持续膨胀，且容易漏。

### 2.3 待 PIE 确认的边界

- V2 背包是否在 **`PlayerPawn` 生成之后**才完成初始化（当前补发挂在 `PetActorDic` 恢复属性之后，依赖 Pawn 已存在）；
- 差量补发在玩家**在线期间二次触发**是否会重复（`CheckInitPersistCompleted` 保证只一次初始化，理论上安全，未实机验证）。

## 六、iPad11 竖屏仓库页双窗口（用户指令 6）

- 玩家给的仓库 UI 路径：`UGCGameSystem.GetUGCResourcesFullPath('Asset/UI/text1.text1_C')`。

**根因**：`Script\Blueprint\Prefabs\UI\OpenShop.lua` 的 `Image_119_OnMouseButtonDownEvent`（仓库按钮）
**每次点击都** `NewWidgetObjectBP` 新建 `text1` 实例并 `AddToViewport(1000)`，**从不检查既有实例**；
而 `text1:Construct` 末尾又把自身 `AddToSlot("UI.UISlot.MainUISlot_Low", 0)`。
⇒ 触屏连点/双击会创建**两个实例进入同一插槽**，表现为双窗口。

**为什么只在 iPad 竖屏出现**：不是横竖屏布局适配问题，而是**触屏更易产生连点/双击**；鼠标端点击间隔长，概率极低。

**修复**：打开前查 `UIUtils.LoadedUIWidgets["text1"]`，存在且有效就直接 `ShowWidget` 复用（并打印分支日志），不再重复创建。AST PASS。

**遗留**：`Script\Blueprint\Cube_Blueprint.lua`（领养触发盒）有同型隐患——每次 overlap 新建 UI、并用 `HideWidget` 关闭未注册控件；它开的是 `linyanann` 不是 `text1`，不在本轮范围，建议后续单独立项。

## 八、同日追加：季卡专属特效改到宠物脚下、放大到 2 倍

用户在同一天追加要求：「季卡专属巨型特效应该在宠物脚下，大小改为 2 倍」。相较第一轮「1 倍就好」，本次明确了两个维度：**挂点**与**倍率**。

### 9.1 为什么「脚下」不是把 Z 偏移改个数

特效在 `Pet.lua` 里是 `UGCGameSystem.SpawnEmitterAttached(...)` 挂到 `self:K2_GetRootComponent()`，
`LocationType = EAttachLocation.KeepRelativeOffset` ⇒ 位置是**相对根组件**的。
宠物 Actor 的位置等于根组件世界位置，而**根组件原点通常在宠物身体中部**（与 NPC/怪物一致用胶囊或场景根），
所以相对 `(0,0,0)` 挂出来的特效会悬在**腰身高度**，表现就是「不在脚下」。

固定 Z 偏移不可靠：宠物有 `baseModelScale + petSizeAddRate` 体型加成（见 `Pet:ApplyPetScale`），
同一个偏移在不同体型下会飘。⇒ 采用**运行时差量**：

```
feetOffsetZ = 宠物包围盒底部世界Z - 宠物Actor世界Z   （通常为负值）
effectLocation.Z = feetOffsetZ + WorkEffectFeetLiftZ
```

包围盒读取复用本文件已验证的写法 `pet:GetActorBounds(false)`（`origin.Z - extent.Z`，见 `GetActorBottomZ`），
`K2_GetActorLocation` 亦为本文件既有用法（如 `GetActorLocationSafe`）。两者都用 `pcall` 保护，失败回退到配置偏移并打日志。

### 9.2 配置改动（`Script\Common\SeasonCardBenefitConfig.lua`）

| 键 | 值 | 说明 |
| --- | --- | --- |
| `WorkEffectScale` | `{X=2, Y=2, Z=2}` | 用户确认 2 倍（此前为 1 倍） |
| `WorkEffectAttachToFeet` | `true` | 新增；true 时按包围盒底部动态补偿 Z |
| `WorkEffectFeetLiftZ` | `0` | 新增；脚底基础上再抬升，0=正好贴脚底 |
| `WorkEffectLocationOffset` | 保持 `{0,0,0}` | 其 `Z` 仅在 `AttachToFeet=false` 时生效 |

新增读取函数：`IsWorkEffectAttachToFeet()`、`GetWorkEffectFeetLiftZ()`（均有回退值，不外抛）。

### 9.3 脚本改动（`Script\Blueprint\Prefabs\Monsters\Pet.lua`）

- 新增 `local function ResolveSeasonCardFeetOffsetZ(pet)` → `(offsetZ, ok)`，出口打印 `petWorldZ / bottomWorldZ / feetOffsetZ`。
- `Pet:PlaySeasonCardWorkEffect()` 用 `effectLocation`（新表，不修改配置返回的同一张 table）替换直接传参；
  出口日志补 `locationZ` 与 `scale`，便于 PIE 直接判定是否落到脚底。
- **踩坑点（可复用）**：`ResolveSeasonCardFeetOffsetZ` 必须**文本顺序上先于** `Pet:PlaySeasonCardWorkEffect`
  （本文件里两个既有 helper `GetActorBottomZ`(2599)、`GetActorLocationSafe`(1800) 都定义在 `Pet:PlaySeasonCardWorkEffect`(1062) **之后**，
  位于它们之前的函数体**引用不到**——
  Lua 的 `local function` 是块作用域局部变量，前面的函数体里同名引用会被解析成**全局**从而拿到 nil，
  运行时报 `attempt to call a nil value`）。因此本处没有复用 `GetActorBottomZ`，而是新写了一个自包含 helper 放在使用点之前。

### 9.4 验证与限制

- 两文件 `luaparser` AST PASS、无 BOM；`decl(1002) < use(1095)` 顺序正确。
- 写前备份：`D:\知识库\和平精英绿洲起源\备份\pet_paradise\20260917_季卡特效脚底2倍\before\`（含 SHA256）。
- **未 PIE 实机验证**：`feetOffsetZ` 的实际数值取决于宠物根组件与网格的相对位置，需实机打印该值确认符合预期。
- 已知限制：偏移在**生成时**算一次。打工期间若宠物体型加成发生变化，特效不会重新贴脚；需要的话可在 `ApplyPetScale` 后重挂。
- 生效方式：**建议重新调试 PIE**（纯函数体改动理论上可热更，但本次要验证挂点，走 PIE 更稳）。

## 九、订正与收窄：项2 只有卡类道具跨局丢失（根因 = ShouldPersist）

用户更正：「项2 就只有这几张指出来的卡出现跨局丢失状态，其他物品未出现。」
据此推翻本文件 2.1 节的推断（「V2 背包物品整体不跨局」），并定位到官方根因。

### 9.1 根因：物品 Handle 蓝图 CDO 上的 `ShouldPersist`

`UGCBattleItemHandleBase` 有 `ShouldPersist : bool [Edit]`，决定该物品是否跨局持久化。
**它不在 `UGCBattleItem` 表的列里**，只能通过 `ItemHandlePath` 指向的 Handle 蓝图 CDO 读写。
官方旁证：`UGCBackpackSystemV2.md` 的 `GetBackpackPersistData(Player, ContainsNoPersist)`
参数说明为「true: 包含**不持久化物品**数据」⇒ 官方按物品区分持久化。

MCP 扫描全部 78 行得到 38 True / 38 False，被报丢失的卡**全部落在 False 组**：

| ItemId | 名称 | Handle 资产 | 原值 | 现值 |
| --- | --- | --- | --- | --- |
| 8310006 | 等级经验卡大 | `Items/WorkItems/ExpCard/LevelExperinceCard_Large` | False | **True** |
| 8310007 | 等级经验卡中 | `…/ExpCard/LevelExperinceCard_Mid` | False | **True** |
| 8310008 | 等级经验卡小 | `…/ExpCard/LevelExperinceCard_Small` | False | **True** |
| 8310013 | 完美打工卡 | `…/WorkItems/WorkItem/WorkPerfectCard` | False | **True** |
| 8310062 / 8310070 / 8310071 | 扫荡卡（三行共用同一 Handle） | `…/WorkItems/WorkItem/SDK` | False | **True** |
| 8310012 | 打工翻倍卡 | `…/WorkItems/WorkItem/WorkMult` | **原本就是 True** | 未改 |

**因此项2 的正确答案是改 `ShouldPersist`，不是写背包快照。** 5 个资产已通过 MCP（PRV：Plan → Execute → 回读）写入并 `save_package`，
文件级证据：5 个 `.uasset` 的 SHA256 与写前备份均不同（各 +48 字节，与 CDO 新增一个 bool 序列化一致）。

**未改的 False 组**：其余 33 行（全部枪械 `A1/A2/A7/A8/A9/A10/test1/testuzi`、金币 `Gold`、改名卡 `NameCard`、止痛药 `sdf`、
`ProMaxGMPack`、`clean/feed/interact/SkillBase` 系列等）保持原状——这些通常是官方刻意不跨局保留的，**不要顺手全开**；如后续发现确实需要，再逐项确认。

**易错点**：多个 ItemId 共用同一 Handle（3 行扫荡卡共用 `SDK`）→ 改一次全生效；
同名文件分布在不同目录（`Items/SkillItem/clean` 与 `Items/WorkItems/Base/clean` 是两个资产）→ 必须按完整路径定位。

### 9.2 收窄 Lua 兜底：整包快照 → 卡片白名单

`BackpackArchiveHelper` 由「整包快照 + 差量补发」收窄为**卡片白名单兜底**：
新增 `PersistMode`（`allowlist`/`all`/`off`，默认 `allowlist`）与 `PersistItemIDs`（8310013/8310012/8310006/8310007/8310008/8310071）。

**为什么必须收窄**：整包快照会在重进后把 `ShouldPersist=False` 的武器、金币、改名卡等
「官方刻意不跨局保留」的物品一并补回来，属于新的副作用。
兜底与官方机制不冲突：官方恢复到位时差量为 0，不会重复发放。
