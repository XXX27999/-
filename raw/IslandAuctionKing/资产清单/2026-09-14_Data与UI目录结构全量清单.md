### 物品目录的编辑器归属（MCP 实测）

`objed_query_asset_types('Item')` 返回物品编辑器下 4 类资产类型及其落盘根目录：

| asset_type | 模板数 | 落盘根目录（相对项目根） |
| --- | ---: | --- |
| 物品 | 212 | `Asset/Blueprint/Prefabs/Items` |
| 枪械 | 93 | `Asset/Blueprint/Prefabs/Weapons` |
| 投掷物 | 4 | `Asset/Blueprint/Prefabs/Throwables` |
| 近战武器 | 8 | `Asset/Blueprint/Prefabs/MeleeWeapons` |

`objed_query_assets('Item')` 当前仅返回 1 个资产：

```text
text    [Blueprint]    /IslandAuctionKing/Asset/Blueprint/Prefabs/Items/text
```

**结论**：`Prefabs/Items` 是物品编辑器「物品」类型的固定落盘目录。往里新增物品应走
`ue.objed_create_asset('Item', '物品', <模板名>, <英文资产名>, <可选子目录>)`，
而不是手工放 `.uasset`。该 API 的模板共 212 个，其中含 16 个「空白」模板
（空白物品 / 空白消耗品模板 / 空白装备物品模板 / 空白药品模板 / 空白头盔模板 / 空白防弹衣模板 /
空白背包模板 / 空白枪械物品模板 / 空白投掷物模板 / 空白近战武器模板 / 空白枪口 / 空白握把 /
空白弹匣 / 空白枪托 / 空白瞄准镜 / 空白侧面瞄准镜模板）。`objed_save_asset` 保存时会触发
OnPackagesSaved→HandleItemTable，把蓝图 CDO 同步进 BattleItem 表。单次批量创建不要超过 3 个。

## 五、可复用观察（项目内）

1. 表格侧结构为 `Data/Table/Customized/<功能域>/<功能域>ConfigTable`，与 `AGENTS.md` 规范的 `Asset/Data/Table/Customized/<功能模块名>/` 一致；目前已有 `Dress/`、`Guarantee/`、`UI/` 三个功能域子目录。
2. 每个业务表都配有一份 `UGCTemplateRowStruct_<表名>`，位于同目录，属官方行结构模板约定。
3. 根级 `Data/` 下的 `DA_GameModeGeneral` 与 `Table/` 是并列关系，未放入 `Table/Customized`。
4. UI 侧为**单层平铺**，无子目录；命名统一采用 `<业务><功能>UI` 后缀式，唯一例外是拼音名 `ZhuJieMian`（主界面）。
5. 物品侧当前仅一个测试资产 `text`，命名尚未进入项目规范；后续经物编创建的物品会以指定英文名直接落在该目录，也可用 `objed_create_asset` 的 `sub_dir` 参数建子目录分层。
