## 三、根因链

1. `text1:Construct` 里 `UIUtils.LoadedUIWidgets["text1"] = self` 注册缓存；
2. `text1:Close_OnClicked` 末尾只做 `HideWidget` + `DestroyWidget`，**不清缓存**；清理缓存写在 `text1:Destruct`，而 `Destruct` 依赖蓝图事件绑定，实测一次都没触发（日志计数 0）→ 缓存里永久留下一个已销毁的 `text1_C`；
3. 下次点击：`ExistingWarehouse` 非 nil → `UIUtils:IsWidgetValid` 用 `SetVisibility(HIDDEN)` 做探测，**对已销毁控件只打日志不抛错**，pcall 返回 true → 判定为“有效”；
4. 进入复用分支，`UGCWidgetManagerSystem.ShowWidget(失效实例)` 抛异常，被 `pcall` 吞掉 → **界面不显示，且无任何失败日志**（只有引擎的 LuaException）。

## 四、修复（2026-09-17 已改）

1. `Script/UI/text1.lua` `text1:Close_OnClicked`：在 `HideWidget`/`DestroyWidget` 之前 `UIUtils.LoadedUIWidgets["text1"] = nil`，并补日志 `已清除仓库UI缓存`。
2. `Script/Common/UI/UIUtils.lua` `UIUtils:IsWidgetValid`：先判空；再用 `UE.IsValid` 判定，**仅在明确返回 false 时短路返回 false**，其余沿用原 pcall 探测，避免改动共享工具类的既有行为。

- **打开之后日志里没有任何 LuaException / 报错指向点击失败** —— 点击无响应本身不落日志，这是本次排查的最大证据缺口。

### 7.2 已确证的缺陷（结构性，两轮同源）

`text1:Close_OnClicked` 用 `HideWidget` + `DestroyWidget` 关闭，**从不调用 `RemoveFromSlot`**：

- 官方依据：`RemoveFromSlot` = 从 UI 挂点槽位移除控件；`UI.UISlot.MainUISlot_Low` = 和平主界面**低层级**锚点，`ZOrder 0` 即该层最底（`raw/docs/api/class/和平全局接口/UI 界面/UGCWidgetManagerSystem.md`、`raw/docs/wiki/进阶内容/UI系统/20097_和平控件锚点.md`）。
- 后果：挂点上残留已销毁控件；第二轮修复后每次点击都重建新实例且都进 `MainUISlot_Low` / `ZOrder 0`，**同层同 ZOrder 排序不确定**，新实例可能被压在残留控件之下 → 表现为"仓库UI打开了却点不动"。
- 讽刺点：`text1:Close_OnClicked` 里对别人的残留做了完整清理（`GetAllWidgetsOfClass` → `HideWidget` → `RemoveFromSlot` → `RemoveFromViewport` → `DestroyWidget`），唯独没对自己做。

### 7.3 本轮改动（2026-09-17 16:5x）

1. `Script/UI/text1.lua` `Close_OnClicked`：`HideWidget` / `DestroyWidget` 之前新增 `UGCWidgetManagerSystem.RemoveFromSlot(self)`（pcall 保护 + 结果日志 `从UI挂点摘除, ok=...`）。
2. `Script/UI/text1.lua` `Construct` 宠物按钮回调：新增点击埋点 `【text1+PetButton】收到点击, 索引=N, PetName=...`，用于区分"点击没到控件"与"点击到了但业务没走"。

原文件备份：`D:\知识库\和平精英绿洲起源\备份\pet_paradise\20260917_仓库UI无法点击\before\`。

### 7.4 尚未证伪的第二假设：宠物列表按钮的触摸模式

`text1:Construct` 把 `Button_1~Button_27` 全部设为 `SetTouchMethod(1)`（`ConfiguredButtonCount=27`，每会话必打）。官方枚举 `raw/docs/api/cppenum/E/EB/EButtonTouchMethod.md` 只有两个值：`DownAndUp = 0`、`PreciseTap = 1` —— 代码注释与数值一致，**不是枚举写错**。但 `PreciseTap` 的语义是"只有精准点击才触发，位移交给滚动列表"，触屏/iPad 上手指略有位移就不触发，属"有时候点不动"的候选机制。

判别方法（本轮埋点已可支撑）：

- 若日志出现 `【text1+PetButton】收到点击` 而界面无反应 → 点击到了控件，是业务/刷新问题；
- 若完全没有该日志、但关闭按钮可点 → 命中 `PreciseTap` 语义，改为 `SetTouchMethod(0)`（DownAndUp）验证；
- 若连关闭按钮都点不动 → 属 7.2 的层级/挂点问题或上层存在可点击遮挡。
