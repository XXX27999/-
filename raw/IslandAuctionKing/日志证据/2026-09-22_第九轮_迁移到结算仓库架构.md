# 竞拍仓库遮挡问题：迁移到结算仓库架构

日期：2026-09-22（第九轮）
项目：IslandAuctionKing（海岛竞拍王）

---

## 一、为什么前八轮修不好：架构性冲突

### 现状（竞拍仓库，错误）

```
CollectibleCodexItemUI_C（单格）
└── CanvasPanel_0
    └── ItemButton (256×268)  ← 格子纹理写在它的 WidgetStyle 四态画刷里
        └── ItemContent (CanvasPanel)
            ├── CardBackground (Border)
            ├── ItemImage (Image, 168×168)
            ├── ...
            └── ItemArt (Border, 224×141)  ← 最后一个子控件 → 压住全部兄弟
```

三个死结：

1. **格子外观与「是否遮挡」共用 `ItemButton` 一个通道**
   本引擎 `UButton.BackgroundColor.A` 是**整格绘制开关**：
   - `A=1` → 格子可见，但整块不透明底板盖住其后的藏品覆盖层；
   - `A=0` → 不遮挡了，但格子连纹理带边框**一起消失**（第七轮用户实测）。

   **同一层做不到「既显示格子又不遮挡」。**

2. **`ItemArt` 是 `ItemContent` 的最后一个子控件**，`Border` 无贴图但 `BrushColor` 深灰 `A=1.0`，
   尺寸 `224×141` 远大于格位 `85.2` → 它压住 `ItemImage`。

3. **`ClipToBounds` 不能用来兜底**（第八轮定论）：
   格位尺寸 85.2 远小于内部 224×141 → 裁切会把整格内容裁没。

### 对照（结算仓库，正确）

```
背景格：纹理写在 ItemImage（UImage）上
        ItemButton:SetBackgroundColor({A=0}) + SetVisibility(HitTestInvisible)
        → 按钮完全不参与绘制，不遮挡任何东西
藏品图：NewWidgetObjectBP 新建实例 → AddChildToCanvasSafe 追加到父画布末尾（z=40，格 z=30）
        → 天生最上层
```

**关键差异：结算把「格子像素」交给 `ItemImage`，把「按钮」降级为纯命中层。
竞拍仓库把两件事都压在 `ItemButton` 上，于是必然自相矛盾。**

## 二、正解：迁移到结算架构

三层改动：

### 1. 格子像素改由 `ItemImage` 承担

`AuctionWarehouseImageMaterialService.ApplyGridTexture` / `ApplyCellTexture`
原先写 `button.WidgetStyle` 四态画刷；改为写 `cellWidget.ItemImage:SetBrushFromTexture(...)`，
与结算 `LayoutSettlementGridCells:1068` 完全一致。

同时 `ItemButton` 转为纯命中层：

```lua
button:SetBackgroundColor({R = 0, G = 0, B = 0, A = 0})
button:SetVisibility(ESlateVisibility.HitTestInvisible)
```

### 2. `ItemArt` 必须折叠，且 `ItemImage` 不再折叠

`CELL_CHROME_NAMES` 里 `ItemImage` 是**格子纹理的载体**，不能再折叠；
`ItemArt` / `CardBackground` / `NameFrameImage` 必须折叠（`ItemArt` 是遮挡 `ItemImage` 的元凶）。

### 3. 覆盖层顺序

`EnsureOverlays` / `RaiseOverlays` 的「先 RemoveFromParent 再 AddChildToCanvas 追加末尾」
保持不变 —— 这是覆盖层在最上层的保证，与格子像素载体改动互不冲突。

---

## 三、验收判据

双客户端 PIE（`team_count=2`）后逐项核对：

1. 仓库格子可见（84 格纹理/边框齐全）；
2. 藏品图浮在格子上方，任意滑动位置均不被格盖住；
3. `ItemArt` 折叠成功（`ApplyCellChrome` 日志含 `ItemArt`）；
4. `EnsureOverlayOrder ... wrongCount=0`。

## 四、前八轮失败路径归档（避免重蹈）

| 轮次 | 尝试 | 失败原因 |
|---|---|---|
| 1-4 | 调 `SetZOrder` | 本引擎 z 不驱动绘制顺序 |
| 5 | 勾 `bIsVariable` + `ClipToBounds` | 裁切矩形(85.2) ≪ 内容(224×141) → 整格裁没 |
| 6 | 直接 `AddChildToCanvas` 重挂 | 对已同父控件不改变相对顺序 |
| 7 | 底色 `A=0` | 连格子一起抹掉（A 是绘制开关） |
| 8 | 恢复 `A=1` + 去裁切 | 格子回来了，但遮挡回归（本轮起点） |
| 9 | **迁移到结算架构：像素交给 ItemImage** | ← 正解 |
