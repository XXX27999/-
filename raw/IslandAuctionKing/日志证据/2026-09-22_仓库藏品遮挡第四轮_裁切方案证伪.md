# 仓库藏品遮挡 · 第四轮实测（裁切方案证伪）

## 一、用户现象（复报）

> 「往下滑动时还是会被仓库格子盖住」
> 「在滑动框上方部分没遮挡，下方部分还是被遮挡，并且往下滑动时上方的也会被遮挡」

## 二、本轮假设（方案 B）与证伪

**假设**：`WarehouseContentSizeBox` / `WarehouseContentCanvas` 引入了额外的裁切空间，
导致子控件被切到不同 draw layer，`ZOrder` 只在各自层内生效，滚出视口后底格反压覆盖层。

**依据**：官方 `UWidget.Clipping` NOTE「Elements in different clipping spaces can not be batched together」。

**实测结果：假设不成立。**

`ApplyClippingPolicy` 执行日志：

```
【AuctionWarehouseCellService+ApplyClippingPolicy】关键数据 name=WarehouseContentSizeBox before=0 after=0 setOK=true error=nil
【AuctionWarehouseCellService+ApplyClippingPolicy】关键数据 name=WarehouseContentCanvas before=0 after=0 setOK=true error=nil
【AuctionWarehouseCellService+ApplyClippingPolicy】出口 appliedCount=2 failedCount=0 inheritClipping=0
```

两者**本来就是 0（Inherit）**，写入前后均为 0。即：链路上**不存在多余的裁切空间**，
方案 B 无对象可改。`EWidgetClipping.Inherit = 0`（来源：官方 `EWidgetClipping` 枚举文档）。

## 四、由此确立的事实

1. **`Slot:GetZOrder()` / `SetZOrder()` 在本引擎完全生效**。
   覆盖层读到 `40`，底格读到 `10`，与 `layout.overlayZOrder=40` / `baseCellZOrder=10` 完全一致。
   → 此前「SetZOrder 无法翻转绘制顺序」的注释结论**错误**，本轮证伪。
2. **绘制顺序已按 Z 值正确排序**（首 10 → 末 40）。
3. **`bExplicitCanvasChildZOrder` 在本引擎不存在**。
   客户端日志明确：`Object [CanvasPanel ...WarehouseContentCanvas] PropName [bExplicitCanvasChildZOrder]: property not exist`。
   `EnableExplicitZOrder()` 的四个候选字段全部探不到，该函数恒返回 false。
   → 之前「未开启显式 ZOrder 导致 ZOrder 不参与排序」的推论**不成立**；本引擎按 Slot ZOrder 排序是默认行为。
4. **裁切空间只有一层**（ScrollBox 的 `ClipToBounds`），不存在「跨裁切空间合批」问题。
5. **`ScrollBox` 直接子控件数为 1**（只挂 SizeBox），与「SizeBox → ContentCanvas → 148 子控件」的链路一致。

## 五、未决 / 下一步

- 现象（滑动时被盖住）与「ZOrder 已正确」之间存在矛盾，**尚未定位到最终根因**。
- 待验证方向（按优先级）：
  1. **`ScrollBox` 自身的渲染裁剪与子控件绘制顺序**：`ClipToBounds` 下，ScrollBox 的滚动
     是否会重排子控件的 draw order（而非沿用 Slot ZOrder）。
  2. **底格控件自身是否带遮挡性容器**：`CollectibleCodexItemUI_C` 内是否有不透明 `Image`/`Border`
     以更高 z 覆盖；需查单格控件内部结构。
  3. **覆盖层是否真的可见**：`imgVis=3`（`HitTestInvisible`）不影响渲染，但需确认 05–32 的 `Hidden` 状态与画刷。
  4. 用「滚动后立即采样」验证：滚动过程中 `child0/childLast` 的 z 是否被引擎改写。
- 本轮探针受限于会话中断（12:05:52 PIE 停止），未能完成滚动中的采样。

## 六、方法学教训

1. **`doluastring` 不能用 `\n`**：控制台按单行处理，含换行只回显不执行。
2. **片段过长被静默丢弃**：只回显、无输出、无报错。探针必须拆小。
3. **`doluastring` 返回 `{}` ≠ 成功**，必须读客户端日志。
4. **PIE 会自行停止**：中途停止后所有探针失效，需重启（本工程必须 `team_count=2`）。
5. **先测再改**：本轮若未实测就继续按裁切假设改代码，会叠加无效改动。
   两次「按推理改代码」均被实测推翻（ZOrder 无效论、裁切空间论）。
