## 1. 知识来源与查证规则

### 1.1 官方文档优先

涉及绿洲起源 API、Lua 生命周期、蓝图 JSON、组件、事件、RPC、PIE、热更新、服务端/客户端调用限制时，必须先通过 `oasis-official-docs` 技能查询官方文档，再回答或编码。

### 1.2 项目经验库辅助

涉及 `oasis-skill-plus` 项目已有经验、历史问题、实现模式、最佳实践时，必须同时查阅 `oasis-skill-plus` 记录。

### 1.3 禁止编造

无法从官方文档或项目记录确认的 API、字段、端侧限制、蓝图结构，不得编造。必须明确说明"不确定，需要进一步查证"。

### 1.4 不确定必查

只要对 API 是否存在、参数含义、返回值、调用端限制、生命周期时机、蓝图字段结构存疑，必须先查证再输出。

## 2. RPC 整体架构

### 2.1 架构总览

```
┌─────────────────────────────────────────────────────────┐
│                    客户端 (Client)                       │
│                                                         │
│  UI / Widget / Tick                                    │
│       │                                                 │
│       ▼                                                 │
│  UnrealNetwork.CallUnrealRPC(self, self,                 │
│       "KHDRPC_Call", "FuncName", ...)                   │
│       │                                                 │
│       ▼                                                 │
│  UGCPlayerController:KHDRPC_Call(funcName, ...)         │
│       │                                                 │
│       ▼                                                 │
│  CF_KHDRPC(funcName, self, ...)                         │
│       │  (通过 __call 元表分发)                          │
│       ▼                                                 │
│  CF_KHDRPC.FuncName(self, ...)                          │
│       │                                                 │
│       ▼                                                 │
│  (网络传输到服务端)                                     │
└─────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────┐
│                    服务端 (Server)                       │
│                                                         │
│  CF_KHDRPC.FuncName(self, ...)                          │
│       │  (实际执行逻辑)                                  │
│       ├── HasAuthority() = true → 执行业务逻辑           │
│       └── HasAuthority() = false → 打印日志跳过           │
│       │                                                 │
│       ▼ (如需通知客户端)                                │
│  UnrealNetwork.CallUnrealRPC(self, self,                 │
│       "FWDRPC_Call", "ClientFuncName", ...)             │
│       │                                                 │
│       ▼                                                 │
│  (网络传输到所有客户端)                                 │
└─────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────┐
│                    客户端 (Client)                       │
│                                                         │
│  UnrealNetwork.CallUnrealRPC → 触发 FWDRPC_Call         │
│       │                                                 │
│       ▼                                                 │
│  UGCPlayerController:FWDRPC_Call(funcName, ...)         │
│       │                                                 │
│       ▼                                                 │
│  CF_FWDRPC(funcName, self, ...)                         │
│       │  (通过 __call 元表分发)                          │
│       ▼                                                 │
│  CF_FWDRPC.FuncName(self, ...)                          │
│       │                                                 │
│       ├── HasAuthority() = true → 打印日志跳过           │
│       └── HasAuthority() = false → 执行业务逻辑           │
└─────────────────────────────────────────────────────────┘
```

### 2.2 两种 RPC 方向

| 方向 | 分发器函数 | 脚本文件 | 调用方式 | 执行端 |
|------|-----------|----------|----------|--------|
| 客户端 → 服务端 | `KHDRPC_Call` | `CF_KHDRPC.lua` | `CallUnrealRPC(self, self, "KHDRPC_Call", "FuncName", ...)` | 服务端 |
| 服务端 → 客户端 | `FWDRPC_Call` | `CF_FWDRPC.lua` | `CallUnrealRPC(self, self, "FWDRPC_Call", "FuncName", ...)` | 客户端 |

### 2.3 关键约定

- `KHDRPC` = "客户端到服务端 RPC"（KHD = 客户端 → 服务端）
- `FWDRPC` = "服务端到客户端 RPC"（FWD = 转发到客户端）
- 所有 RPC 函数均通过 **字符串名称** 进行分发，利用 Lua metatable 的 `__call` 元方法实现

## 3. 脚本命名与文件组织

### 3.1 文件命名

| 文件 | 路径 | 说明 |
|------|------|------|
| `CF_KHDRPC.lua` | `Script/Blueprint/CF_KHDRPC.lua` | 所有客户端→服务端 RPC 函数实现 |
| `CF_FWDRPC.lua` | `Script/Blueprint/CF_FWDRPC.lua` | 所有服务端→客户端 RPC 函数实现 |

### 3.2 函数命名约定

#### 客户端→服务端 RPC（CF_KHDRPC）

```
ServerRPC_<动作描述>(self, ...)
```

命名规范：
- 必须以 `ServerRPC_` 开头
- 使用帕斯卡命名（PascalCase），首字母大写
- 动词在前，名词在后

示例：
```lua
ServerRPC_ApplyAreaCare(self, AreaCareType, AreaRideType, PetActor)
ServerRPC_BuyPetFromPool(self, RowName, Price)
ServerRPC_SetSelectedChenHao(self, TitleName)
```

特殊约定：
- 特定功能 RPC 不使用 `ServerRPC_` 前缀，直接使用功能名称，如：
  - `StartWork(self, WorkArea, WorkCount, PetActor)`
  - `Warehouse(self, behavior, actor)`
  - `Map(self, num)`
  - `PetNameChange(self, Name, Actor, IsBag)`
  - `OnGoldChanged(self, DeltaGold)`
  - `OnItemSelected(self, Index, PetStateUI)`
  - `Server_SendLoad(self)`
  - `ServerReceiveUseItem(self, Type, Actor)`
  - `SpawnPet(self, Path, Location, Rotation, Scale)`
  - `SpawnPetRPC(self, Path, Rotation, Scale, Name, Texture)`

#### 服务端→客户端 RPC（CF_FWDRPC）

```
Client<动作描述>(self, ...)
```

命名规范：
- 必须以 `Client` 开头
- 使用帕斯卡命名（PascalCase）

示例：
```lua
ClientOpenWorkingAreaUI(self, WorkArea, UIPath)
ClientShowTiShi(self, TipText)
ClientUpdateUI3D(self, ui3dName)
ClientBroadcastSelectedChenHao(self, PlayerKey, TitleName)
```

特殊约定：
- 部分函数使用 `C_` 前缀替代 `Client`，如 `C_ShowOfflineWorkGoldTips`、`C_SyncTimeOffsetForDebug`
- 建议统一使用 `Client` 前缀，减少不一致性

### 3.3 函数签名格式

```lua
--- <函数功能描述>
--- @param self UGCPlayerController_C 控制器实例
--- @param Param1 type1 参数1说明
--- @param Param2 type2 参数2说明
--- @return type 返回值说明（如适用）
function CF_KHDRPC.ServerRPC_<FuncName>(self, Param1, Param2)
```

注释要求：
- 第一行简要说明函数功能
- 每个 `@param` 标注参数类型和说明
- 如有返回值，标注 `@return` 说明

## 4. RPC 分发器模式

### 4.1 KHDRPC_Call / FWDRPC_Call 分发器

在 `UGCPlayerController.lua` 中定义两个分发函数：

```lua
function UGCPlayerController:GetAvailableClientRPCs()
    return "FWDRPC_Call","KHDRPC_Call"
end

--- 服务端 RPC 分发器
function UGCPlayerController:KHDRPC_Call(funcName, ...)
    CF_KHDRPC(funcName, self, ...)  -- 通过 __call 元表分发到具体函数
end

--- 客户端 RPC 分发器
function UGCPlayerController:FWDRPC_Call(funcName, ...)
    CF_FWDRPC(funcName, self, ...)  -- 通过 __call 元表分发到具体函数
end
```

### 4.2 模块元表分发机制

`CF_KHDRPC.lua` 和 `CF_FWDRPC.lua` 中必须包含 `setmetatable` 实现：

```lua
-- 模块级函数列表缓存
local _functionList = nil
function CF_KHDRPC.GetFunctionNames()
    if not _functionList then
        _functionList = {}
        for k, v in pairs(CF_KHDRPC) do
            if type(v) == "function" and k ~= "GetFunctionNames" then
                table.insert(_functionList, k)
            end
        end
    end
    return _functionList
end

-- 字符串名称分发元表
setmetatable(CF_KHDRPC, {
    __call = function(t, funcName, ...)
        local fn = t[funcName]
        if fn then
            fn(...)
        else
            ugcprint("[CF_KHDRPC] 未知函数: " .. tostring(funcName))
        end
    end
})

return CF_KHDRPC
```

### 4.3 调用链路完整示例

**客户端调用（从 UI/Tick 触发）：**
```lua
-- 客户端代码中调用服务端 RPC
UnrealNetwork.CallUnrealRPC(self, self, "KHDRPC_Call", "ServerRPC_ApplyAreaCare", "Feed", "", petActor)
```

**服务端通知客户端：**
```lua
-- 服务端代码中调用客户端 RPC
UnrealNetwork.CallUnrealRPC(self, self, "FWDRPC_Call", "ClientShowTiShi", "操作成功")
```

## 6. 代码生成铁律

### 6.1 注释规则

#### 变量注释
每个变量声明处必须添加清晰中文注释，说明变量用途。

**正确示例：**
```lua
local PlayerPawn = UGCGameSystem.GetPlayerPawnByPlayerController(self)  -- 玩家Pawn对象，用于获取玩家属性和位置
local CurrentGold = UGCAttributeSystem.GetGameAttributeValue(PlayerPawn, "Gold") or 0  -- 当前金币数量，用于校验是否足够支付
local TargetLocation = { X = PlayerLocation.X + 120, Y = PlayerLocation.Y, Z = PlayerLocation.Z }  -- 宠物传送目标点，默认放在玩家X轴前方约120单位
```

#### 函数注释
每个函数必须注释：
- 函数功能简要说明
- 每个参数的类型和说明（`@param`）
- 返回值说明（`@return`，如有）

### 6.2 日志规则（三层日志结构）

#### 全路径打印
每一条关键执行逻辑都必须使用 `ugcprint` 输出日志。每个函数的开头与结尾都必须使用 `ugcprint` 输出日志。

#### 格式固定
日志必须以 `【脚本名+函数名】` 开头。

#### 三层日志结构

每个函数必须包含以下三级日志：

**第一层：入口层**
```lua
ugcprint("【CF_KHDRPC+FuncName】=== 开始[功能名称] ===")
```

**第二层：数据层**
输出该函数涉及的所有关键上下文数据：
- 自身引用 `self`、`HasAuthority` 状态
- 所有入参
- 关键变量的值、中间计算结果
- 条件分支的比对结果
- 错误/警告时的具体原因和关联数据

```lua
ugcprint("【CF_KHDRPC+FuncName】数据: self=" .. tostring(self) .. ", HasAuthority=" .. tostring(self:HasAuthority()) .. ", Param1=" .. tostring(Param1) .. ", Param2=" .. tostring(Param2))
```

**第三层：出口层**
```lua
ugcprint("【CF_KHDRPC+FuncName】=== [功能名称]完毕：成功 ===")
-- 或
ugcprint("【CF_KHDRPC+FuncName】=== [功能名称]完毕：失败-金币不足 ===")
```

#### 覆盖所有分支
`if-else` 的每个分支都应有相应的日志，不能有静默路径。

**正确示例：**
```lua
if self:HasAuthority() == true then
    ugcprint("【CF_KHDRPC+FuncName】分支: 服务端执行逻辑")
    -- ... 业务逻辑
else
    ugcprint("【CF_KHDRPC+FuncName】分支: 客户端收到RPC调用，不执行服务端逻辑")
end
```

### 6.3 错误处理

#### try-catch 保护
关键逻辑必须用 `pcall` 保护。

#### 标准 pcall 模式

```lua
local bOk, ErrorMessage = pcall(function()
    -- 关键业务逻辑
    -- ...
end)
ugcprint("【CF_KHDRPC+FuncName】数据: bOk=" .. tostring(bOk) .. ", ErrorMessage=" .. tostring(ErrorMessage))
if bOk then
    ugcprint("【CF_KHDRPC+FuncName】分支: 执行成功")
else
    ugcprint("【CF_KHDRPC+FuncName】错误: " .. tostring(ErrorMessage))
end
```

### 6.4 语言与规范

所有代码必须符合绿洲起源编辑器的 Lua 编码规范：
- 使用 `ugcprint` 而非 `print`
- 使用 `pcall` 而非 `xpcall`
- 2 空格缩进
- 变量名使用驼峰命名（camelCase）

## 7. 端侧安全规则

### 7.1 禁止"静默跳过"模式

**禁止**使用 `if not XX then return end` 直接跳过某个端。

**错误示例（禁止使用）：**
```lua
-- ❌ 禁止：静默跳过客户端
function CF_KHDRPC.ServerRPC_FuncName(self, ...)
    if not self:HasAuthority() then return end  -- 客户端静默跳过，无日志
    -- 服务端逻辑
end

-- ❌ 禁止：静默跳过服务端
function CF_FWDRPC.ClientFuncName(self, ...)
    if self:HasAuthority() then return end  -- 服务端静默跳过，无日志
    -- 客户端逻辑
end
```

### 7.2 必须使用 HasAuthority 分支包裹

服务端逻辑必须使用 `if self:HasAuthority() then ... end` 结构包裹。
客户端逻辑必须使用 `if self:HasAuthority() == false then ... end` 结构包裹。
**两端都必须打印日志**，不允许任何端静默跳过。

#### KHDRPC（客户端→服务端，理应服务端执行）

```lua
function CF_KHDRPC.ServerRPC_FuncName(self, ...)
    ugcprint("【CF_KHDRPC+ServerRPC_FuncName】=== 开始[功能名称] ===")
    ugcprint("【CF_KHDRPC+ServerRPC_FuncName】数据: self=" .. tostring(self) .. ", HasAuthority=" .. tostring(self:HasAuthority()) .. ", ...")
    local bOk, ErrorMessage = pcall(function()
        if self:HasAuthority() == true then
            ugcprint("【CF_KHDRPC+ServerRPC_FuncName】分支: 服务端执行逻辑")
            -- 服务端业务逻辑
        else
            ugcprint("【CF_KHDRPC+ServerRPC_FuncName】分支: 客户端收到RPC函数调用，不执行服务端逻辑")
        end
    end)
    ugcprint("【CF_KHDRPC+ServerRPC_FuncName】数据: bOk=" .. tostring(bOk) .. ", ErrorMessage=" .. tostring(ErrorMessage))
    if bOk then
        ugcprint("【CF_KHDRPC+ServerRPC_FuncName】分支: 执行成功")
    else
        ugcprint("【CF_KHDRPC+ServerRPC_FuncName】错误: " .. tostring(ErrorMessage))
    end
    ugcprint("【CF_KHDRPC+ServerRPC_FuncName】=== [功能名称]完毕 ===")
    return nil
end
```

#### FWDRPC（服务端→客户端，理应客户端执行）

```lua
function CF_FWDRPC.ClientFuncName(self, ...)
    ugcprint("【CF_FWDRPC+ClientFuncName】=== 开始[功能名称] ===")
    ugcprint("【CF_FWDRPC+ClientFuncName】数据: self=" .. tostring(self) .. ", HasAuthority=" .. tostring(self:HasAuthority()) .. ", ...")
    local bOk, ErrorMessage = pcall(function()
        if self:HasAuthority() == true then
            ugcprint("【CF_FWDRPC+ClientFuncName】分支: 服务端不创建客户端UI")
        else
            ugcprint("【CF_FWDRPC+ClientFuncName】分支: 客户端执行逻辑")
            -- 客户端业务逻辑
        end
    end)
    ugcprint("【CF_FWDRPC+ClientFuncName】数据: bOk=" .. tostring(bOk) .. ", ErrorMessage=" .. tostring(ErrorMessage))
    if bOk then
        ugcprint("【CF_FWDRPC+ClientFuncName】分支: 执行成功")
    else
        ugcprint("【CF_FWDRPC+ClientFuncName】错误: " .. tostring(ErrorMessage))
    end
    ugcprint("【CF_FWDRPC+ClientFuncName】=== [功能名称]完毕 ===")
    return nil
end
```

### 7.3 规则例外说明

如果函数只允许某一端执行，也必须在另一端打印明确日志说明，不允许静默 return。

**允许的例外写法（带日志的守卫）：**
```lua
if not self:HasAuthority() then
    ugcprint("【CF_KHDRPC+FuncName】分支: 非服务端调用，跳过执行")
    return false  -- 必须先打印日志再 return
end
```

**允许的所有端通用的辅助函数（非 RPC）：**
辅助函数如果被 RPC 函数内部调用，且明确只在服务端分支内执行，可以不做 HasAuthority 检查。

## 8. API 调用安全规则

### 8.1 调用端确认

调用任何 API 前，必须通过官方文档确认：
- API 是否存在
- 参数和返回值是否正确
- **仅服务端可用、仅客户端可用，还是双端可用**
- 是否有生命周期或对象类型限制

### 8.2 常见 API 端侧分类（基于项目经验）

| API | 调用端 | 说明 |
|-----|--------|------|
| `UGCAttributeSystem.*` | 双端 | 属性系统，服务端写入，客户端只读 |
| `UGCGameSystem.*` | 双端 | 游戏系统查询函数 |
| `UGCActorComponentUtility.SpawnActor` | 服务端 | 生成 Actor |
| `UGCWidgetManagerSystem.*` | 客户端 | UI 管理 |
| `UserWidget.*` | 客户端 | UI Widget 操作 |
| `UGCPersistEffectSystem.*` | 服务端 | 持久效果系统 |
| `UGCBackpackSystemV2.*` | 服务端 | 背包系统 |
| `UGCGameSystem.SendModeCustomEvent` | 双端 | 发送自定义事件 |
| `UGCEventSystem:SendEvent` | 双端 | 发送本地事件 |
| `UGCPlayerControllerSystem.*` | 双端 | 玩家控制器系统 |
| `K2_SetActorLocation` | 双端 | Actor 位置设置 |
| `SetIgnoreMoveInput` | 服务端 | 设置移动输入 |

### 8.3 严禁越界调用

绝对不能在任何超出文档规定的端上调用 API。例如：
- 不能在客户端调用 `SpawnActor`
- 不能在服务端调用 `AddToViewport`
- 不能在客户端调用 `SetGameAttributeValue` 进行写入（只读查询可以）

### 8.4 不确定时的处理

如果对 API 的单双端限制不清楚，必须先查阅 `oasis-official-docs` 技能确认。禁止凭猜测使用 API。

## 9. 蓝图与文件联动规则

### 9.1 蓝图事件机制

蓝图没有事件图标。所有事件默认启用，只通过对应函数调用触发。

### 9.2 蓝图修改方式

蓝图结构修改优先编辑 `_JsonOutput` 文件夹下对应 JSON 文件，不直接假设可修改 `.uasset`。

### 9.3 JSON 参照要求

修改蓝图、脚本挂载、组件引用、资源引用、事件绑定前，必须先检查 `_JsonOutput` 文件夹下同名 JSON 文件：
- 与 Lua 脚本同名的 JSON
- 与相关 `.uasset` 同名的 JSON
- 与当前蓝图、Prefab、组件路径相关的 JSON

### 9.4 一致性要求

修改 Lua、蓝图 JSON、脚本绑定、组件引用、资源路径后，必须确认 Lua 逻辑与 JSON 结构一致，避免脚本引用不存在的组件、变量或资源。

### 9.5 RPC 相关的 JSON 检查要点

- `UGCPlayerController` 的 JSON 文件中必须声明 `KHDRPC_Call` 和 `FWDRPC_Call` 函数
- `GetAvailableClientRPCs()` 必须返回 `"FWDRPC_Call","KHDRPC_Call"`
- 确认蓝图 JSON 中脚本绑定路径指向正确的 `.lua` 文件

## 10. 修改与验证流程

### 10.1 修改前

修改前必须先阅读目标 Lua / JSON 文件上下文，理解现有命名、日志、函数结构、继承关系和调用方式。

### 10.2 修改中

保持原项目代码风格，不随意改名，不删除已有必要逻辑，不引入未确认 API，不添加无依据的资源路径。

### 10.3 修改后

完成脚本或蓝图相关修改后，必须进行可行的静态检查或上下文校验，包括但不限于：

1. **重新读取被修改文件**：确认内容已正确写入，格式无问题
2. **检查语法结构**：函数闭合、变量引用、括号匹配
3. **检查 JSON 与 Lua 引用一致性**：组件名称、脚本绑定路径
4. **检查 RPC 调用链路完整性**：
   - 新增的 RPC 函数是否在 `CF_KHDRPC` 或 `CF_FWDRPC` 中正确注册
   - `setmetatable` 的 `__call` 能否正确分发
   - `CallUnrealRPC` 调用的字符串名称是否与函数名完全一致
5. **检查日志完整性**：三层日志结构是否完备，所有分支是否都有日志
6. **检查端侧安全性**：是否误用 `if not Authority then return end` 跳过一个端

## 15. 附录：常见违规模式与正确写法对照

### 15.1 端侧静默跳过

**违规（禁止）：**
```lua
-- ❌ 服务端函数，客户端静默跳过
function CF_KHDRPC.ServerRPC_DoSomething(self)
    if not self:HasAuthority() then return end  -- 静默跳过
    -- 服务端逻辑
end
```

**正确：**
```lua
-- ✅ 两端都有日志
function CF_KHDRPC.ServerRPC_DoSomething(self)
    ugcprint("【CF_KHDRPC+ServerRPC_DoSomething】=== 开始[执行操作] ===")
    ugcprint("【CF_KHDRPC+ServerRPC_DoSomething】数据: self=" .. tostring(self) .. ", HasAuthority=" .. tostring(self:HasAuthority()))
    if self:HasAuthority() == true then
        ugcprint("【CF_KHDRPC+ServerRPC_DoSomething】分支: 服务端执行操作")
        -- 服务端逻辑
    else
        ugcprint("【CF_KHDRPC+ServerRPC_DoSomething】分支: 客户端跳过服务端逻辑")
    end
    ugcprint("【CF_KHDRPC+ServerRPC_DoSomething】=== [执行操作]完毕 ===")
end
```

### 15.2 缺少入口/出口日志

**违规：**
```lua
function CF_KHDRPC.ServerRPC_DoSomething(self)
    -- 无入口日志
    if self:HasAuthority() then
        -- 业务逻辑
    end
    -- 无出口日志
end
```

**正确：**
```lua
function CF_KHDRPC.ServerRPC_DoSomething(self)
    ugcprint("【CF_KHDRPC+ServerRPC_DoSomething】=== 开始[执行操作] ===")
    -- ... 逻辑 ...
    ugcprint("【CF_KHDRPC+ServerRPC_DoSomething】=== [执行操作]完毕 ===")
end
```

### 15.3 缺少数据层日志

**违规：**
```lua
ugcprint("【CF_KHDRPC+FuncName】=== 开始 ===")
-- 没有打印任何参数和状态
```

**正确：**

ugcprint("【CF_KHDRPC+FuncName】=== 开始[功能名称] ===")

### 15.4 缺少 pcall 保护

**违规：**
```lua
function CF_KHDRPC.ServerRPC_DoSomething(self)
    if self:HasAuthority() then
        local result = SomeAPIThatMightFail()  -- 无保护，崩溃会导致整个函数失败
    end
end
```

**正确：**

function CF_KHDRPC.ServerRPC_DoSomething(self)

    end
end
```
