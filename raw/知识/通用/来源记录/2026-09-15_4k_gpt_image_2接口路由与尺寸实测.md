## 背景

用户在 WorkBuddy 中配置了自定义模型 `custom-local:4k/gpt-image-2`（vendor=Custom，url=`https://apihub.veletis.com/v1`，`supportsImages=true`、`supportsToolCall=true`）。本轮任务是验证该模型能否调用、走哪个端点、支持哪些参数。

同批配置的自定义模型还有 `custom-local:deepseek-v4-flash`、`custom-local:gemini-3.5-flash`，共用同一密钥。

## 实测过程与结果

### 1. 模型存在性

`GET https://apihub.veletis.com/v1/models` → 200，返回 21 个模型，其中含：

- `4k/gpt-image-2`（本轮目标）
- `4k/gpt-image-2.5-flare`、`4k/gpt-image-2.5-sunburst`（同系列，未测）
- `deepseek-v4-flash`、`gemini-3.5-flash` 等对照组

### 2. 端点路由

| 请求 | 结果 |
| --- | --- |
| `/v1/chat/completions` + `4k/gpt-image-2`，中文长提示「一只橘猫趴在阳光下的窗台上，写实摄影风格」 | ❌ 502 `upstream_server_error`（4.7s） |
| `/v1/chat/completions`，英文短提示「a red apple on a table」 | ❌ 502 `upstream_server_error`（1.4s） |
| `/v1/chat/completions`，英文短提示「draw a red apple」（等待 5s 后第 3 次） | ❌ 502 `upstream_server_error`（1.2s） |
| `/v1/chat/completions` + `deepseek-v4-flash`（对照组） | ✅ 200，返回 `ok` |
| `/v1/images/generations` + `4k/gpt-image-2` | ✅ 200，`data[0].b64_json` |

对照组成功说明密钥与网关正常，502 只发生在该图像模型的对话链路。

### 3. 尺寸矩阵

| `size` | HTTP | 结果 |
| --- | --- | --- |
| `1024x1024` | 200 | PNG，实测 1024x1024，1 453 558 字节，耗时 56.0s |
| `1024x1536` | 200 | PNG，实测 1024x1536，1 795 570 字节，耗时 133.9s（人物立绘补充测试） |
| `2048x2048` | 200 | PNG，实测 2048x2048，6 104 763 字节，耗时 346.2s |
| `auto` | 200 | PNG，实测 1254x1254 |
| `1536x1024` | 503 | `upstream_configuration_error` |
| `4096x4096` | 400 | `invalid_parameter_value`（复测一次，同样 400） |
| `4096x2160` | 400 | `invalid_parameter_value` |
| `2K` | 400 | `invalid_parameter_value` |
| `4K` | 400 | `invalid_parameter_value` |

### 4. 参数白名单

一次性传 `quality=high`、`output_format=jpeg`、`background=transparent` → 400 `unsupported_parameter`。

服务端回显（不可控）：`background: opaque`、`output_format: png`、`quality: low`。

`usage` 示例（2048 图）：`input_tokens: 48`（text 48 / image 0）、`output_tokens: 892`（image 892 / text 0）、`total_tokens: 940`。

### 5. 耗时基线

- 1024x1024：约 56s
- 1024x1536：约 134s（人物立绘，`output_tokens` 158）
- 2048x2048：约 346s（超过常见 120s 默认超时，必须显式放大超时）

结论：耗时随像素量与主体复杂度上升；1024x1536 与 2048x2048 均超过 120s 默认超时。

## 环境坑

1. 本机 Git Bash 被 WorkBuddy 的 shell shim 污染，直接执行 `ls`/`grep` 报 `command not found`，需先 `export PATH="/usr/bin:/bin:/usr/local/bin:$PATH"`。
2. 长耗时出图请求会被工具默认 120s 超时掐断（第一次 2048 请求即 SIGTERM），需显式加大超时。

## 结论

- `4k/gpt-image-2` 可用，但**只支持 `/v1/images/generations`**，不支持对话端点。
- 名称里的 “4k” 不代表支持 4096：实测上限 2048x2048。
- 只认 4 个参数：`model`、`prompt`、`n`、`size`。
- 与既有 [4k/gpt-image-2 图片生成流程](../工具与流程/4k_gpt_image_2_图片生成流程.md) 中「Codex 本地代理 57321 + OpenAI SDK」路径并存，同属实测，互不否定。
