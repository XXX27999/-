## 一、背景

上一轮日志核查（见 `../日志证据/20260917_离线收益日志核查.md`）结论：结算数值零偏差，但定位到 3 个问题：

1. **缺陷1**：`RevenueUI:Button_57_OnClicked` 对同一实例重复执行 `HideWidget` + `DestroyWidget`。
2. **缺陷2**：`RevenueUI` 引用了 `TextBlock_Title`，但 UMG 资产中不存在该控件。
3. **风险**：离线结算仅依赖「退出游戏时存档写回 `OfflineIncome.ExitTime`」做跨会话幂等；PIE 强停 / 退出存档失败时 `ExitTime` 不更新，下次登录会用同一个 `ExitTime` 重复结算同一段离线时长。

## 三、核查结论（针对用户提出的三个问题）

| 问题 | 结论 | 依据 |
| --- | --- | --- |
| ① 结算时是否读取玩家上次下线时正在打工的宠物列表 | **是**。遍历 `playerController.PetDataArr`，逐宠读 `Behavior`；`Behavior == 3` 判定为打工中 | `PlayerLogin.lua:367-385` |
| ② 是否校验剩余打工次数、耗尽时是否正确终止 | 原逻辑只处理 `behavior == 3 and workCount > 0`；`behavior == 3 and workCount == 0` 落入 `else`，**打工状态不被清除**。本轮新增 `elseif` 分支显式终止 | `PlayerLogin.lua:263-270` |
| ③ 是否存在打工状态未持久化 / 跨次叠加 / 重复领取 | **打工状态已持久化**（`ControllerExitGame.MergeControllerData` 写 `PetData[i].WorkCount/Behavior`，`PetActorDic.LoadPlayerArchive` 读回），**不存在跨次叠加**（每宠 `WorkCount` 独立递减）；**重复领取风险真实存在**——依赖退出时存档写回 `ExitTime`，PIE 强停会导致下次登录重复结算。本轮用「结算后立即写回 + `LastSettledExitTime` 幂等」双重消除 | `ControllerExitGame.lua`、`PetActorDic.lua:346-348`、`PlayerLogin.lua:343-350/408-417` |

**数值平衡未改动**：`settledCount`、`goldEarned = floor(settledCount * goldRate * baseWorkGold)`、`expEarned`、`usedHours` 的计算式与常量（`BASE_WORK_DURATION_SECONDS`、`TIME_CALC_EPSILON_SECONDS`）保持原样。

### 3.1 每只宠物的结算次数是怎么定的（补充确认）

**结论：结算次数以「下线时存档里该宠的剩余打工次数 `WorkCount`」为基数，不是在线重新生成次数。** 但受三重约束：

| 约束 | 规则 | 依据 |
| --- | --- | --- |
| ① 状态门槛 | `Behavior == 3` 且 `WorkCount > 0` 才结算 | `PlayerLogin.lua:213` |
| ② 次数上限 | 基数 = 存档中的 `WorkCount`（下线时的剩余次数） | `PlayerLogin.lua:204/218` |
| ③ 时长上限 | 非永久托管且 `总需要时长 > 可用时长` 时，`settledCount = min(WorkCount, floor(可用秒数 / 单次打工秒数))` | `PlayerLogin.lua:221-228` |

- 单次打工耗时 `GetWorkDurationSeconds` = `max(15 - PetWorkTimeReduceTotal, 1)` 秒（`PlayerLogin.lua:131-137`），`BASE_WORK_DURATION_SECONDS = 15`。
- 结算后**无条件**写 `Behavior = 2`、`WorkYou = 0`（`PlayerLogin.lua:248-249`）。因此**若离线时长不足以装下全部次数，`remainingWorkCount = WorkCount - settledCount` 会留在存档里，但该宠已不再是打工状态，下次登录因 `Behavior != 3` 不会再结算**——这部分剩余次数实际处于冻结状态，需玩家重新发起打工。属既有行为，本轮未改动。
- **多宠之间是共享时长池、先到先得**：`remainingSettlementHours` 逐宠扣减 `usedHours`（`PlayerLogin.lua:379-383`），按 `PetDataArr` 索引顺序分配，排在后面的宠物可用时长可能更少。

## 五、踩坑记录

1. **补丁锚点必须落在正确的分支**：首轮补丁把 `PersistOfflineSettlement` 调用插进了 `if finalizeOk then ... else` 的 **else 分支**，导致只在「收尾写属性失败」时才写回存档。修正后移到分支外无条件执行。**教训：补丁的 old 串必须带上足够的分支上下文**（本例用 `tostring(finalizeError))\n      end\n\n      -- 结算结果立即写回存档` 作为新代码独有幂等标记）。
2. **`ue.widget_slot` 不能写 CanvasPanelSlot**：`Position` / `Size` / `AutoSize` 均返回 `failed to set`，`LayoutData` 结构体同样不可写。UMG 槽位布局只能在编辑器里手拖，或在 Lua 运行时用 `UCanvasPanelSlot:SetPosition/SetSize` 校正。
3. **`ue_py` 里对 UObject 调 `dir()` 会挂起**，触发 `UE_PY_WAIT_TIMEOUT`（120s）。探测属性改用 `ue.widget_inspect` 或逐个 `getattr`。
4. **UMG 资产类名是 `UGCWidgetBlueprint`**，不是 `UserWidget`；`ue.load_object(UserWidget, path)` 会报「package 中无该资产」。先用 `ue.list_assets('<目录>')` 取 `load_path`。
5. **Lua 侧 `FVector2D` 可直接传表**：工程内 `Script/UI/text1.lua:199/233` 已在用 `slot:SetSize({X = 139, Y = 136})`，与官方 `SetSize(FVector2D)` 一致。

### 7.1 永久托管标记在逐宠结算调用处被硬编码为 false

- 现状：`PlayerLogin.lua:379` 调用 `SettlePetOfflineWork(playerPawn, petActor, remainingSettlementHours, false, workDurationSeconds)`，第 4 个形参 `hasPermanentPrivilege` **恒为 `false`**，而外层同作用域已有真实值 `hasPermanentPrivilege`（`PlayerLogin.lua:352`）。
- 结果：对永久托管玩家，函数内部仍会走「按时长上限截断 `settledCount`」并计算 `usedHours > 0`，进而扣减共享时长池 `remainingSettlementHours`（`PlayerLogin.lua:383`）；而外层 `PlayerLogin.lua:388-392` 又不写 `OfflineIncomeTime` 属性，形成「池被扣但属性不扣」的不一致。
- 实际影响估计很小：单次打工仅 15 秒（最低 1 秒），永久托管池初值为 `elapsedOfflineHours`（`PlayerLogin.lua:357`），正常离线时长远大于消耗量，只有极短离线才会触发截断。
- 状态：**推断**，未实机验证，未确认是否为有意设计。因涉及数值平衡口径，本轮**不做修改**，需需求方确认后另开一轮处理。
