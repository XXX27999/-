# 装扮材质表控件字段扩展实测

- **日期**：2026-09-14
- **项目**：IslandAuctionKing（《海岛竞拍王》）
- **主题**：给已上线的 `DressMaterialTable` 增加「目标控件」字段，并按控件展开行实现材质隔离
- **证据状态**：项目实测（MCP 回读 + UAssetGUI JSON 双证，逐字段全量比对通过）
- **关联主题**：[配置表与结构体的 MCP 编辑](../工具与流程/配置表与结构体的MCP编辑.md)（本页结论已写入其第六节）

## 一、需求与判读

用户要求：`/IslandAuctionKing/Asset/Data/Table/Customized/Dress/DressMaterialTable` 增加字段，
标识每条材质记录对应的 UI 控件，确保不同 UI 控件的材质**相互独立、互不共通**，并说明字段命名与取值。

关键判读：**「每条记录对应一个控件」意味着行必须按控件展开**。
只在字段里写「适用控件清单」满足不了隔离要求——共享一条记录就是共享状态。

先确认粒度后动手（`AskUserQuestion`），选定「仅 8 个已定名控件展开」。

## 二、改动前的真实状态

| 项 | 改动前 |
| --- | --- |
| 行结构体 | `UGCTemplateRowStruct_DressMaterialTable`，4 列（`ValueType` / `Value` / `Description` / `ModificationNotes`） |
| 行数 | 16（1 行 `Dress.Material.TablePath` + 15 行材质） |
| 行名 | `Dress.Material.<材质键>`，**无控件归属** |
| 控件表 | `DressControlTable` 18 行，12 个区域中 8 个已定名控件名、4 个未定 |

8 个已定名控件（来自 `DressControlTable` 的 `Value`）：

`参考图`（主界面底图）、`HUDBackgroundPanel`、`RightDetailPanel`、`WarehousePanel`、
`TopBarPanel`、`FooterPanel`、`BidKeypadPanel`、`PropPanel`

## 三、落地方案

### 字段

| 项 | 值 |
| --- | --- |
| `VarName` | `TargetWidget` |
| `FriendlyName` | `目标控件名` |
| 类型 | `string` |
| 取值 | 目标 UI 控件名，与 `DressControlTable` 同区域行的 `Value` 完全一致 |
| 空串 | 未定项 / 非材质记录（元数据行），脚本跳过 |

### 行名

`Dress.Material.<界面键>.<区域键>.<材质键>`，与控件表的 `Dress.Control.<界面键>.<区域键>` 同级。

例：`Dress.Material.Auction.BidBoard.Gold` → 报价板 · 金品质。

### 行数

8 控件 × 15 材质 = **120 条**，加 1 行元数据共 **121 行**。
4 个未定区域（玩家头像框、玩家称号、拍卖席位、结算界面整体）**不建空行**。

## 五、关键陷阱

1. **`clone()` 会连带模板的 `FriendlyName` 与 `ToolTip`**。只改 `VarName` 时，
   编辑器列显示名仍是模板那一列的旧值。第一次加字段就踩到了（显示名成了 `TargetWidget`、
   提示还是 `Value` 的文案）。改显示名只能 `struct_remove_variable(v.VarGuid)` 再重加。
2. **`struct_remove_variable` 只接受 `FGuid`**，`v.VarGuid` 可取；传下标/名称报 `object is not a FGuid`。
3. **没有「改行」API**。批量写入时已存在的行被 `SKIP_EXISTS` 跳过，要改文案只能
   `data_table_remove_row` + `data_table_add_row`。本次元数据行就是这么修的。
4. **JSON 里 `ObjectMetaDataEntry` 条数 ≠ 变量数**。实测 5 个变量却出现 15 条
   `ObjectMetaDataEntry`（混入了被引用结构体的元数据）。校验变量数要看
   `StructVariableDescription` 出现次数与 `VarName` 序列。
5. **加字段不影响已有行**，旧行该列取默认空串，无需回填；但新字段若参与逻辑判断，
   记得让脚本把空串当「跳过」。
