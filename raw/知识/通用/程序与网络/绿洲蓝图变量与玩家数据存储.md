## 核心结论

玩家私有运行时数据，优先在工程 `UGCPlayerController` 蓝图上建变量，用 Lua 读写 `playerController.变量名`。不要把金币、选择结果、私有进度塞进 UI Widget 或散落的 Lua 模块全局表。

加载该类用官方路径函数，不要手写 `/Game/`：

```lua
local pcClassPath = UGCGameSystem.GetUGCResourcesFullPath("Asset/Blueprint/UGCPlayerController.UGCPlayerController_C")
```

MCP 改蓝图资产时用 `/<ProjectName>/Asset/Blueprint/UGCPlayerController`，不要带 `_C`。`_C` 是生成类后缀，给 `LoadClass` / `GetUGCResourcesFullPath` 用。

官方框架不允许把这句话理解成「所有和玩家有关的数据都只能放 Controller」：

| 数据性质 | 存放位置 | 依据 |
| --- | --- | --- |
| 仅自己需要：金币、击杀、私有选择、私有 UI 状态 | `UGCPlayerController` 蓝图变量 | 官方：Controller 适合自身参数；工程约定：优先建在该蓝图 |
| 全员都要看的阶段、倒计时、全局比分 | `UGCGameState` | 官方：GameState 是全局同步桥梁 |
| 护甲、血量、攻击力等角色实体属性 | PlayerPawn | 官方：角色强相关参数 |
| 队友面板、小队小地图，敌人不该看 | PlayerState | 官方：Client 只能拿到同队 PlayerState |
| 静态配置、贴图路径表、时长数值 | DataTable | 配置表规范，不是玩家实例数据 |

需要客户端看到服务端权威值时，必须走属性同步，不能只在一端改 Lua 字段。官方确认链路是：

1. Actor 开启 `Replicates`（面板勾选，或 `AActor.SetReplicates`）。
2. Lua 在对应脚本实现 `GetReplicatedProperties()`，返回变量名字符串。
3. 需要回调时实现 `OnRep_变量名()`。
4. 只在 `HasAuthority()==true` 的 DS 写权威值。Client 改复制变量不会回到 DS。

蓝图变量面板上的「变量复制」对应 `FBPVariableDescription.ReplicationCondition` / 复制标记，官方 Wiki 没有操作页。工程约定：需要跨端同步的蓝图变量要开启变量复制。它不能替代第 2 步的 `GetReplicatedProperties()`，两者关系见待查证。

## 可执行步骤

### 1. 先判定数据该不该放 Controller

1. 只服务当前玩家、UI 从自己的 PC 读：放 `UGCPlayerController`。
2. 其他客户端也要读同一份：不要只放 PC。全员走 GameState，队友走 PlayerState。
3. 纯配置不放蓝图变量，放 `Asset/Data/Table/Customized/<功能>/`。
4. UI Widget 只展示，不存权威玩家数据。

### 2. 在 UGCPlayerController 建变量

手工：打开 `Asset/Blueprint/UGCPlayerController` → 我的蓝图 → 新增变量 → 设类型、分类、是否复制 → 编译保存。

MCP 简单类型（项目实测，新建 Actor 探针）：

```python
bp = ue.load_object(Blueprint, "/IslandAuctionKing/Asset/Blueprint/UGCPlayerController")
ue.blueprint_add_member_variable(bp, "ProbeGold", "int")
ue.compile_blueprint(bp)
bp.save_package()
```

结构体成员按 IslandAuctionKing 实测：

1. 先建 UserDefinedStruct，schema 回读字段类型。
2. 写前备份到 `D:\知识库\和平精英绿洲起源\备份\<ProjectName>\<YYYYMMDD>_<Theme>\`，禁止写回 UGC 工程 Backup。
3. 在 Controller 上新增成员，类型指向该结构体。
4. 回读 `schema:UGCPlayerController_C?filter=变量名`，确认类型、`[Edit, BPVisible]`。
5. 检查 `NewVariables`：`VarName` 唯一，`VarGuid` 非全 0，`PropertyFlags` 含 `CPF_Edit | CPF_BlueprintVisible`（项目回读为 `5`）。Guid 为 0 或只有 `CPF_Edit=1` 时，编辑器「我的蓝图」可能不显示，Lua 也不当 BlueprintVisible。
6. 编译、保存、重新 `load_object` 再读。写入 API 返回 `None` 不算成功。

Lua 读写：

```lua
ugcprint("【Foo+Bar】入口 pc=" .. tostring(playerController))
if playerController == nil then
    ugcprint("【Foo+Bar】错误 playerController 为空")
    return
end
local gold = playerController.GoldCount
ugcprint("【Foo+Bar】关键数据 gold=" .. tostring(gold))
```

### 3. 需要客户端服务端同步时

官方 Wiki 躲猫猫案例：

```lua
function UGCPlayerController:GetReplicatedProperties()
    return
        "GoldCount",
        "SelectedCharacterId"
end

function UGCPlayerController:OnRep_GoldCount()
    ugcprint("【UGCPlayerController+OnRep_GoldCount】关键数据 GoldCount=" .. tostring(self.GoldCount) .. " HasAuthority=" .. tostring(self:HasAuthority()))
end
```

同时满足：

- Actor 已勾选 `Replicates`。
- 蓝图变量已开启变量复制（工程约定）。
- 权威写入只在 DS：`if self:HasAuthority() then ... else 打日志 end`。
- 禁止用静默 `return` 跳过客户端。
- 互相强依赖的多个值放进同一个 Lua table 再同步；官方说明 `OnRep_` 顺序不保证。
- 一帧内多次改同一复制变量，中间值会丢，只同步最后一次。

`AuctionUITexturePaths` 是客户端读配置表后写入的路径缓存，不是 DS 权威玩家数据，当时没有走复制。不要把它的做法当成同步模板。

## 常见错误

- **把玩家数据写在 UI 蓝图或 Widget Lua 模块全局表**：UI 只在 Client，重开界面或切端后权威对不上。改放到 `UGCPlayerController`。
- **其他玩家也要显示的数据只放 Controller**：Client 拿不到别人的 PC。改 GameState 或 PlayerState。
- **只建了蓝图变量，没开 Actor 复制、也没写 `GetReplicatedProperties`**：Client 读到的是本地默认值。按官方 203 补齐。
- **只勾选模板文档里的 Actor/组件「复制」，以为蓝图变量已经同步**：那是 Actor `Replicates`。变量还要单独处理。
- **MCP 新建变量后面板看不到**：查 `VarGuid` 是否全 0、`PropertyFlags` 是否只有 `1`。项目实测要非零 Guid 且 `PropertyFlags=5`。
- **用 JSON 给蓝图加变量或改复制标记**：禁止。JSON 只读。必须 MCP 回读。
- **客户端改复制变量当扣费/选角结果**：官方属性同步单向 DS→Client，必须 ServerRPC 申请，DS 改值。
- **以为建了蓝图变量就等于持久化**：蓝图变量每局重建，不跨局。必须服务端走 `UGCPlayerStateSystem.Get/SavePlayerArchiveData`，见上文「跨局持久化」。
- **`blueprint_add_member_variable` 传 `"str"`**：会生成 int32。FString 要传 `"string"`。

## 跨局持久化：蓝图变量 ≠ 存档（2026-09-16 项目实测）

**蓝图变量只解决「运行时去哪里读写」，不解决「重进游戏还在不在」。** `UGCPlayerController` 上的变量在每次新对局都会重新构造，值不会自动保留。要跨局/跨重连保留，必须在**服务端**显式落盘到玩家存档，再由服务端写回控制器变量。

IslandAuctionKing 实测链路（`Script/Function/AuctionPlayerService.lua`）：

1. 存档键与版本：`AuctionConfig.ArchiveKey = "IslandAuctionKing"`、`ArchiveVersion = 3`（`Script/Function/AuctionConfig.lua`）。
2. 读：服务端 `LoadOrReconnectPlayer` → `UGCPlayerStateSystem.GetPlayerArchiveData(uid)` → 取 `archive[ArchiveKey]` → 规范化 → 写回 `player.*` 与控制器变量。
3. 写：服务端 `SavePlayer` → 组装 table（含 `Version`）→ `UGCPlayerStateSystem.SavePlayerArchiveData(uid, archive)`。
4. PIE 环境跨会话继承依赖 `Saved/ArchiveData/<Proj>/<uid>.json`；正式环境由平台存档服务承载。

**两个高频坑：**

- **授权过滤吞掉选择**：若 `SavePlayer` 里对「未解锁/测试授权临时选择」做回落（写默认值而非实际选择），玩家在非默认角色或未购买道具组上的选择会**每次都被重置**。修法是加显式开关（如 `Test.PersistTestGrantedSelection`）控制是否直写实际选择，且 `NormalizeArchiveData` 不要因未解锁而清空已有值。
- **只在少数时机落盘**：选择、购买、使用、开局激活扣库存、结算这些状态跃迁点必须**立即**落盘，否则中途退出即丢。做法是把 `SavePlayer` 用 `pcall` 包一层 `SavePlayerImmediate(player, reason)`，在各跃迁点调用，日志带 `reason`。

## 属性标志位 PropertyFlags 与「Instance Editable」（2026-09-16 实测）

> 证据状态：**项目实测（MCP 回读）+ 引擎通用语义**。**本地官方 API 库无 `EPropertyFlags` 页面**（`D:\oasis-skill-plus\docs\api` 下 Glob `**/EPropertyFlags*.md` 零命中），因此 CPF 位值属引擎通用语义推断，未在本地官方文档中逐位核验；UI 侧可用本文「验证步骤」第 2 条 30 秒自查。

### 位值与实测数据

`FBPVariableDescription.PropertyFlags`（官方确认字段，见 `raw/docs/api/cppstruct/F/FB/FBPVariableDescription.md`）常用位：

| 位 | 名称 | 语义 |
| --- | --- | --- |
| `0x1` | `CPF_Edit` | 编辑器可编辑（Class Defaults 可见可改） |
| `0x4` | `CPF_BlueprintVisible` | 蓝图图表 / 脚本可见可读写 |
| `0x20` | `CPF_Net` | 参与网络属性复制 |
| `0x10000` | `CPF_DisableEditOnInstance` | **禁止在关卡实例的 Details 面板编辑**，等价 C++ `EditDefaultsOnly` |

IslandAuctionKing `UGCPlayerController` 实测：

| 变量 | NewVariables flags | 编译后 UProperty flags | Instance Editable |
| --- | --- | --- | --- |
| `AuctionUITexturePaths`（手工在编辑器建） | `5` | `5` | 勾选 |
| `AuctionGold` | `65541` | `1073807877` | **未勾选** |
| `AuctionOwnedPropGroups` / `AuctionOwnedProps` | `65541` | — | **未勾选** |
| `AuctionSelectedCharacter` / `AuctionSelectedPropGroup` / `AuctionGroupPropUsage` | `65541` | `66053`（GroupPropUsage） | **未勾选** |

`65541 = 0x1 | 0x4 | 0x10000`。编译后引擎会再补 `0x200`（`CPF_ZeroConstructor`）等位，所以 UProperty 值大于 NewVariables 值属正常。

### 结论：对哪一类变量无害

`UGCPlayerController` / `UGCGameState` / GameMode / PlayerState 这类**由框架运行时生成、不会被摆进关卡**的类，不勾选 Instance Editable **不会造成任何运行期问题**：

1. **Class Defaults（CDO）仍可见可改**——变量带 `CPF_Edit(0x1)`。`CPF_DisableEditOnInstance` 只禁「关卡实例」，不禁「类默认值」。
2. **Lua / slua 读写不受影响**——slua 通过 UProperty 反射访问，只要求 UProperty 存在，不检查 `CPF_Edit` 或 `DisableEditOnInstance`。项目实测 `AuctionGold`（flags 65541）在 PIE 中长期正常读写。
3. **蓝图图表 Get/Set 节点不受影响**——由 `CPF_BlueprintVisible(0x4)` 决定。
4. **网络属性复制完全无关**——官方依据 `raw/docs/wiki/进阶内容/203_网络同步系统介绍.md:15-16`：同步链路是 ①Actor 勾选 `Replicates` ②Lua 实现 `GetReplicatedProperties()` 返回变量名 ③DS 写权威值。`CPF_Edit` / `DisableEditOnInstance` 都不在这条链路上。

### 何时必须勾选

- 蓝图 Actor / 组件会摆进关卡，且需要**逐个实例调参**（灯色、门速、刷怪点 ID）。
- 需要在 SpawnActor 节点上暴露输入引脚（还需再加 `CPF_ExposeOnSpawn`）。
- 需要策划/关卡设计师不改蓝图资产就改实例值，并让实例值**覆写**父 CDO。

### 何时建议不勾选

- PlayerController / GameState / GameMode / PlayerState 等运行时生成类。
- 值由 Lua 或服务端权威写入，编辑器侧只需留默认值的镜像字段。
- 想防止「关卡实例上手改的值悄悄覆盖 CDO，导致改蓝图不生效」。

### 读写与验证

```python
# 读（NewVariables 层）
for v in bp.NewVariables:
    print(str(v.get_field("VarName")), int(v.get_field("PropertyFlags")))

# 读（编译后 UProperty 真值）
gc = bp.GeneratedClass
print(int(gc.get_property_flags("AuctionGroupPropUsage")))

# 写：清掉 0x10000 即勾选 Instance Editable

ue.compile_blueprint(bp); bp.save_package()
```

MCP 另提供 `obj.add_property_flags(...)` / `obj.set_property_flags(...)` / `obj.get_property_flags(propName)`（`py:guide property`，property 类别）。

**文档冲突**：`py:blueprint_add_member_variable` 官方签名文档把 `type_str` 示例写成 `'bool','int','float','str'`，但项目实测传 `"str"` 会生成 **int32**，正确值是 `"string"`。以实测为准。

## MCP 建变量的类型串坑（2026-09-16 实测）

`ue.blueprint_add_member_variable(bp, name, type_str)` 的 `type_str` **不是** UE 的 PinCategory 简写：

| 传参 | 实际生成 | 结论 |
| --- | --- | --- |
| `"str"` | **int32** | ❌ 错误，且 `schema:` 查询会显示成 int32 |
| `"string"` | StrProperty | ✅ 正确 |
| `"int"` / `"float"` / `"bool"` | 对应类型 | ✅ 正确 |

已建错类型时**无法**用 Python 直接改 `VarType`（`v.VarType.PinCategory = "string"` 与 `v.VarType = goodVarType` 都会把类型写空，回读 `PinCategory=''`）。正解是整体替换 VarType 再编译保存：

```python
bp = ue.load_object(Blueprint, "/<Project>/Asset/Blueprint/UGCPlayerController")
target = [v for v in bp.NewVariables if str(v.get_field("VarName")) == "MyVar"][0]
good   = [v for v in bp.NewVariables if str(v.get_field("VarName")) == "AuctionOwnedPropGroups"][0]
target.set_field("VarType", good.get_field("VarType"))   # 复制同类型变量的 VarType
ue.compile_blueprint(bp)
bp.save_package()
```

验证用 `bp.GeneratedClass.get_uproperty(name)` 看 UClass 名（`StrProperty`/`IntProperty`/`FloatProperty`/`BoolProperty`）。**`schema:` 查询有缓存，reload 后仍可能显示旧类型**，不能当最终依据。
