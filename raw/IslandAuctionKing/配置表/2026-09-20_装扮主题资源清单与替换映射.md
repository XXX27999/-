## 4. 一致性核对

### 4.1 缺失

- `HouseArt_IslandContainer` / `HouseArt_MountainArmory` / `HouseArt_AirdropSecret`：
  `UIConfigTable` 有行（`UI.HouseSelect.Texture.*`），磁盘无文件 → 房产选择界面取不到图（**既有缺陷，与主题无关**）。
- `AuctionUI_BidKeypad`：`UIConfigTable` + `DressMaterialTable` 槽位 `BidBoard` 都引用它，
  但磁盘只有 `AuctionUI/Price/PriceInput`。建议把配置改指 `PriceInput`，而非补一张同名图。

### 4.2 冗余（磁盘有、控件树与配置都不引用）

`Settlement` 5 个（SettlementGrid / LeftBigCard / LeftCard / LeftFooter / LeftTopBar）、
`AuctionSkill` 5 个（SkillOption / SkillReference / SkillSelected / SkillSlider / SkillTransparentBar）、
`Codex` 3 个（Codex_Reference / ScrollThumb / ScrollTrack）、`Hub` 2 个（ZJM2 / ZJM4）、
`Auction` 1 个、`AuctionInfo` 1 个。
其中 `*Reference` 是设计稿留档（字节与正图接近），建议统一加 `_Reference` 后缀从主题清单中排除。

另有第三类「配置引用·未绑控件」（如 `AuctionUI_FooterBid`、`AuctionUI_NameLabelFrame`），
判据 = 磁盘数 − 使用中 − 未引用。主题目录**不必**为它们准备变体。

### 4.3 命名与层级不统一

| 问题 | 现状 | 建议 |
|---|---|---|
| 主界面用无语义编号 | `ZJM1`~`ZJM12`，其余模块全用语义名 | 主题目录保持同名即可，不改名；语义靠 `Dress.SameName.TextureNames` 登记 |
| 竞拍素材已迁移、配置未跟 | 文件在 `Auctioninterface/`，9 条配置仍写 `AuctionUI/` | 补一层目录 |
| 路径前缀写法不一 | 15 条绝对路径 vs 31 条相对路径 `Asset/TuPian/...` | 统一 `/IslandAuctionKing/` 开头 |
| 房产立绘前缀混用 | `HouseSelect*` 与 `HouseArt_*` | 统一 `HouseSelect` 前缀并补 3 张图 |
| 层级深度 | 主界面/图鉴/结算单层；竞拍两层 | 主题目录严格镜像基目录层级，**不改层** |

## 5. 默认 → 主题替换映射

沿用已验证通过的**同名画刷机制**：

```
默认主题（DefaultGray）：Asset/TuPian/<BaseFolder>/<素材名>.uasset           ← 不加后缀
其他主题（TestTopic）  ：Asset/TuPian/<BaseFolder>_TestTopic/<素材名>.uasset ← 基目录 + '_' + ThemeId
```

- 缺素材回退基目录，不会白图；主题目录不必与基目录文件数相等（少文件 = 部分回退）。
- 需写 `DressConfigTable` 13 行 `Dress.SameName.BaseFolder.<UiKey>`（见 MD §4.2）。
- 需写 `DressControlTable` 66 行 `Dress.SameName.Texture.<UiKey>.<素材名>` = 绑定控件名（见 MD §4.3）。
- 同一界面用到多个素材目录（竞拍用到 5 个）→ 按目录拆成多个 UiKey，各自调用一次。
