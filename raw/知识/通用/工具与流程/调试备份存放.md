## 核心结论

调试产生的写前备份、临时脚本和非法文件名隔离文件，统一放到知识库备份根目录，按项目分放：

D:\知识库\和平精英绿洲起源\备份\<项目名>\<YYYYMMDD>_<主题>\

禁止再写入 UGC 工程。项目实测：工程内 Backup 也会被 PIE CheckName 递归扫描，下划线或连字符开头的文件名会中断调试。

备份目录不是知识正文，不进 wiki/000_索引.md，也不写入 raw/docs/。

## 可执行步骤

1. 确定项目名，必须与编辑器工程目录一致，且匹配 ^[A-Za-z][A-Za-z0-9_]*$。
2. 在 D:\知识库\和平精英绿洲起源\备份\<项目名>\ 下创建 <YYYYMMDD>_<主题> 子目录。主题只用英文、数字和下划线。
3. 复制目标 .uasset、.lua、临时脚本或隔离文件到该子目录，保留原文件名若合法；非法文件名改为英文字母开头后再存放。
4. 通知用户备份绝对路径，然后才走 UGCAskQ MCP 的 Resolve -> Plan -> Execute。
5. 在来源记录或项目日志中登记本次备份绝对路径，不要把二进制备份写进 Wiki 正文。

## 禁止位置

- UGC 工程根目录
- 工程 Backup/、_Backup/、Saved/Backup/
- 工程 _JsonOutput/Backup、_JsonOutput/_Backup
- 工程内任何名为 `$null` 的文件（含工程根、Asset、Saved、`_JsonOutput`、`Saved/UGCLinuxDebug/<项目名>/`）
- Asset 目录
- D:\UGCBackup、D:\IslandAuctionKing_Backups、D:\OasisBackups（已废弃，历史内容已迁入知识库备份目录）

## `$null` 强制规避（2026-09-24 项目实测）

PowerShell 中 `>$null` / `2>$null` 在未被正确解析时会被当成真实重定向路径，在工程目录生成 0 字节文件 `$null`。该文件进入 PIE 上传副本后会触发：

```
LogUGCKeyLog: Content=$null may contain the following characters: $ , please rename the file or path
LogUGCUpload: CheckName, Operation: CheckUploadFileNameFailed, Result: 10001
LogUGCPIEFlowLog: Error: PIE 调试失败：上传文件名验证失败
LogUGCUpload: CheckLua, Operation: CheckUploadLuaFileValidationFailed, Result: 10001, Parent: CancelDebug
```

其中 `CheckLua ... Parent: CancelDebug` 是文件名校验失败后的连锁取消，不代表 Lua 语法错误。处理顺序固定为：

1. 先删除工程内 `$null`，再删除上传副本 `Saved\UGCLinuxDebug\<项目名>\$null`。
2. 递归复扫工程，确认 `$null` 命中为 0，再重新 PIE。
3. 若 `luacheck ReturnCode: 0` 而仍报 `lua file validation failed`，按文件名链路排查，不要先改 Lua。

禁止在会落到 UGC 工程目录的命令里写 `>$null` / `2>$null`；丢弃输出统一用 `2>&1 | Out-Null`、`| Select-Object -Last N` 或 `-ErrorAction SilentlyContinue`。任务收尾必须执行：

```powershell
Get-ChildItem -Recurse -Force -File | Where-Object { $_.Name -eq '$null' }
```

命中即删除并复扫为 0。

## 常见错误

- 把备份放进工程 Backup，以为非 Asset 目录不会被 PIE 扫描。
- 用 _tmp_*.py 这种下划线开头的临时脚本留在工程根目录。
- 在工程目录内用 `2>$null` 丢输出，生成 0 字节 `$null` 文件，导致 PIE 上传校验中断。
- 把二进制备份当项目证据写进 raw/<项目名>/ 正文，或登记进 wiki/000_索引.md。
- 修改蓝图或配置表却不备份，或备份后不告知绝对路径。
