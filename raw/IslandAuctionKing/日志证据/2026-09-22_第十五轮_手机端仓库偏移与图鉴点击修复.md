# 第十五轮：手机端仓库偏移与图鉴点击修复

## 本轮纠正

前一轮只启动了一个客户端，不能作为竞拍验证依据。按项目人数要求停止旧会话，并使用：

```text
action=start
submode_id=0
team_count=2
players_per_team=1
spectators_per_team=0
simulation_platform=mobile
```

启动前核对 `Script/Function/AuctionConfig.lua` 的 `AuctionConfig.RequiredPlayers = 2`，并核对 `AuctionGameService.lua` 的 `ParticipantKeys` 人数门禁。窗口实测同时存在 `PIEPlayer_T1_10001` 与 `PIEPlayer_T2_20001`。

## 代码修改

1. `Script/Function/AuctionTestUIService.lua`：藏品点击覆盖层的背景色继续保持全透明，但可见性由 `HitTestInvisible` 改为 `Visible`。此前按钮不可命中，`OnCollectibleClicked` 无法执行，手机端点击不能切换藏品图鉴。
2. `Script/Function/AuctionTestUIService.lua`：每次藏品图片布局前将 `CollectibleImage` 的渲染位移归零、渲染缩放归一，再写入动态格的真实 `Slot` 位置和尺寸，避免移动端残留动效变换导致藏品图相对格子轻微向左偏移。
3. `Script/Function/AuctionWarehouseCellService.lua`：仓库覆盖层使用动态格 `Slot` 矩形作为布局几何；手机端日志中 `geometrySource=CellSlot`，例如单格坐标与尺寸为 `X=95.4/190.8/286.2...`、`Y=187.0/280.5...`、`85.2x85.2`，多格藏品按包围盒复用真实格边界。

## 手机端验证

- `CollectibleButton01` 回读 `visibility=0`，对应本项目运行时 `Visible`。
- 直接调用 `AuctionTestUIService.OnCollectibleClicked(widget, 1)`：`ok=true result=true`。
- `AuctionCollectibleCodexFilterService.OpenForWarehouseItem`：`success=true`，返回图鉴实例，筛选摘要为 `形状=2×3 · 占格=6`。
- 仓库刷新日志持续报告 `geometrySource=CellSlot`，未回退到配置步长几何。
- `luaparser` 通过 `AuctionTestUIService.lua`、`AuctionWarehouseCellService.lua`、`AuctionWarehouseFeedbackService.lua`、`AuctionWarehouseImageMaterialService.lua`；`git diff --check` 通过；工程临时文件扫描通过。

## 仍需确认

本轮日志证明运行时几何一致、点击和图鉴筛选链路已恢复；尚未通过用户手机端截图完成最终像素级目视确认。若画面仍偏移，应继续采集手机端截图和 `CollectibleImage` 画刷的实际绘制参数，不能再仅凭 Slot 坐标推断。
