## 二、已查证并转为结论的条目

### 1. 枚举整数值（12 个，官方 md 与编辑器反射一致）

`ESlateBrushDrawType` / `ESlateBrushTileType` / `ESlateBrushMirrorType` / `ESlateBrushImageType` / `ESlateColorStylingMode` / `EStretch` / `EStretchDirection` / `EWidgetClipping` / `ETextWrappingPolicy` / `TextureGroup` / `TextureCompressionSettings` / `TextureMipGenSettings`。

全量表已落到独立页 [绿洲 UI 枚举与结构体速查](../UI与交互/绿洲UI枚举与结构体速查.md)。

其中官方 ToolTip 给出的三条可执行结论：

- `DrawAs=Image(3)` 官方原文 **`Draw an image; margin is ignored`** —— 九宫格底图必须用 `Box(1)`。
- `EWidgetClipping` 类 ToolTip 明确 **Slate 无法跨裁剪区合批**，且 `OnDemand(4)` 是「主要为文本添加」的模式，可避免给每层容器强开裁剪。
- `Tiling` / `Mirroring` 官方注明只在 **Image 模式**生效，且 `Mirroring` 通常只用于摄像头等硬件动态画刷。

### 2. `MipGenSettings` 订正：13 而非 2

`raw/docs/ai/20260824_图鉴UI素材批量导入与视觉优化.md` 第 12 行记为 `MipGenSettings=2 (TMGS_NoMipmaps)`。查 `raw/docs/api/cppenum/T/TE/TextureMipGenSettings.md`：`TMGS_Sharpen0=2`，`TMGS_NoMipmaps=13`。编辑器 `enum:TextureMipGenSettings` 输出一致。

实测项目贴图（`ue_py` 只读）：

```
TEX Codex_CardFrame LODGroup=16 MipGen=13 Comp=0 SRGB=True
TEX Codex_Close     LODGroup=16 MipGen=13 Comp=0 SRGB=True
TEX ZJM4            LODGroup=0  MipGen=13 Comp=0 SRGB=True
```

→ 素材本身设置正确（13），只是原记录的数字标注写错。另外 `ZhuJieMian/ZJM4` 的 `LODGroup=0 (TEXTUREGROUP_World)`，未归入 UI 组，是项目内待修正项。`raw/` 只读，订正只写在 wiki。

### 3. 官方 UI 贴图设置有正式出处

`raw/docs/wiki/新手入门/资源管理与编辑/资源编辑/300_贴图与材质编辑.md` 第 2 节「UI贴图设置」原文：

```
Compression Settings：默认使用TCQ_Default
Compression Quality：TCQ_Highest
Mip Gen Settings:TMGS_NoMipmaps
Texture Group:TEXTUREGROUP_UI
```

映射到属性：`CompressionSettings=0 (TC_Default)`、`CompressionQuality=5 (TCQ_Highest)`、`MipGenSettings=13`、`LODGroup=16`。原文「Compression Settings：TCQ_Default」的 `TCQ_` 前缀与枚举定义不符（`TCQ_` 属 `CompressionQuality`），已列入待查证。

同一文件末段「地表材质…修改方法是修改画刷贴图」指的是**地形笔刷**，与 `FSlateBrush` 无关，已在概念页加术语区分说明。

### 4. `FSlateBrush` 14 字段与 `FButtonStyle` 官方 ToolTip

关键三条：

- `Disabled` 官方原文 **by default this is set to an invalid resource, when that is the case default disabled drawing is used** —— 证明「只设 Normal 会视觉突变」的根因是回落到引擎默认禁用绘制。
- `NormalPadding` / `PressedPadding` 官方定位是抵消按钮背景图边框、并让内容跟随边框图位移，**不应该靠移动子控件坐标模拟按下下沉**。
- `bHasUObject_DEPRECATED` / `Tint_DEPRECATED` 已废弃；实例 `fields()` 里的 `bHasUObject` 就是废弃字段，不要写。

### 5. `FSlateFontInfo.Size` 的官方中文警告

官方 ToolTip 原文含中文：「手机端无法渲染过大的字体图集，且出于内存考虑也不宜将字体设置过大。若有大字体需求，请用小字体+调整Scale的方案。See MAXFONTSIZE」。另注明磅→Slate 单位换算在 **96 dpi** 下完成，Photoshop 出稿要从 72 dpi 改 96 dpi。

这是本轮唯一能作为**官方硬结论**引用的字体规范。

### 6. `UICommonFunctionLibrary` 的真实身份

它不是 C++ 类，而是蓝图函数库 `BlueprintGeneratedClass /Game/UMG/UI_BP/Common/UICommonFunctionLibrary.UICommonFunctionLibrary_C`，因此 `raw/docs/api` 无类文档、`ue.find_class` 查不到。定位与签名提取（实测）：

```python
cls = None
for c in ue.all_classes():
    if c.get_name() == 'UICommonFunctionLibrary_C':
        cls = c
        break
cls.functions()
# -> ['ExecuteUbergraph', 'FormatSecondsToString', 'FormatSecondsToString2', 'FormatSecondsToString3',
#     'GetLocalizeText', 'GetUIRectOffset_WithSetting', 'SetAdaptation', 'SetAdaptation_Lobby',
#     'SetAdaptation_Lobby_IPX', 'SetAdaptation_ScreenHole', 'SetAndroidPhoneAdaptation',
#     'SetSquareFixedScslr', 'SetTabStyle', 'SetUnAdaptation']

base = '/Game/UMG/UI_BP/Common/UICommonFunctionLibrary.UICommonFunctionLibrary_C'
f = ue.find_object(base + ':SetAdaptation')
[p for p in f.properties() if not p.startswith(('CallFunc_', 'K2Node_', 'Temp_'))]
# -> ['Widget', '__WorldContext']
```

实测签名（9 个适配相关函数）：

```
SetAdaptation(Widget, __WorldContext)
SetUnAdaptation(Widget, __WorldContext)
SetAdaptation_ScreenHole(widget, __WorldContext)
SetAdaptation_Lobby(Widget, __WorldContext)
SetAdaptation_Lobby_IPX(Widget, __WorldContext)
SetAndroidPhoneAdaptation(Panel, __WorldContext)
GetUIRectOffset_WithSetting(__WorldContext, RealOffset)
SetSquareFixedScslr(Widget, __WorldContext)
SetTabStyle(isCheck, Text, icon, onColor, offColor, __WorldContext)
```

只有 `SetAdaptation` 有官方 Wiki 示例（`357_异形屏适配.md`），其余 8 个**只确认签名、用途属推断**，仍在待查证。

坑点：`properties()` 返回**字符串列表**，对元素调 `get_name()` 会报 `'str' object has no attribute 'get_name'`。

### 7. EditCondition 门控链（编辑器反射确认）

| 被门控字段 | 门控 | DisplayName |
| --- | --- | --- |
| `UTextBlock.MutiEllipsisLine` | `MutiEllipsisText` | — |
| `UButton.bUseCustomSettings` | `IsImgAlphaBtn` | 是否采用用户自定义设置 |
| `UButton.CustomHitAreaTexture` | `bUseCustomSettings` | 自定义点击区域透明贴图 |
| `UButton.CustomHitAreaAlpha` | `bUseCustomSettings` | 自定义点击区域透明度阙值 |

`IsImgAlphaBtn` DisplayName 为「是否异形按钮」，构成三层链式门控。`CanvasPanelSlot.bAntiAdaptation` DisplayName 为「贴边反适配」（Category `Layout|Canvas Slot`）。

### 8. `UImage.Brush` vs `BrushImage` 的官方判据

`schema:UImage?level=full&filter=Brush,BrushImage` 输出：`Brush` 是 `FSlateBrush`，官方 ToolTip **`Image to draw`**，`Edit + BPVisible`；`BrushImage` 是 `UObject*`，**仅 `Edit`、无 ToolTip、非 BPVisible**。这从反射层面证实了用户轮次 3 的纠正——改样式要改 `Brush`，不是「画刷 图像」。

同 Category 还有 `BrushMaterialParamNames`（DisplayName `Material Paramters`），官方 ToolTip 注明皮肤覆盖材质参数「暂时只支持 PC 上的 Float 参数修改」。

### 9. `UScaleBox` 有两套并行缩放字段

`Stretch/StretchDirection/UserSpecifiedScale/UserSpecifiedScaleBias/IgnoreInheritedScale`（Category `Stretching`）与后缀 `Pc` 的同名字段（Category `StretchingPC`）。只改一套会导致 PC 与移动端表现不一致。`UserSpecifiedScale` 官方注明仅在 `Stretch=UserSpecified(7)` 下生效。

## 三、未能查证的条目

### 字体规范页是纯图片，无机器可读文本

`raw/docs/wiki/开发者须知/271_字体规范.md` 正文只有一行图片引用，指向 `raw/docs/wiki/_assets/images/285b0fde_LDD02.864755c6[1].png`（1731×3712 px，约 1.19 MB）。

本轮处理过程：`await import("sharp")` 在 node_repl 中失败（`Unsupported import specifier "../package.json"`），改用 PowerShell + `System.Drawing` 切成 6 段并缩放，`view_image` 读取前两段——内容为大幅纯色/渐变设计稿，字号/字重/行高等数值**不可辨**。

→ 结论：绿洲官方字体规范的具体数值需人工打开原图确认，已列入两个概念页的「待查证」。

其余未查证项（`bUseImageSizeAsTextureSize` 无描述、`UVRegion` 未 PIE 验证、`UserSpecifiedScaleBias` ToolTip 为宏残留、`ScaleBySafeZone` 与异形屏方案关系、`AutoEllipsisText`/`MutiEllipsis*` 语义、材质作 `ResourceObject` 的运行时表现等）见两个概念页的「待查证」小节。
