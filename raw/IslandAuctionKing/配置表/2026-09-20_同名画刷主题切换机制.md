## 1. 需求与机制定位

用户原话要点：

> 主界面当前使用的图片素材来源于主题文件夹 `Asset/TuPian/ZhuJieMian`。当切换到 `TestTopic` 主题时，需将主界面 UI 的**边界画刷与图片画刷全部替换**为主题文件夹 `Asset/TuPian/ZhuJieMian_TestTopic` 下的**同名图片素材**，并按照当前主题对应的文件夹进行素材区分与切换。

**两套机制并行的判据**：既有的 SlotKey 槽位机制（见 2026-09-18 页）素材文件名是**自定义槽位词**（`HubBackground`），与控件上原本贴的素材无关；本机制素材文件名就是**控件现用素材的原名**（`ZJMBackground`、`ZJM5`）。

| 维度 | SlotKey 槽位机制 | 同名画刷机制（本页） |
|---|---|---|
| 素材文件名 | 自定义槽位词 `HubBackground` | 控件现用素材原名 `ZJMBackground`、`ZJM5` |
| 目录 | `Asset/TuPian/Dress/<StyleTheme>/` | `Asset/TuPian/<BaseFolder><Suffix>/` |
| 控件指定方式 | `DressControlTable` 的 `Dress.Control.<UiKey>.<SlotKey>` | `DressControlTable` 的 `Dress.SameName.Texture.<UiKey>.<素材名>` |
| 目录规则来源 | `Dress.Theme.PathTemplate` | `Dress.SameName.PathTemplate` + `FolderTemplate` + `FolderSuffixTemplate` |
| 缺素材回退 | 回退 `Dress.Theme.DefaultStyle` 主题目录 | 回退**基目录**（`Dress.SameName.FallbackToBase`） |
| 当前覆盖范围 | Hub 仅「参考图」1 个控件 | Hub 全部 **14 个 Image 控件** |

两套机制**互不影响、可各自单独开关**；同名替换**排在 SlotKey 应用之后**（两套都会写「参考图」控件，同名机制代表主界面最终外观）。

## 2. 文件夹命名规则

```
<Dress.SameName.ThemeRoot>/<BaseFolder><Suffix>
```

| 组成部分 | 取值来源 | 当前值 |
|---|---|---|
| `ThemeRoot` | `Dress.SameName.ThemeRoot` | `Asset/TuPian` |
| `BaseFolder` | `Dress.SameName.BaseFolder.<UiKey>` | `Hub` → `ZhuJieMian`（= 主界面现用素材所在文件夹原名） |
| `Suffix` | 默认主题取**空串**；其余主题取 `Dress.SameName.FolderSuffixTemplate`（`_<ThemeId>`） | `DefaultGray` → 空；`TestTopic` → `_TestTopic` |

完整素材路径（`Dress.SameName.PathTemplate` = `<Folder>/<Texture>`）：

```
Asset/TuPian/<Folder>/<Texture>
```

| 主题 ID | 计算出的目录 | 说明 |
|---|---|---|
| `DefaultGray`（默认主题） | `Asset/TuPian/ZhuJieMian` | **不加后缀**，直接用基目录 = 主界面原始素材，切换后画面与现状一致 |
| `TestTopic` | `Asset/TuPian/ZhuJieMian_TestTopic` | 基目录 + `_` + 主题 ID |

**为什么默认主题不加后缀**：主界面原始素材就在 `ZhuJieMian`，「默认主题 = 什么都不换」必须成立，否则默认态会丢图。若将来要按主题切 `ZhuJieMian` 里的图，做法是新建 `ZhuJieMian_DefaultGray` 并把 `Dress.Theme.DefaultStyle` 改成别的主题 ID，**不要**改基目录名。

**新增主题的条件**：① 建目录 `Asset/TuPian/ZhuJieMian_<ThemeId>`；② 按第 3 节对应表把同名文件放齐；③ 在 `Dress.Theme.StyleIds` 追加 `<ThemeId>`；④ 加一行 `Dress.Theme.Style.<ThemeId>.Name`。**脚本零改动**。

## 4. 生效范围与执行者

- **执行者**：`Script/Function/AuctionDressThemeService.lua` 的 `SameName*` / `ApplySameName*` 函数族（与既有 `BuildSlotPath` 等 SlotKey 函数并存，**未改动既有函数**）。
- **替换范围**：仅 `UImage.Brush` 与 `UBorder.Background` 的**贴图资源**。不改控件布局与锚点、不改 `TintColor` / `ColorAndOpacity`、不改 `Button` 四态样式、不改 `TextBlock` 文案。
  - UImage 走**两参** `SetBrushFromTexture(texture, false)`；UBorder 走**单参** `SetBrushFromTexture(texture)`；读取当前贴图用 `Brush.ResourceObject`。
- **端侧范围**：仅客户端展示层，不涉及服务端数据与存档；服务端 `Initialize` 直接跳过。
- **接入点**：`AuctionHubUIService.Initialize` 末尾（首帧尝试）+ `Tick` 每帧（`AuctionHubInitialized == true` 守卫下 `pcall` 调用），调
  `AuctionDressThemeService.ApplySameNameThemeToHostUIWhenReady(widget, "Hub", nil)`；
  配置表就绪前空转等待（`DressControlLoaded`），就绪后只应用一次，主题 ID 变化时自动重应用。
- **与 SlotKey 机制的次序**：同名替换排在 SlotKey 应用之后。
- **主题切换触发**：`AuctionDressThemeService.SetCurrentStyleId(themeId)` 之后，主界面 `Tick` 检测到 `SameNameThemeApplied_HubStyleId` 与当前主题不一致即自动重应用，**无需重开界面**。
- **调试开关**：当前工程尚无主题切换 UI，故加 `Dress.SameName.DebugThemeId`——非空时同名机制强制读该主题目录，用于单独验证素材目录是否接通；**验证完必须置回空串**。

## 6. PIE 运行验证

### 6.1 第一轮：两个真缺陷（DebugID `_dkck7pp6wwstp8`）

**缺陷 A — 子路径重复**：同名素材路径拼成 `Asset/TuPian/Asset/TuPian/ZhuJieMian/ZJM1`。
后果：11 个素材全部 `LoadSameNameTexture 出口 success=false` → `ApplySlotSameName 分支 同名素材缺失，保留原画刷` → `appliedCount=0`。
根因：`Dress.SameName.PathTemplate` 初值 `Asset/TuPian/<Folder>/<Texture>` 与 `ThemeRoot=Asset/TuPian` 重复。
修复：MCP 改 `PathTemplate` 为 `<Folder>/<Texture>`；`BuildSameNamePath` 用 `folder`（已含 `ThemeRoot`）+ `textureName` 拼接即得正确路径。

**缺陷 B — 装载时序**：`【AuctionConfig+Get】错误 中间节点不是table path=Dress.SameName.Enabled`。
后果：惰性入口在表装载前就读 `Dress.SameName.*`，报错并把 `ResolvedDebugTheme` 缓存为空串，导致机制静默不生效。
根因：惰性入口原判定次序为「先判 `IsSameNameEnabled` → 再判 `IsDressControlLoaded`」。
修复：次序改为「**界面非空 → 表已装载 → 机制已启用 → 快速路径 → 应用**」；且 `GetCurrentStyleSilentlyForSameName` 内「仅当 `IsDressControlLoaded()` 为真才读调试主题」。

### 6.2 第二轮：全绿证据（DebugID `_dkck7pp6wwsxum`）

### 6.3 方法论：客户端日志 0 字节的三种成因

PIE **运行期间** LuaLog / TagLog / FullLog 可保持 0 字节，**进程退出（stop）才落盘**。判据顺序：

1. 运行中 → 0 B 属正常，别当故障；
2. 崩溃 → 0 B **且**存在 `Saved\Crashes\UE4CC-Windows-<ID>_0000\`（原路径被截为 0 B，日志被搬进崩溃目录）；
3. 未启动 → 0 B 且无进程。

本轮第一轮 PIE 曾误判「客户端起不来」，实测客户端进程 `Responding=True`、窗口标题 `…PIEPlayer_T1_10001`，stop 后日志正常落盘（704992 B TagLog / 1859936 B LuaLog）。
