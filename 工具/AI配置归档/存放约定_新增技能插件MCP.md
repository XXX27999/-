# 存放约定：新增技能 / 插件 / MCP

> 类型：知识库工程规范 / 治理约定
> 主题：绿洲起源 AI 工具链资产（技能包、插件、MCP 配置）的存放、登记与调用契约
> 适用范围：本机所有 AI 客户端；新建或引入技能、插件、MCP 时强制适用
> 证据状态：用户明确要求（2026-09-16）/ 仓库工程约定
> 来源：2026-09-16 会话。用户明确「后续创建的新技能，插件，MCP 都存放于知识库」
> 更新时间：2026-09-24
> 关联主题：AI 配置归档、非运行辅助文件索引与调用规范、知识库准确性与关联性读取写回
> 排除范围：UGC 工程运行文件；市场内置插件正文；`raw/docs/` 官方原始资料
> 官方依据：官方未覆盖；本条为仓库工程约定

## 一、核心结论

**先归档，后部署。** 新建或引入的技能 / 插件 / MCP 配置，第一份权威副本必须落在知识库归档目录，客户端目录只作为运行副本。

- 归档根：`D:\知识库\和平精英绿洲起源\工具\AI配置归档\`
- 技能：`…\skills\<来源层>\<技能名>\`（技能名须匹配 `^[a-z0-9][a-z0-9_-]*$`，保留 `SKILL.md` 原名）
- 插件：清单写入 `…\plugins\<客户端>\`；插件正文如可本地固化则放 `…\plugins\<客户端>\packages\<插件名>\`
- MCP：配置快照写入 `…\mcp\<客户端>\`；服务端脚本（若有）放 `…\mcp\<客户端>\servers\<服务名>\`

## 二、为什么不能只留在客户端目录

| 风险 | 后果 | 归档如何消除 |
| --- | --- | --- |
| 客户端目录可被自动更新覆盖 | 自研技能被市场同名版本替换 | 归档保留原始字节 + SHA256 |
| 私钥式配置随客户端重装丢失 | UGCAskQ 等自建 MCP 需重新摸索端口与参数 | MCP 配置快照可原样还原 |
| 多客户端各存一份且互相漂移 | 同一技能在不同端行为不一致 | 归档记录分层来源与字节差异 |
| 客户端目录不适合做检索源 | 相关问题查不到技能能力 | 归档在知识库内可被 L0→L3 检索命中 |

## 三、目录分配规则

| 资产类型 | 归档位置 | 客户端运行位置（部署目标） |
| --- | --- | --- |
| WorkBuddy 用户级技能 | `skills\workbuddy\<技能名>\` | `C:\Users\Administrator\.workbuddy\skills\<技能名>\` |
| Codex 侧技能 | `skills\codex\<技能名>\` | `C:\Users\Administrator\.codex\skills\<技能名>\` |
| cc-switch 共享技能 | `skills\shared_cc-switch\<技能名>\` | `C:\Users\Administrator\.cc-switch\skills\<技能名>\` |
| 绿洲仓库自带技能 | `skills\repo_oasis-skill-plus\<技能名>\` | `D:\oasis-skill-plus\skills\<技能名>\` |
| WorkBuddy MCP | `mcp\workbuddy\` | `…\.workbuddy\mcp.json`、`…\.workbuddy\connectors\` |
| Codex MCP | `mcp\codex\` | `…\.codex\config.toml` 的 `[mcp_servers.*]` |
| 插件清单 | `plugins\<客户端>\` | `…\.workbuddy\plugins\installed_plugins.json` |
| 全局提示词 | `全局提示词\` | `…\.workbuddy\rules\`、`…\.codex\AGENTS.md` |

## 四、登记契约（缺一不可）

新增任何资产后，必须在 `…\归档记录\<YYYYMMDD>_<主题>.md` 追加一条登记项，字段固定：

```markdown
### AICFG-YYYYMMDD-NNN <资产名>

- 资产类型：技能 / 插件 / MCP / 全局提示词
- 归档绝对路径：`D:\知识库\和平精英绿洲起源\工具\AI配置归档\...`
- 来源绝对路径：`C:\Users\Administrator\...`（原生创建时为「本会话新建」）
- 部署目标绝对路径：`C:\Users\Administrator\...`
- 关联实体：完整 API / 函数名 / MCP 服务名 / 端口 / 技能名 / 触发词
- 用途：一句话说明解决什么问题
- 调用入口：可复制执行的加载或安装命令
- 输入 / 输出：参数、产物路径、返回码
- 依赖：Python/Node 版本、库、前置服务、其他技能或 MCP
- 版本：技能 `metadata.version` 或插件 `version`；无版本则填 `未标注`
- 证据状态：官方确认 / 项目实测 / 经验归纳 / 推断 / 待查证
- 生命周期：可复用 / 临时；清理条件：<条件>
- 更新时间：YYYY-MM-DD
```

同时更新 `…\000_归档索引.md` 第四节（技能矩阵）或第五节（MCP 与插件）对应表格行。

## 五、新增流程

1. **建前查重**：先按技能名、MCP 服务名、端口、触发词在 `000_归档索引.md` 与 `归档记录\` 中检索，避免同能力重复入档。
2. **写入归档**：把技能包 / 配置快照写入第三节规定的归档位置。
3. **登记**：按第四节模板写登记项，并更新总索引表格行。
4. **算校验**：为新增文件补算 SHA256，追加到 `归档记录\校验清单_SHA256.txt`（保持 `SHA256  相对路径  字节数` 三列格式）。
5. **部署**：再复制到客户端运行位置；若需重启客户端才生效，在登记项「调用入口」中写明。
6. **回写知识库**：若该资产带来新的通用结论，另在 `raw\知识\通用\工具与流程\` 或对应领域建正文并在 `wiki\` 建短索引。

## 六、命名与清理硬约束

1. 归档内文件名以英文字母或中文开头，**禁止**以 `.`、`_`、`-`、`$` 开头（`000_`、`_oasis-sync_` 等已存在的说明/清单文件除外，属知识库既有约定）。
2. 归档内**禁止**残留 `__pycache__`、`*.pyc`、`_tmp_*`、`_mcp_tmp`、`$null`。
3. 一次性脚本用完即删；需要保留时只留在 `备份\<项目名>\<YYYYMMDD>_<主题>\`，不入归档。
4. 归档内文件统一 UTF-8 无 BOM（二进制资产除外）。
5. 归档目录**不得**出现 UGC 工程路径下的 `.uasset`、Lua 或导入资产本体。

## 七、校验清单

- [ ] 归档绝对路径存在，文件字节数与登记项一致
- [ ] SHA256 已写入 `归档记录\校验清单_SHA256.txt`
- [ ] 登记项「关联实体」至少含一个完整技能名 / MCP 服务名 / 端口 / 触发词
- [ ] 「部署目标绝对路径」与「归档绝对路径」均已写明，且部署命令可复制执行
- [ ] `000_归档索引.md` 对应表格行已更新
- [ ] 无 `__pycache__` / `*.pyc` / 临时文件残留
- [ ] 未把客户端缓存目录（`plugins\cache`、`*.db`）纳入归档
