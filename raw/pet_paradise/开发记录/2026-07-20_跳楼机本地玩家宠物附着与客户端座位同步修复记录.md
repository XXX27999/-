# 2026-07-20 跳楼机本地玩家与宠物附着、客户端座位同步修复记录

## 问题摘要

跳楼机 `CG014_Version_2050_Transport01_Blueprint.lua` 的服务端能够成功执行 `K2_AttachToActor`，并且通过 `GetAttachParentActor()` 回读确认玩家 Pawn 的父级就是跳楼机。但是本地客户端画面中的自主玩家仍可能不跟随跳楼机运动；宠物也存在同类问题。

同时，骑乘代码使用 `SetIgnoreLookInput(true)` 会锁定视角。官方文档说明该接口是计数栈：多次加锁需要等量解锁。因此简单调用一次 `SetIgnoreLookInput(false)` 不能保证清理旧的视角锁定。

## 已观察到的日志证据

以下结论来自 2026-07-20 的 PIE 日志，不是推测：

```text
【CG014_跳楼机+_IsPawnAttachedToTower】分支: 玩家真实附着父级为当前跳楼机
【CF_FWDRPC+ClientAttachDropTowerPawn】分支: 客户端真实附着父级验证成功 AttachParent=CG014... seatIndex=3
【CF_FWDRPC+ClientAttachDropTowerPawn】=== [客户端附着玩家到跳楼机]完毕：成功 ===
```

因此不能再用“`GetAttachParentActor()` 返回跳楼机”作为客户端视觉跟随正常的唯一判据。

宠物的旧日志只有服务端附着成功记录：

```text
【CG014_跳楼机+_AttachPawn】分支: 宠物已KeepWorld附着到跳楼机
【CG014_跳楼机+SyncSeatLockedActors】数据: 宠物已由Attach跟随
```

这些日志不能证明客户端宠物已附着或正在跟随。

## 修复架构

采用项目既有的两层 RPC 分发模式，不在 `UGCPlayerController.lua` 新增业务 RPC：

```text
服务端跳楼机 _AttachPawn
    -> K2_AttachToActor (服务端权威状态)
    -> CallUnrealRPC(PC, PC, "FWDRPC_Call", "ClientAttachDropTowerPawn", ...)
    -> CallUnrealRPC(PC, PC, "FWDRPC_Call", "ClientAttachDropTowerPet", ...)

客户端 CF_FWDRPC
    -> 对本地 Pawn / PetActor 显式 K2_AttachToActor
    -> GetAttachParentActor 回读验证
    -> 在跳楼机 ReceiveTick 中按客户端塔身高度差同步座椅世界坐标

下车
    -> 服务端解除附着、恢复移动
    -> ClientDetachDropTowerPawn 同步解除本地 Pawn 和宠物附着、清理客户端同步缓存
```

## 实施要点

### 1. 玩家与宠物的服务端权威附着

1. 先解除旧父级。
2. 关闭碰撞。
3. 玩家/宠物分别设置正确的世界位置与世界旋转。
4. 冻结可用的 `CharacterMovement`：`SetMovementMode(0)`、`GravityScale = 0`、`bOrientRotationToMovement = false`。
5. 调用 `K2_AttachToActor(Tower, nil, 1, 1, 1, true)` 保持世界位姿。
6. 下车时恢复移动模式、重力、朝向和碰撞。

### 2. 客户端显式附着和回读

新增客户端函数放在 `Script/Blueprint/CF_FWDRPC.lua`：

- `ClientAttachDropTowerPawn`
- `ClientAttachDropTowerPet`
- `ClientDetachDropTowerPawn`

服务端在跳楼机脚本中只通过以下固定分发器调用：

```lua
UnrealNetwork.CallUnrealRPC(PC, PC, "FWDRPC_Call", "ClientAttachDropTowerPawn", ...)
UnrealNetwork.CallUnrealRPC(PC, PC, "FWDRPC_Call", "ClientAttachDropTowerPet", ...)
```

客户端完成附着后必须检查：

```lua
local attachParent = PawnOrPet:GetAttachParentActor()
local isAttachedToTower = attachParent == DropTowerActor
```

失败时必须输出父级、目标跳楼机和错误信息；不能仅根据座位缓存表判定成功。

### 3. 客户端逐帧座位同步兜底

对于本地玩家与宠物，客户端 `ReceiveTick` 根据本地跳楼机位置计算：

```lua
deltaZ = towerLocation.Z - seatBaseZ
seatWorldLocation = {
    X = seatBaseWorldLocation.X,
    Y = seatBaseWorldLocation.Y,
    Z = seatBaseWorldLocation.Z + deltaZ,
}
```

然后对客户端缓存的 Pawn 设置位置；对宠物设置位置和固定的座椅朝向。高频日志必须限次，避免输出淹没真实错误。

这个兜底仅针对本地客户端自主 Pawn/宠物视觉同步。它不替代服务端的权威附着，也不应在服务端每帧强制拉回玩家位置。

### 4. 视角与移动输入分离

骑乘只需要禁止移动输入，不能锁死视角：

```lua
PC:ResetIgnoreLookInput()
PC:SetIgnoreMoveInput(true)
```

下车或附着失败时恢复：

```lua
PC:ResetIgnoreLookInput()
PC:SetIgnoreMoveInput(false)
```

`ResetIgnoreLookInput()` 会清理历史锁定计数；适用于此前已经存在多次 `SetIgnoreLookInput(true)` 的项目状态。
