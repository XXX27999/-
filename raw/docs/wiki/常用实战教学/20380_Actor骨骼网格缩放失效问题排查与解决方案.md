# Actor 骨骼网格缩放失效问题排查与解决方案

> 本文档记录了 `pet_paradise` 项目中宠物升级时 `SetActorScale3D` 只改变了碰撞体但模型视觉上没有变大的问题排查与解决过程。核心原因是 **AvatarDisplayProxyComp 接管了角色可视化渲染**，导致直接操作骨骼网格组件无效。

## 涉及 API

| API | 生效范围 | 说明 |
|-----|---------|------|
| `SetActorScale3D({X,Y,Z})` | 服务端&客户端 | 设置 Actor 的根组件世界缩放，会影响碰撞体 |
| `SetWorldScale3D({X,Y,Z})` | 服务端&客户端 | 设置组件的世界缩放（不依赖父级） |
| `GetComponentsByClass(Class)` | 服务端&客户端 | 获取 Actor 上指定类的所有组件，返回数组（1-based，用 ipairs 遍历） |
| `UGCObjectUtility.FindClass("SkeletalMeshComponent")` | 服务端&客户端 | 通过类名字符串查找类对象 |
| `UGCAttributeSystem.AddGameAttributeChangedDelegate(Owner, AttrName, Callback)` | 服务端&客户端 | 注册属性变化回调，属性值变化时自动触发 |
| `UGCAttributeSystem.RemoveGameAttributeChangedDelegate(Owner, AttrName, Delegate)` | 服务端&客户端 | 移除属性变化回调（用于清理） |
| `UGCAttributeSystem.SetGameAttributeValue(Owner, AttrName, Value)` | **仅服务端** | 设置属性值，会自动同步到所有客户端 |
| `pcall(func)` | 服务端&客户端 | Lua 安全调用，捕获异常防止崩溃 |

> **注意**：`SetWorldScale3D` 和 `SetActorScale3D` 的区别：
> - `SetActorScale3D` 是 Actor 级别，修改**根组件**的缩放，所有**子组件**的 WorldScale = 父级 Scale × 子级 RelativeScale。当根组件缩放时，碰撞体（CapsuleComponent/HitBox）会跟随变化。
> - `SetWorldScale3D` 是组件级别，直接设置该组件的世界缩放。对于根组件的子组件，如果父级没有 `bAbsoluteScale=true`，子组件的缩放会被父级缩放叠加影响。

## 问题现象

宠物升级后执行了缩放代码，但从日志和视觉上观察到：

```
[日志输出 - 服务端代码执行成功]
[ExpLevelUp+Execute] Actor根组件已缩放至 3.0
[ExpLevelUp+Execute] 已缩放骨骼网格组件[1], 大小=3.0
[ExpLevelUp+Execute] 方案2共缩放 1 个SkeletalMeshComponent
```

- 碰撞体（胶囊体）变大 ✅ → 碰撞检测正确
- 模型（视觉网格）未变大 ❌ → 角色看起来还是原来的大小

## 根因分析

### 1. AvatarDisplayProxyComp 接管角色可视化渲染

通过检查蓝图的 JSON 文件发现，羊驼角色（AlpaceA）的组件结构中包含：

```
AvatarDisplayProxyComp : GenericCharacterAvatarDisplayProxyComponent
```

这是**角色显示代理组件**。它在运行时创建自己的显示网格体系，替代原生的 `CharacterMesh0`。也就是说：

- **碰撞/物理** ← CapsuleComponent（受`SetActorScale3D`控制 ✅）
- **可视化渲染** ← AvatarDisplayProxyComp 管理的一套独立网格（不继承根组件的缩放 ❌）

### 2. GetComponentByClass 找到的不是显示用的网格

```lua
-- 这段代码只找到了1个SkeletalMeshComponent，但它是被代理接管前的原始组件
local comp = pet:GetComponentByClass(MeshClass)
-- 调用SetWorldScale3D成功，但模型不变，因为AvatarDisplayProxyComp用自己的网格替代了它
```

代理组件（`AvatarDisplayProxyComp`）持有 `CachedMasterPoseComponent` 属性，这才是**实际参与渲染的骨骼网格**，需要直接操作它。

### 3. 服务端 vs 客户端

`SetActorScale3D` 和 `SetWorldScale3D` 在服务端执行后，对子组件的缩放不一定能正确同步到客户端的视觉表现。因此，最佳方案是**在客户端侧注册属性变化监听**，当属性值从服务端同步过来时，客户端自动执行缩放。

## 解决方案（双保险方案）

### 方案 A：服务端侧（ExpLevelUp.lua）

在升级逻辑中，执行三种缩放操作：

```lua
-- 1. 缩放根组件（控制碰撞体）
pet:SetActorScale3D({ X = newSize, Y = newSize, Z = newSize })

-- 2. 通过AvatarDisplayProxyComp的CachedMasterPoseComponent缩放显示网格
local proxyOk, proxyComp = pcall(function()
    return pet.AvatarDisplayProxyComp
end)
if proxyOk and proxyComp then
    local masterOk, masterComp = pcall(function()
        return proxyComp.CachedMasterPoseComponent
    end)
    if masterOk and masterComp then
        masterComp:SetWorldScale3D({ X = newSize, Y = newSize, Z = newSize })
        ugcprint("AvatarDisplayProxy的CachedMasterPoseComponent已缩放")
    end
end

-- 3. 遍历所有SkeletalMeshComponent兜底缩放
local classOk, MeshClass = pcall(function()
    return UGCObjectUtility.FindClass("SkeletalMeshComponent")
end)
if classOk and MeshClass then
    local listOk, compList = pcall(function()
        return pet:GetComponentsByClass(MeshClass)
    end)
    if listOk and compList then
        for i, comp in ipairs(compList) do
            if comp then
                comp:SetWorldScale3D({ X = newSize, Y = newSize, Z = newSize })
            end
        end
    end
end
```

### 方案 B：客户端侧（Pet.lua）- 推荐方案

使用属性系统自带的回调机制，当 `Size` 属性从服务端同步到客户端时自动执行缩放：

```lua
-- 在ReceiveBeginPlay中注册回调
function Pet:ReceiveBeginPlay()
    -- ... 其他初始化逻辑 ...

    -- 注册Size属性变化回调（服务端和客户端均会触发）
    self.SizeChangedDelegate = UGCAttributeSystem.AddGameAttributeChangedDelegate(
        self, "Size", 
        function(owner, attrName, curValue)
            -- 缩放Actor自身（碰撞体）
            self:SetActorScale3D({ X = curValue, Y = curValue, Z = curValue })

            -- 通过AvatarDisplayProxyComp缩放显示网格
            if self.AvatarDisplayProxyComp and self.AvatarDisplayProxyComp.CachedMasterPoseComponent then
                self.AvatarDisplayProxyComp.CachedMasterPoseComponent:SetWorldScale3D({
                    X = curValue, Y = curValue, Z = curValue
                })
            end

            -- 兜底：遍历所有骨骼网格组件
            local MeshClass = UGCObjectUtility.FindClass("SkeletalMeshComponent")
            if MeshClass then
                local compList = self:GetComponentsByClass(MeshClass)
                if compList then
                    for i, comp in ipairs(compList) do
                        if comp then
                            comp:SetWorldScale3D({ X = curValue, Y = curValue, Z = curValue })
                        end
                    end
                end
            end
        end
    )

    -- ... 其他初始化逻辑 ...
end

-- 在ReceiveEndPlay中清理回调
function Pet:ReceiveEndPlay()
    -- ... 其他清理逻辑 ...
    if self.SizeChangedDelegate then
        UGCAttributeSystem.RemoveGameAttributeChangedDelegate(self, "Size", self.SizeChangedDelegate)
        self.SizeChangedDelegate = nil
    end
end
```

## 完整工作流程图

```
服务端 (ExpLevelUp:Execute)
  │
  ├── 1. 计算新等级 Level + 新体型 newSize
  │
  ├── 2. SetGameAttributeValue("Size", newSize)
  │      │
  │      ├── 服务端触发 OnSizeChanged 回调
  │      │     ├── SetActorScale3D → 碰撞体变大 ✅
  │      │     ├── CachedMasterPoseComponent → SetWorldScale3D ✅
  │      │     └── 遍历 SkeletalMeshComponent 兜底 ✅
  │      │
  │      └── 属性同步到客户端
  │             │
  │             └── 客户端触发 OnSizeChanged 回调
  │                   ├── SetActorScale3D → 碰撞体变大（客户端）✅
  │                   ├── CachedMasterPoseComponent → 视觉网格变大 ✅
  │                   └── 遍历 SkeletalMeshComponent 兜底 ✅
  │
  └── 3. 直接调用 SetActorScale3D（双重保障）
       └── 同时尝试 CachedMasterPoseComponent 和遍历组件
```

## 关键注意事项

### 1. 组件获取的数组索引

`GetComponentsByClass` 返回的数组是 **1-based 索引**，必须使用 `ipairs` 遍历：

```lua
-- 正确
for i, comp in ipairs(compList) do ... end

-- 错误（会漏掉第1个元素）
for i = 0, #compList - 1 do ... end
```

### 2. Lua 属性访问方式

在 Lua 中访问蓝图的组件属性时，使用 `self.ComponentName` 直接访问：

```lua
-- 访问蓝图中的 AvatarDisplayProxyComp 组件
local proxyComp = pet.AvatarDisplayProxyComp

-- 访问代理组件的内部属性
local masterMesh = proxyComp.CachedMasterPoseComponent
```

如果属性名不确定或可能 nil，始终用 `pcall` 包裹。

### 3. AddGameAttributeChangedDelegate 的双端特性

`UGCAttributeSystem.AddGameAttributeChangedDelegate` 注册的回调**在服务端和客户端都会触发**：

- **服务端**：当 `SetGameAttributeValue` 调用时，立即触发
- **客户端**：当属性值从服务端同步过来时，触发

因此，在回调中执行 `SetActorScale3D` 和 `SetWorldScale3D` 是安全的（这些 API 在两端都有定义）。

### 4. 清理委托

必须在 `ReceiveEndPlay` 中清理注册的委托，防止 Actor 销毁后回调仍在执行导致崩溃：

```lua
if self.SizeChangedDelegate then
    UGCAttributeSystem.RemoveGameAttributeChangedDelegate(self, "Size", self.SizeChangedDelegate)
    self.SizeChangedDelegate = nil
end
```

### 5. pcall 安全调用

所有可能返回 nil 或可能抛异常的 Lua API 调用，都应该用 `pcall` 包裹：

```lua
local ok, result = pcall(function()
    return someObject.SomeMethod()
end)
if ok and result then
    -- 使用 result
end
```

### 6. 骨骼网格命名查看

如果需要打印组件名称（但某些环境不支持 `comp:GetName()`），可以直接用 `tostring(comp)`：

```lua
ugcprint("组件 = " .. tostring(comp))
```

## 常见问题排查表

| 现象 | 可能原因 | 解决方案 |
|------|---------|---------|
| `SetActorScale3D` 后碰撞体变大但模型不变 | AvatarDisplayProxyComp 接管了渲染 | 通过 `pet.AvatarDisplayProxyComp.CachedMasterPoseComponent` 缩放 |
| `GetComponentsByClass` 只找到 1 个组件 | 代理系统创建的网格可能不在同一个组件列表中 | 优先使用 `CachedMasterPoseComponent` 方案 |
| `comp:GetName()` 报 "attempt to call a nil value" | 该环境不支持 GetName 方法 | 改用 `tostring(comp)` 或去掉命名日志 |
| `SetGameAttributeValue` 后回调未触发 | 属性名拼写错误或属性系统未初始化 | 检查属性名是否在枚举中定义，确认回调在 `ReceiveBeginPlay` 中注册 |
| 客户端模型未变化 | 服务端缩放未正确同步 | 用 `AddGameAttributeChangedDelegate` 在客户端侧执行缩放 |
