## 一、结论

| 层 | 结论 |
| --- | --- |
| 直接现象 | 点击天赋图 → 缩到 `PressScale 0.94` → 回弹过程错乱/迟滞，不能稳定回到 1.0 |
| 根因 1（共用库） | `GetConfig()` 因 `UseTweenConfig=false` 恒返回 `nil`，`TweenFloatValue` 拿不到显式 `RepeatCount=0`，引擎吃默认 `RepeatCount=1` → **每个 Tween 实际播两遍**，中途跳回起始值 |
| 根因 2（天赋界面） | 一次点击触发**两套** `PlayButtonTap`（事件处理器一次 + `SelectTalent` 一次），键不同 → 同一 `SetRenderScale` 上并行两条 Tween，互相覆盖 |
| 修复 | ① 用官方 `UGCTweenSystem.ConfigureTween` 以基础类型参数显式写回 `Delay/RepeatCount/bYoyo`；② `PlayButtonTap` 终值兜底必写 1.0；③ 删除天赋图重复触发 |

**时序判读（决定性）**：相位 2 的 `Bounce` 时长为 0.220s，按下时刻 35.913；若播一遍，相位 3 应在 ≈36.133 创建。实测 **36.391**，即 **+478ms ≈ 2 × 220ms + 38ms（回调派发与日志开销）**。⇒ **该 Tween 播了两遍才完成**，证明引擎默认 `RepeatCount = 1`（与通用知识「`RepeatCount` `0` 播一次、不要依赖 `MakeConfig` 默认值 `1`」一致）。

播两遍的视觉后果：相位 2 在第一遍结束时**跳回起始值 0.94 再跑一遍**，表现就是「缩小后回不来、反复变小」；两套并行 Tween 又把终值互相覆盖，1.0 不再可靠。

## 三、官方依据

- `raw/docs/api/class/Others/UGCTweenSystem.md`：`TweenFloatValue(Start, End, Duration, Easing, Callback, Config)`，`Config` 标注「不传则使用默认值」；`MakeConfig(Delay, RepeatCount, bYoyo, RepeatDelay)` 默认 `RepeatCount = 1`；**`ConfigureTween(Handle, Delay, RepeatCount, bYoyo, RepeatDelay)`** —— 「配置已创建的 Tween 的高级属性（延迟/循环/Yoyo）」，参数全为基础类型。
- `raw/docs/wiki/通用功能/20351_Tween功能.md`：`BindCompletedDelegate(Handle, Callback)` 为官方完成回调入口。
- 通用知识 `绿洲UI动效与Tween.md`：`RepeatCount` 必须显式传、`0` 播一次；`KillTween` 会把对象拉回起始值；**不要在完成回调里再创建 Tween**（`PlayButtonTap` 的相位链依赖完成回调，属已知张力，本次保留该结构但加了终值兜底）。

## 六、Round 3：修复后仅「洁净习性(QJ)」回位，其余 7 个仍卡缩小

- 类型：项目日志证据 + 代码修复
- 主题：天赋点击回弹动效（UIMotionKit.PlayButtonTap）
- 适用范围：pet_paradise / TianFu 天赋 UI（8 个天赋图 TX/DGSY/JK/JE/XQ/QJ/DGSC/SH）
- 证据状态：官方确认（ConfigureTween 语义、同属性并发规则）+ 项目实测（11:58 会话日志、luaparser AST）
- 更新时间：2026-09-18
- 关联主题：四、Round 2 修复；`Script/Common/UI/UIMotionKit.lua`

### 6.1 现象

Round 2 补丁落地后重新 PIE，用户反馈：**除「洁净习性」(QJ) 外，其余 7 个天赋点击后一直处于缩小状态**。

### 6.2 日志证据（项目实测）

会话 `2026.09.18-11.58.16_client__dkck7pnfrvsamp_1`（帧 7700~8950 全量导出，121 行）：

- 8 个天赋的动效序列**完全一致**：每次点击都是 `缩放 → 0.94(0.080)` → `缩放 → 1.03(0.220)` → `点击反馈，键 talent-XX` → **+26 帧后** `缩放 → 1.0(0.150)`。
- 各键点击次数：`entry-tf`1 / `TX`2 / `DGSY`1 / `JK`1 / `JE`2 / `XQ`4 / `QJ`6 / `DGSC`2 / `SH`2。
- 点击区间内**除 UIMotionKit 外没有任何其它代码改动控件**；`SafeWidgetCall` 无一条 `SetRenderScale` 失败日志。
- 结论：**日志无法区分 QJ 与其余 7 个**——链路在日志层面都走到了相位 3。

蓝图侧核验（UGCAskQ MCP 只读，`schema:.../TianFu.TianFu_C`）：

- `TX/QJ/JK/JE/XQ/DGSC/SH/DGSY` 与其 `_1` 副本**全部是 `UImage*`**，结构完全对称，**排除控件类型/身份差异**。

### 6.3 根因（官方依据 + 代码实测）

**`PlayButtonTap` 的相位 1 与相位 2 共用同一 Key 且同步连发**（修复前代码）：

```lua
UIMotionKit.PlayScale(..., METRICS.PressScale, "Instant", Key, nil, 1.0)
UIMotionKit.PlayScale(..., METRICS.ReleaseScale, "Bounce", Key, function() ... end, METRICS.PressScale)
```

`StartTween` 建柄前固定执行 `KillByKey(Owner, Key)`，因此**相位 2 创建时会立刻 Kill 掉相位 1**：

1. 相位 1（按下回压 0.94）在**未渲染任何一帧时即被杀**，按下回压在画面上完全不可见；
2. 整条链（0.94→1.03→1.0）的终值**只能依赖完成回调**，`KillGroup` 无任何终值兜底；
3. 一旦上一条链被后续点击打断（实测相邻点击最接近仅约 390 ms，而链路总长约 370 ms），被杀相位把控件留在被杀瞬间的缩放值，**表现为「点过的天赋一直保持缩小」**；QJ 是日志中最后一个被点的天赋、从未被后续点击打断，因此只有它回位。

官方依据：
- `raw/docs/wiki/通用功能/20351_Tween功能.md` 第 988-993 行：「同一属性：会产生冲突，导致动画效果混乱；解决方案：使用链式动画串联执行，或停止当前动画后再创建新动画」。
- 同上第 968-972 行：`RepeatCount = 0` 为不重复、完成时触发回调（Round 2 写入的 `RepeatCount=0` 语义正确，已核实无误）。

### 6.4 修复（已落地）

文件：`Script/Common/UI/UIMotionKit.lua`、`Script/Blueprint/Prefabs/UI/TianFu/TianFu.lua`

1. **相位串行**：相位 2 改在相位 1 的完成回调内创建，相位 3 在相位 2 完成回调内创建。
   `BindCompletion` 的委托会先执行 `Owner._UIMotionGroups[Group.Key] = nil` 再调 `OnComplete`，因此串行创建**不会触发自 Kill**。
2. **Kill 终值兜底**：`StartTween` 增加 `Terminal` 形参 → `Group.TerminalWidget/TerminalScale`；`KillGroup` 在清句柄后调用
   `SetScale("KillGroup", Group.TerminalWidget, Group.TerminalScale)`。点击链三个相位统一传 `{ Widget = Widget, Scale = 1.0 }`，
   **任何时刻被打断都强制写回 1.0**，结构性消灭「卡缩小」。
3. `PlayScale` 增加第 8 个形参 `Terminal` 并透传；不影响既有调用点。
4. **`PlayAttention` 键补上 `ExtraKey`**：原实现固定用 `MakeKey(Widget, "attention")`，忽略调用方传入的 `ExtraKey`，
   同一宿主下两个控件的呼吸动效会互相 Kill；改为 `"attention:" .. tostring(Options.ExtraKey or "default")`。
5. **控件身份日志**：`PlayButtonTap` / `PlayScale` 的 `LogInfo` 末尾追加 `，控件 <tostring(Widget)>`，供下一轮日志确认 `tostring` 是否唯一。

### 7.5 待查证

1. `UIMotionKit` 是否有可靠的运行时读取接口（如 `Widget:GetRenderScale()`）？
