| 需求 | 结论 |
| --- | --- |

## 二、持久化机制真值（项目实测 + 官方 API）

1. **`UGCPlayerController` 蓝图变量本身不跨局持久化**。它只是服务端玩家数据的**镜像**，供 UI / 蓝图读取。真正落盘必须走服务端：
   - `UGCPlayerStateSystem.GetPlayerArchiveData(uid)` / `SavePlayerArchiveData(uid, data)`
   - 本项目封装在 `Script/Function/AuctionPlayerService.lua` 的 `LoadOrReconnectPlayer` / `SavePlayer`
2. 存档键 `AuctionConfig.ArchiveKey = "IslandAuctionKing"`（`AuctionConfig.lua:5`），版本号 `ArchiveVersion = 3`（第 6 行），上报上限 256KB。
3. PIE 环境跨会话继承依赖 `Saved/ArchiveData/<Proj>/<uid>.json`；正式环境由平台存档服务承载。

## 三、五个持久化缺口的根因

| # | 缺口 | 根因 |
| --- | --- | --- |
| 1 | 角色/道具组选择丢失 | `SavePlayer` 用 `GetPersistentSelectedPropGroup/Character` 做「授权过滤」：`Test.EnableAllSelections=true` 时，未购买的道具组与非默认角色一律被判为「测试授权临时选择」，回落默认值写入存档 → 重进必丢 |
| 2 | 组内道具使用情况丢失 | `player.UsedProps` **从未写入存档**；`LoadOrReconnectPlayer` 每次硬编码恢复为 `{}` |
| 3 | 选择/购买/使用后未即时落盘 | `SavePlayer` 只在少数时机被调用，期间进程/对局结束则丢失 |
| 4 | 开局激活道具组清空使用记录 | `ActivateSelectedPropGroup` 无条件 `player.UsedProps = {}` |
| 5 | 蓝图变量缺位 | 控制器只有 `AuctionGold`/`AuctionOwnedPropGroups`/`AuctionOwnedProps`，无选择与使用镜像 |

## 六、MCP 蓝图变量类型坑（本轮实测，重要）

1. `ue.blueprint_add_member_variable(bp, name, "str")` **会生成 int32**。正确类型串是 **`"string"`**（同族：`"int"` / `"float"` / `"bool"`）。
2. 已建错类型的变量**无法用 Python 直接改 `VarType`**：`v.VarType.PinCategory = "string"` 与 `v.VarType = goodVarType` 都会把类型写空（回读 `PinCategory=''`）。
   **正解**：`v.set_field("VarType", <已有同类型变量的 VarType>)` → `ue.compile_blueprint(bp)` → `bp.save_package()`。
3. 验证用 `bp.GeneratedClass.get_uproperty(name)` 看 UClass 名（`StrProperty` / `IntProperty`）。**`schema:` 查询有缓存，reload 后仍可能显示旧类型**，不可作为最终依据。
4. `ue.load_object(None, path)` 报 `argument is not a UObject` → 必须先 `ue.find_class("UGCWidgetBlueprint")` 再 `load_object(cls, path)`。
5. `data_table_add_row(name, dict)` 报 `argument is not a UScriptStruct` → 必须 `r = tbl.data_table_empty_row()` + `r.set_field(...)` + `data_table_add_row(name, r)`，再用 `data_table_find_row` 回读。
