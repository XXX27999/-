## 一、问题 1：仓库滑到底仍被截断，只能看到 10 行

### 现象

结算界面右侧仓库应展示 6 列 × 14 行（84 格）。实测滚动到底后仍有若干行看不到，可视内容约 10 行。

### 取证

| 项 | 数值 | 来源 |
| --- | --- | --- |
| 结算网格 | `grid=6x14`、`cellSize=118`、`cellStep=122`、`gap=4` | 日志 `GetSettlementMetrics 关键数据` |
| 内容宽高 | `GridWidth=728`、`GridHeight=1704` | `cellSize*cols + gap*(cols-1)` / `cellSize*rows + gap*(rows-1)` |
| 视口高度 | `viewHeight=728`（`VisibleRows=6`） | 日志 `ApplySettlementScrollGeometry` |
| 脚本写入 | `widthOverride=728.0 heightOverride=1704.0` | 日志 `ApplySettlementScrollGeometry 关键数据` |
| 蓝图设计态 | `HeightOverride=1239.0`、`WidthOverride=527.0`、`bOverride_HeightOverride=True` | MCP `ue_py` → `WarehouseContentSizeBox.as_dict()` |

`1239 ÷ 122 ≈ 10.15` 行，与用户口述的「只能看到 10 行」完全吻合。

### 根因

脚本用**属性赋值**写入尺寸：

```lua
sizeBox.WidthOverride = metrics.GridWidth
sizeBox.HeightOverride = metrics.GridHeight
```

Lua（slua）侧的属性赋值只改 `UObject` 字段，**不会触发 `SynchronizeProperties`**，已构建的 `SSizeBox` 仍持有设计态值 `1239`。`UScrollBox` 的滚动范围按 Slate 侧子控件期望高度计算，因此内容实际只有 1239 可滚 → 第 11~14 行永远滚不到。

日志里回读 `heightOverride=1704.0` 只是**读回刚写的 UObject 字段**，不能证明 Slate 已同步——这正是上一轮误判「几何已生效」的原因。

### 修改

1. `AuctionSettlementUIService.lua` 新增 `ApplySizeBoxOverrides(sizeBox, width, height)`（L893）：
   - 优先调 UMG 方法 `SetWidthOverride` / `SetHeightOverride`（内部同时写属性并推送到 Slate）；
   - 补 `SetMinDesiredHeight`（防子 `CanvasPanel` 期望高度 0 导致滚动范围塌缩）；
   - 方法不存在时退回属性赋值，并把实际采用的写入方式记进日志 `applied=`。
2. `ApplySettlementScrollGeometry` 改用该辅助函数，并新增滚动范围探针：`scrollBox.GetScrollOffsetOfEnd` 可读时打印 `scrollOffsetOfEnd`。
   - 判据：内容 1704 / 视口 728 → **期望 `scrollOffsetOfEnd ≈ 976`**；若仍约 511 则说明 Slate 仍按 1239 计算。
3. 蓝图 `AuctionSettlementUI` 兜底：`WarehouseContentSizeBox.WidthOverride 527→728.0`、`HeightOverride 1239→1704.0`（MCP `ue.widget_set_property` + `save_package`，回读 `bOverride_*` 均为 True）。改前已备份 `.uasset` 到
   `D:\知识库\和平精英绿洲起源\备份\IslandAuctionKing\20260922_结算界面布局异常\before\uasset\AuctionSettlementUI.uasset`。

> 注意：蓝图设计态是**兜底值**，网格行数/格子尺寸改配置后仍需同步该值，或被运行时的 `SetHeightOverride` 覆盖。

## 二、问题 2：跳过展示后左侧藏品价值不变成最终仓库价值

### 现象

点「跳过」后，右侧仓库估值变成最终值，左侧「藏品估值 / 净收益」停留在跳过前的中间累加结果。

### 根因

`AuctionSettlementUIService.SkipShowcase` 的 `pcall` 块内**只更新右侧**：

```lua
local totalValue = tonumber(widget.InitialEstimatedValue) or 0
for _, item in ipairs(items) do totalValue = totalValue + (tonumber(item.Valuation) or 0) end
widget.EstimatedValue = totalValue
ApplyWarehouseEstimateTexts(widget, totalValue)   -- 只写右侧
```

而写左侧的唯一路径是 `ShowNextItem`（`widget.AccumulatedValue += item.Valuation` → `ActualValueText` → `ProfitText` → `EstimatedValueText`）。跳过流程根本不走 `ShowNextItem`，左侧永远停在最后一次 `ShowNextItem` 的中间值。

### 修改

`SkipShowcase` 内收敛到最终值（口径对齐 `ShowNextItem`）：

- `itemTotalValue` = 本轮全部藏品估值合计（**不含**进入结算前已有估值，与 `AccumulatedValue` 语义一致）；
- `totalValue = InitialEstimatedValue + itemTotalValue`（右侧仓库最终估值，口径不变）；
- 补写左侧：`widget.AccumulatedValue = itemTotalValue`、`ActualValueText = FormatSettlementMoney(itemTotalValue)`、
  `ProfitText = FormatSettlementMoney(itemTotalValue - FinalPrice)`，并 `ApplySettlementGoldText(..., 32)`；
- 新增关键数据日志：`itemTotalValue / initialValue / totalValue / finalPrice / finalProfit / serverFinalProfit`。

`widget.FinalProfit` 保持服务端权威值**不覆写**，只做日志对比。
