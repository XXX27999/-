## 一、需求

1. 人机道具使用概率第一轮最大、第五轮最小，按轮次递减。
2. 轮次详情中玩家名字与计分板不同步：详情标题与玩家名显示的是 `PlayerKey`（如 `-910001`），而计分板显示 `DisplayName`（如 `小唐`）。

## 二、实现

### 2.1 按轮递减的道具概率

文件：`Script/Function/AuctionBotService.lua`

- 新增模块级函数 `GetPropUseChance(bidRound)`：
  - 读取 `Bot.PropUseChanceByRound`（英文逗号分隔序列），按 `bidRound` 取第 N 项。
  - 序列缺项时回退 `Bot.PropUseChance`（默认 `0.4`）。
  - 结果 clamp 到 `[0, 1]`。
- `AuctionBotService:TryUseProp(player)` 的随机判定改为 `local chance = GetPropUseChance(owner.BidRound)`。
- 随机跳过分支日志补充轮次：`本轮随机不使用道具 BidRound=<N> chance=<X>`。

文件：`Asset/Data/Table/Customized/Bot/BotConfigTable`（MCP 写入，plan_id `plan_16781828_23570973`）

- 新增行 `Bot.PropUseChanceByRound`，`ValueType=string`，`Value=0.9,0.7,0.5,0.3,0.15,0.1`。
- 表行数 21 → 22。
- MCP 回读确认四列值：
  - `ValueType` = `string`
  - `Value` = `0.9,0.7,0.5,0.3,0.15,0.1`
  - `Description` = `人机各竞价子轮道具使用概率，按轮次递减：第一轮最大、第五轮最小；第6轮为并列加赛的兜底概率。`
  - `ModificationNotes` = `修改注意事项：英文逗号分隔 6 个 0~1 数值，依次对应第1~6子轮；缺项回退 Bot.PropUseChance。生效：重新 PIE。`

### 2.2 轮次详情玩家名同步

文件：`Script/Function/AuctionRoundHistoryUIService.lua`

- 新增模块级函数 `FindPublicDisplayName(publicState, playerKey)`：
  - 从 `publicState.PublicScores[].DisplayName` 取值（与计分板同一数据源）。
  - 未命中回退 `"玩家 <PlayerKey>"`；空 key 回退 `"未知玩家"`。
- `OpenRoundDetail` 中 `displayName` 同时用于：
  - `RoundDetailTitleText`：由 `"玩家 " .. PlayerKey .. " · 第 N 轮"` 改为 `displayName .. " · 第 N 轮"`。
  - `RoundDetailPlayerText`：由 `PlayerKey` 改为 `displayName`。
- 出口日志新增 `PlayerKey=... displayName=...`。

数据链路依据：`AuctionGameService.lua` 中 `PublicScores = self.PlayerService:BuildPublicScores(...)`，`AuctionPlayerService:BuildPublicScores` 输出字段含 `PlayerKey / TotalProfit / SelectedCharacter / IsBot / DisplayName`，因此客户端可从公共状态直接取展示名。

## 四、探针方法与注意

- `ue_pie doluastring` 的 DS 目标经客户端转发；返回 `{}` 只代表派发成功，必须回读 DS 日志确认。
- 运行时实例入口：`UGCGameSystem.GetGameMode().AuctionRuntime`；`AuctionRuntime.BotService` 为 `AuctionBotService` 实例，`AuctionRuntime.PlayerService:GetPlayerByKey(-910001)` 可取人机玩家。
- `NextUnit` 为线性同余：`seed = (seed * 1103515245 + 12345) % 2147483647`。种子 `33` 首次取值 `0.9575286316487606`，高于全部六轮概率，故可只观测概率而不触发道具消耗。
- **本轮探针一度消耗了道具**：`PROBE3` 用种子 `2147483646` 使随机门禁通过，`-910001` 连续使用了 `特殊尺寸仪器 / 中型鉴定仪器 / 中型品鉴仪器`。该行为只发生在已进入 `Phase=Ended` 的本局运行时，人机不写存档，因此不产生持久化副作用；后续 `PROBE4` 已改用高值种子规避。
- 探针改写 `rt.BidRound` 与 `p.BotSeed` 后已恢复原值。
