## 二、根因（实测证据）

### 2.1 决定性日志

DS TagLog（2026-09-17 多局一致，UID=10001）：

```
【BackpackArchiveHelper+SnapshotBackpack】错误: 获取物品实例列表失败, Error=userdata: 0x7f62471080a8
【BackpackArchiveHelper+MergeBackpackIntoArchive】错误: 背包快照失败，保留既有快照, UID=10001, Reason=获取物品实例列表失败
【ControllerExitGame+SaveAllPlayerArchive】分支: 背包快照合并未执行，保留存档既有PlayerBackpack, UID=10001
```

登录侧对应日志：

```
【BackpackArchiveHelper+RestoreBackpackFromArchive】分支: 存档无背包快照，跳过恢复
```

出现位置（2026-09-17 DS TagLog）：`16.56.42`、`17.08.26`、`17.34.48`、`17.55.52`、`18.12.00` 等每一局。

### 2.2 代码链路

1. `SnapshotBackpack` 调 `UGCBackpackSystemV2.GetAllItemDefineIDsV2(owner)`。
2. 该接口在 Lua 侧返回 **userdata**（UE 容器包装），`type(defineIDs) ~= "table"` 恒为 true。
3. → 快照恒返回 `nil` → `MergeBackpackIntoArchive` 返回 false → `PlayerData["PlayerBackpack"]` 从未写入。
4. → 登录 `RestoreBackpackFromArchive` 读到 `archivedBackpack` 为 nil → 跳过恢复。
5. 叠加官方 `ShouldPersist=false`（物品 Handle 蓝图 CDO 属性）→ 卡类跨局不持久化 → **净丢失**。

### 2.3 官方依据缺口

`raw\docs\api\class\和平全局接口\物品与背包\UGCBackpackSystemV2.md` 中 `GetAllItemDefineIDsV2` 的 **Return Type 为空（未标注）**，不可假定为 Lua table。同文档 `GetItemCountV2` 同样未标注 Return Type，但工程内 `CF_KHDRPC.ServerReceiveUseItem`、`BackpackCapacityHelper.CheckGrantBlocked` 长期使用 `tonumber(GetItemCountV2(...))` 且日志显示数值正常，**属于已验证可用接口**。

## 三、修复内容（仅动一个文件，不影响其他道具）

文件：`Script/Common/Utils/BackpackArchiveHelper.lua`

1. 新增 `SnapshotAllowlist(owner)`：遍历 `PersistItemIDs` 白名单的固定 ID，逐个 `GetItemCountV2`；>0 才写入快照；读取失败（pcall 失败或 `tonumber` 为 nil）时**跳过该 ID 并打错误日志**，禁止用 0 覆盖误判为"已用完"。
2. `SnapshotBackpack` 的 `allowlist` 分支改走 `SnapshotAllowlist`；`all` 分支显式报错返回（依赖枚举接口，当前不可用）；`off` 分支不变。
3. 白名单补齐 `8310062`、`8310070`（原只有 `8310071`）。依据 MCP 回读 `UGCBattleItem`：

   | ItemID | ItemName | ItemHandlePath |
   | --- | --- | --- |
   | 8310062 | 扫荡卡 | `.../WorkItems/WorkItem/SDK.SDK_C` |
   | 8310070 | 扫荡卡 | `.../WorkItems/WorkItem/SDK.SDK_C` |
   | 8310071 | 扫荡卡 | `.../WorkItems/WorkItem/SDK.SDK_C` |

   三个 ID 名称与 Handle 完全一致，只兜底 8310071 会漏掉另外两个。
4. 存档侧与恢复侧日志补打快照明细（`ItemID=Count;...`），回归时可直接从日志核对每张卡数量。
5. 保留 `ShouldPersistItem` 供外部查询与后续 `all` 模式复用（当前 allowlist 路径不再调用）。

### 未改动（有意保留）

- `PersistMode` 仍为 `"allowlist"`：不整包快照，避免把武器/金币/改名卡等官方刻意不持久化的物品补回来。
- 恢复仍为「差量补发」：`missing = 存档数量 - 当前数量`，官方恢复到位时差量为 0，不会重复发放。
- 恢复仍先用 `BackpackCapacityHelper.CheckGrantBlocked` 做容量前置拦截。

## 五、尚未覆盖的风险点

1. **保存时机唯一**：快照只在最终存档写入一次。局中获得卡后若 DS 崩溃 / 强退 / 未触发 EndPlay，快照停留在上一局值 → 本局新增仍会丢失。后续可在局内 patch 存档路径（`SaveCardArchivePatch`）追加快照刷新，但会扩大改动面，本轮未做。
2. **Pawn 失效时保留旧快照**：`MergeBackpackIntoArchive` 在 `PlayerPawn` 为 nil 时返回 false 且不覆盖，安全（不会清空），但也意味着该次退出没记录最新数量。
3. **恢复重试上限**：`CheckInitPersistCompleted` 未完成时延 1 秒重试，最多 5 次；超时跳过本轮但快照仍保留在存档，下次登录继续补发 → 属延迟补发，不是永久丢失。
4. **打工翻倍卡扣除口径不一致（低风险，需实测确认）**：`WorkMult:OnUseV2` 显式 `RemoveItemV2(PlayerController, ...)`，与工程内其他入口传 `PlayerPawn` 的口径不一致；官方签名 `Player` 标注为 `PlayerPawn | PlayerController`，理论上两者皆可。
   - **已证伪"双扣"猜测**：官方 Wiki `20101_物品编辑器.md` 第 392-410 行的示例基于**空白消耗品**模板，`OnUseV2` 内只加 Buff、不显式 `RemoveItemV2` ⇒ 消耗品模板由 `SuperClass.OnUseV2` 负责扣减。但 MCP 回读 `UGCBattleItem` 显示 8310012 / 8310013 / 8310006-8 / 8310062 / 8310070 / 8310071 的 **`Consumable` 全为 `False`** ⇒ 官方不会自动扣，显式 `RemoveItemV2` 是必要的且只扣一次，**不是双扣**。
   - 仍需回归确认：一次使用是否恰好扣 1 张（见回归清单「单卡专属验证点」）。
5. **完美打工卡效果跨局**：效果存宠物属性 `WorkPerfectCard`（到期时间戳），跨局依赖宠物存档，不在本轮"道具数量"修复范围，回归时需一并看。
6. **扫荡卡旧 ID 来源未查清**：8310062 / 8310070 是否仍会通过掉落/商店/补偿发放，本轮未查证；已按"三个 ID 全兜底"处理。

### 通用步骤（四张卡都一样）

| # | 步骤 | 通过判据 |
| --- | --- | --- |
| 1 | 进入 PIE，GM 发放目标卡 N 张，打开背包记下数量 N | 背包显示 N |
| 2 | 直接退出（点离开 / 关闭 PIE） | DS TagLog 出现 `【BackpackArchiveHelper+MergeBackpackIntoArchive】出口: UID=..., Reason=..., 背包快照物品种类=..., 明细=<ItemID>=<N>;`；**不再出现** `获取物品实例列表失败` |
| 3 | 重新进入 | TagLog 出现 `【BackpackArchiveHelper+RestoreBackpackFromArchive】入口: 存档快照明细=<ItemID>=<N>;`；**不再出现** `存档无背包快照，跳过恢复` |
| 4 | 打开背包核对 | 数量仍为 N（官方若已持久化则差量 0，不会重复发放） |
| 5 | 用掉 K 张（K<N），立即退出 | 退出日志明细为 `<ItemID>=<N-K>` |
| 6 | 重新进入 | 数量为 N-K，且**没有**被补回 N |
| 7 | 局中再发 M 张后退出重进 | 数量 = 剩余 + M |
| 8 | 把卡用到 0 后退出重进 | 数量 0，且日志快照中**不含**该 ItemID（不能被补回） |

### 边界场景（每张卡在步骤 1-8 通过后补跑）

| 场景 | 操作 | 通过判据 |
| --- | --- | --- |
| A 断线重连 | 局中直接杀客户端进程 / 断网后重连 | 重连后走 `LoadPlayerArchive`，恢复日志存在，数量不丢 |
| B 回合切换 | 局内触发回合/局切换（不退出 DS） | 切换后数量不变；若重走了 LoadPlayerArchive，差量补发为 0，不会翻倍 |
| C 使用后立即退出 | 用 1 张后在 1 秒内退出 | 退出快照为 N-1，重进为 N-1（验证扣除先于快照） |
| D 背包满时恢复 | GM 填满背包后带卡退出重进 | 出现 `背包已满，剩余物品保留在存档中待下次登录补发`，清理背包再登录能补齐（不永久丢） |
| E 卡用尽边界 | 只剩 1 张，用掉后退出重进 | 数量 0，快照中无该 ID |
