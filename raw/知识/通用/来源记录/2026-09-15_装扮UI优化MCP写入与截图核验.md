## 一、本绑定不存在的 API（v1 脚本据此写错，实测报错原文）

| 写法 | 实测报错 | 正确写法 |
| --- | --- | --- |
| `slot.call_function('SetPosition', V2(x,y))` | 不存在该方法 | UFunction 用 Layer 1 PascalCase 直接调；但槽位几何见下 |
| `slot.set_editor_property('ZOrder', n)` | `AttributeError: 'unreal_engine.UObject' object has no attribute 'set_editor_property'` | `slot.ZOrder = n`（直接属性赋值） |
| `v.set_field('x', 0.0)`（v 为 `anc.get_field('Minimum')`） | `AttributeError: 'unreal_engine.FVector2D' object has no attribute 'set_field'` | `anc.set_field('Minimum', ue.FVector2D(0.0, 0.0))`（构造后整体写） |

结论：
1. **没有 `set_editor_property`**，一律 Layer 1 直接赋值（`obj.Prop = value`），批量时用 `setattr`。
2. **没有 `call_function`**，UFunction 直接点号调用。发现用 `obj.functions()` / `obj.properties()`。
3. **`FVector2D` 是纯结构体值，没有 `set_field`**：作为**子结构体字段**必须先 `ue.FVector2D(x,y)` 构造再整体 `set_field`；只有 `float` 标量字段（如 `Offsets.Left/Top/Right/Bottom`）能逐字段 `set_field`。

`TextBlock` 文案：`ue.FText` **不存在**，`w.SetText('中文')` 直接传 `str` 成功（`TextBlock.functions()` 含 `SetText`）。

## 二、UMG 槽位几何的存放位置（决定遍历方式）

实测 `UIButton01` 等行控件的 Slot 是 **`VerticalBoxSlot`**，`sl.get_property('LayoutData')` 直接报 `unable to find property LayoutData`。

| Slot 类型 | 几何属性 | 写法 |
| --- | --- | --- |
| `CanvasPanelSlot`（CanvasPanel 的子级） | `LayoutData{Offsets, Anchors, Alignment}` | `ld.get_field('Offsets').set_field('Left', float)`；`ld.set_field('Alignment', FVector2D(0,0))`；`anc.set_field('Minimum', FVector2D(0,0))` |
| `VerticalBoxSlot`（VerticalBox 的子级） | **无 `LayoutData`**，只有 `Size={Value,SizeRule}`、`Padding={Left,Top,Right,Bottom}` | `sl.get_property('Size').set_field('SizeRule', 1)`；`sl.get_property('Padding').set_field('Bottom', gap)` |

`CanvasPanelSlot.properties()` 只暴露 `ZOrder` / `bAutoSize`（几何不在里面）；`functions()` 含 `SetPosition/SetSize/SetAlignment/SetAnchors/SetZOrder/SetOffsets/SetMinimum/SetMaximum`，但本轮采用结构体直写（项目既有可行路径），未验证这些 UFunction 的调用形式。

`VerticalBoxSlot.functions()` = `SetHorizontalAlignment` / `SetPadding` / `SetSize` / `SetVerticalAlignment`（**无** `SetPosition`/`SetAlignment`/`SetZOrder`）——按 Slot 类型分支处理是必需的。

## 三、`widget_add` 后 `WidgetTree.AllWidgets` 不刷新（对索引策略的修正）

实测：连续 `ue.widget_add(wbp, 'Border', name, parent)` 新增 7 个控件后，`len(widget_bp.WidgetTree.AllWidgets)` 仍为 **73**（未变）；`compile_blueprint` 之后才变 86。

但**从 `RootWidget` 递归遍历读的是实时控件树**，新增控件立即可见（同一次调用内即得 86）。

对既有结论的订正：`UGCAskQ-MCP实测陷阱清单` 第 3 条记「`WidgetTree.AllWidgets` 恒为空须手动递归」；本轮实测 `AllWidgets` **非空但会滞后**。两者合并后的正确策略是：**索引一律以 `RootWidget` 递归为主，`AllWidgets` 仅作兜底**，不能把 `AllWidgets` 当权威实时来源。

## 四、FlaUI 编辑器截图：窗口能列出 ≠ 画面有目标 UI

背景：`AuctionDressUI` 已用 MCP `open_editor_for_asset(wbp)` 在设计器打开（返回 True），`FlaUiCapture.exe --list` 也返回了该 PID 的编辑器窗口，但两个候选窗口的画面都不是 UMG 设计器：

| 标题 | 尺寸 | 均值亮度 | 白像素占比 |
| --- | --- | --- | --- |
| `ShadowTrackerExtra (64 位，PCD3D_SM5) <pid>, Compiled: ...` | 1936×1048 | 73.6 | 7.4% |
| `调试游戏` | 1000×600 | 251.75 | 95.8% |

根因：`FlaUI.Core.Capturing.Capture.Element(window).ToFile(...)` 读的是**桌面矩形**，遮挡窗口会一起被抓进来。所以「窗口存在/已激活」不能推出「设计器画面可见」。

**确定性判据（不依赖肉眼）**——用设计 token 反查像素：

```python
import numpy as np
from PIL import Image
a = np.asarray(Image.open(png).convert('RGB')).astype(np.int16)
m = (np.abs(a[:,:,0]-245) <= 14) & (np.abs(a[:,:,1]-163) <= 14) & (np.abs(a[:,:,2]-59) <= 14)  # 金 #F5A33B
print(int(m.sum()))     # 命中 0 → 目标 UI 不在画面内
```

处置：命中 0 的 PNG **不得当成功截图交付**，改名 `capture_fail_*.png` 留存证据并回报状态码。

## 五、顺带确认的可用项

- `ue.objed_open_editor('UI')`、`ue.objed_save_asset(name, 'UI')`、`ue.open_editor_for_asset(wbp)` 均返回 `True` 可用（用于把资产在设计器打开）。
- 长脚本注入方式：脚本落在知识库备份目录，`exec(compile(open(SRC, encoding='utf-8').read(), 'mod', 'exec'), g)`，`g = {'__name__': 'mod'}`；**每次 `ue_py` 只调一个 step**，避免超长 code 与频率限制。捕获输出用 `contextlib.redirect_stdout(io.StringIO())` + `ue.log()`（`print` 不保证回传）。
- `FlaUiCapture.exe` 参数形态：`--list` / `--process-name X --title '<exact>' --output a.png [--activate]` / `--capture-file <资产路径>`；标题必须与 `--list` 完全一致（含全角括号与逗号），建议从 `--list` 输出里程序化取标题再传参，避免手抄。
