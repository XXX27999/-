# 知识库准确性与关联性读取写回规范

> 类型：知识库治理规范
> 来源：[2026-08-28 知识库准确性与关联性读取写回治理](../来源记录/2026-08-28_知识库准确性与关联性读取写回治理.md)、[2026-08-28 Codex 全局提示词与知识库规则对齐](../来源记录/2026-08-28_Codex全局提示词与知识库规则对齐.md)、[2026-09-14 创建文件存放边界](../来源记录/2026-09-14_创建文件存放边界.md)；关联治理页 [知识库分层与索引隔离](./知识库分层与索引隔离.md)、[Raw目录结构](./000_Raw目录结构.md)、[Wiki主索引模板](./001_Wiki主索引模板.md)
> 官方依据：知识库目录、索引和写回规则属于本仓库工程约定，官方文档不定义该组织方式。API、编辑器机制和错误码的事实依据仍分别以 `raw/docs/api`、`raw/docs/wiki` 为准。
> 状态：已建立，属于知识库执行规范；其中“相关性评分”是检索工程规则，不是官方功能结论。
> 更新时间：2026-09-14

## 一、目标与适用范围

本规范解决两个容易相互冲突的问题：

1. **准确度**：回答中的每个可执行结论都能追溯到实际存在的资料，并区分官方结论、项目实测、经验推断和待查证内容。
2. **关联性**：读取范围覆盖当前问题所需的直接知识和必要依赖，但不因共享一个泛关键词而加载整库无关内容。

本规范适用于知识库检索、回答前查证、开发问题排障、Lua/蓝图/UI 修改记录、以及每次回答后的知识回写。它不改变 `raw/docs/` 原始资料的内容，也不把项目专属事实提升为全局通用结论。

## 二、资料层级与证据状态

### 2.1 资料层级

| 优先级 | 资料位置 | 主要用途 | 使用规则 |
| :--- | :--- | :--- | :--- |
| 1 | `raw/docs/api` | API 是否存在、参数、返回值、端侧和生命周期 | API 结论的唯一真源；不得用经验页替代 |
| 2 | `raw/docs/wiki` | 编辑器机制、操作路径、错误码和官方说明 | 解释机制与操作；与 API 页冲突时分别保留证据并标记冲突 |
| 3 | `raw/知识/通用` | 已整理的跨项目通用结论、规范和排障流程 | 作为检索入口和执行摘要，必须保留原始来源链接 |
| 4 | `raw/docs/ai` | 历史项目实战和 AI 整理记录 | 仅作为经验或案例；不能单独证明官方 API 行为 |
| 5 | `raw/<项目名>` | 项目配置、资产、蓝图回读、日志和实测结果 | 只对指定项目生效，不能直接写入全局概念结论 |
| 6 | 社区档案 | 补充实践经验和未覆盖线索 | 仅作辅助；必须标注社区来源和未被官方确认的状态 |

“优先级”用于确定事实依据，不等同于“离问题更近”。例如，项目 PIE 日志可以证明某项目当次运行结果，但不能推翻官方 API 的普适定义；应分别写成“官方定义”和“项目实测表现”。

### 2.2 证据状态

每个新增或修改的关键结论必须能归入下列状态之一：

| 状态 | 含义 | 允许的表述 |
| :--- | :--- | :--- |
| `官方确认` | `raw/docs/api` 或 `raw/docs/wiki` 有直接依据 | 可以作为通用结论和操作步骤 |
| `项目实测` | 有项目文件、MCP 回读、截图或 PIE/DS/客户端日志证据 | 只在对应项目范围内使用，除非另有跨项目证据 |
| `经验归纳` | 多个案例呈现一致做法，但没有官方直接说明 | 必须注明经验性质，不得写成 API 保证 |
| `推断` | 根据现有证据推导，尚未直接验证 | 单独放入“待查证”，不得放入核心结论 |
| `冲突` | 两份有效资料对同一事实给出不同结果 | 同时保留来源、版本、范围和验证结果，禁止静默覆盖 |
| `废弃` | 旧路径、旧做法或旧结论已被新证据替代 | 保留历史来源，明确替代页和失效条件 |

没有来源、证据状态或适用范围的句子，不得作为“已验证结论”写回。

## 三、Raw 文档的最小元数据

每个新增 Raw 正文或来源页的页首必须包含以下字段。已有老页可在下一次维护时补齐，不要求为了格式立即批量改写所有历史资料。

```markdown
> 类型：通用知识 / 项目证据 / 来源记录 / 治理规范
> 主题：UI / API / Lua / 蓝图 / PIE / 资产 / 配置表 / 其他
> 适用范围：全局通用 / IslandAuctionKing / 指定版本或端侧
> 证据状态：官方确认 / 项目实测 / 经验归纳 / 推断 / 冲突 / 废弃
> 来源：具体文件、MCP 回读、截图、日志或会话日期
> 更新时间：YYYY-MM-DD
> 关联主题：用逗号列出直接依赖的主题或文档名
> 排除范围：明确本页不覆盖的相邻主题，避免误读
> 官方依据：具体 `raw/docs/api` 或 `raw/docs/wiki` 路径；无官方依据时写明“未覆盖”
```

字段规则：

- `适用范围` 决定内容能否进入全局概念索引；项目路径、具体数值、资产名、日志原文默认是项目证据。
- `来源` 必须是可定位的绝对文件路径、仓库内相对路径、MCP 回读对象、截图路径或日志文件，不得只写“网上资料”“之前测试过”。
- `关联主题` 只填写直接依赖，不把整类文档作为关联；每个关联项应能在索引或目录中找到。
- `排除范围` 用于消除同名词误命中，例如图鉴 UI 页不自动包含结算 UI、DataTable 运行时加载或通用按钮事件。
- `官方依据` 不存在时写“知识库未覆盖”或“官方未确认”，并把可执行内容降为实测、经验或推断。

## 四、写回决策与执行流程

### 4.1 先判定内容归属

写回前先提取本轮的新事实、纠正项、项目数据和未解决问题，按下表分流：

| 内容特征 | 写入位置 | 是否进入 `wiki/` |
| :--- | :--- | :--- |
| API 存在性、参数、返回值、端侧限制 | 只能引用或补充对应官方 Raw；原始资料不可改 | 仅在已有概念页建立导航 |
| 可跨项目复用的 UI/Lua/蓝图操作规范 | `raw/知识/通用/<领域>/` | 建立短索引页并登记总索引 |
| `/<项目名>/Asset/...`、控件具体数值、DataTable 行值、MCP 回读 | `raw/<项目名>/<子目录>/` | 不进入全局概念正文 |
| PIE/DS/客户端日志原文或截图证据 | `raw/<项目名>/日志证据/` | 不进入全局正文；概念页只链接摘要 |
| 写前 `.uasset` 副本、调试临时脚本、非法文件名隔离文件 | `备份/<项目名>/<YYYYMMDD>_<Theme>/` | 不进 Wiki；禁止放回 UGC 工程 |
| 与地图运行无关的 Codex 文件（Python、网页、文档、报告、截图等） | `备份/<项目名>/<YYYYMMDD>_<Theme>/`；可复用正文另入 `raw/知识/通用/` | 不得写入 UGC 工程；蓝图、Lua 和运行所需导入资产按项目流程处理 |
| 新原始资料的来源、时间线和校验记录 | `raw/知识/通用/来源记录/` | 可在 `wiki/来源/` 建短索引 |
| 未确认的假设或待补充需求 | 原文页“待查证” | 不得写入核心结论 |

### 4.2 选择追加、修订还是新建

1. 先用标题、核心实体、API 全名、资产路径、错误文本和中英文别名检索已有 Raw 与索引。
2. 已有页面覆盖同一主题且适用范围相同：在对应小节追加证据或订正，不新建重复页。
3. 主题相同但项目范围不同：保留通用页，新增或更新项目证据页，并互加链接。
4. 结论被新证据纠正：更新状态为 `冲突` 或 `废弃`，记录旧结论、来源、原因和替代结论；不能直接删除历史证据。
5. 内容同时包含通用规则和项目事实：拆成两页，通用页引用项目证据，项目页引用通用规则。
6. 只增加一个新来源而没有新结论：写来源记录，不复制大段正文到概念页。

### 4.3 写回后的强制校验

写入后必须按顺序检查：

1. Raw 正文、来源页、项目证据和索引条目路径均真实存在。
2. 新结论的每一个 API、控件字段、资源路径、错误文本和参数都有来源或明确标记为未覆盖。
3. `官方确认`、`项目实测`、`推断`、`冲突`没有混写在同一无标记段落中。
4. 新页面与至少一个已有页面互有相对链接；索引条目指向 Raw 正文或短索引页，而不是不存在的概念正文。
5. 没有把项目数值、日志原文、未验证猜测写进全局通用页。
6. 文件为 UTF-8 无 BOM；相对链接、Raw 引用和项目索引路径可解析。
7. 用精确关键词复检新结论，确认没有旧结论仍以“已确认”状态孤立存在。
8. **相对链接必须逐级数层数，不能凭印象写。**

   知识库目录层级固定，`..` 的层数按“文件所在目录 → 知识库根”逐层数：

   | 文件位置 | 回到 `D:\知识库\和平精英绿洲起源\` 需要 |
   | --- | --- |
   | `raw\知识\通用\<领域>\<页>.md` | `../../../../` |
   | `raw\<项目名>\<页>.md` | `../../` |
   | `wiki\概念\<页>.md` | `../` |

   实测翻车案例（2026-09-14）：`raw\知识\通用\工具与流程\资产目录名中英与拼音翻译.md`
   把项目索引写成 `../../../wiki/项目/000_项目资料总览.md`，少一层 `../`，实际指向
   不存在的 `raw\wiki\项目\...`。**写完必须用脚本把该页所有 Markdown 链接目标解析成绝对路径
   再 `Test-Path` 一次**，不要靠肉眼扫。

推荐的 PowerShell 校验命令：

```powershell
$kb = 'D:\知识库\和平精英绿洲起源'
rg -n "官方依据|证据状态|待查证|来源|关联主题" "$kb\raw\知识\通用\知识库治理" "$kb\raw\知识\通用\UI与交互"
rg -n "CollectibleCodexUI|Codex_TopBar|PIE|非法字符" "$kb\wiki\000_索引.md" "$kb\raw\知识\通用" "$kb\raw\IslandAuctionKing"
```

## 五、按需读取索引的闭环

### 5.1 从问题提取检索实体

先把用户问题拆成最多四类实体，再开始读取：

| 实体类型 | 示例 | 用途 |
| :--- | :--- | :--- |
| 功能主题 | 图鉴 UI、RPC、配置表、PIE | 选择领域目录 |
| 精确符号 | `UGCGameSystem.GetUGCResourcesFullPath`、`HasAuthority` | 定位 API 或代码证据 |
| 资产/路径 | `CollectibleCodexUI.CollectibleCodexUI`、`Asset/TuPian/TuJian` | 定位项目蓝图和资产记录 |
| 症状/错误 | 文字重叠、按钮样式、`cversions.2.db` | 定位排障页、日志和解决方案 |

同义词只作为第二轮扩展：例如“图鉴/藏品/Collectible/Codex”。不能一开始用“UI”“错误”“脚本”等过宽词扫描整个知识库。

### 5.2 四级读取范围

| 级别 | 首选路径 | 读取内容 | 触发条件 |
| :--- | :--- | :--- | :--- |
| L0 导航 | `wiki/000_索引.md`、目标领域 `000_目录.md` | 主题、Raw 正文位置、项目入口和来源入口 | 每次查询必读 |
| L1 主文档 | 与实体精确命中的一个或多个 Raw 正文 | 直接回答问题所需的结论、步骤、参数 | 每次查询必读 |
| L2 直接依赖 | 主文档的“关联主题”、正文引用的 API/资产/日志页 | 补足前置条件、生命周期、端侧、资源或验证方法 | 只有主文档显式依赖或问题涉及该依赖时读取 |
| L3 证据复核 | `raw/docs/api`、`raw/docs/wiki`、项目回读/日志原文 | 核验 API、冲突、关键修改和未解决项 | 需要官方查证、存在冲突或准备写入/改文件时读取 |

默认只读 L0 → L1；L2 和 L3 是条件扩展，不是每次都全量读取。项目问题先进入 `raw/<项目名>/000_项目索引.md`，再读取项目子目录，不扫描其他项目。

### 5.3 命中与扩展规则

按以下顺序筛选候选页：

1. **精确命中优先**：完整 API、资产路径、蓝图名、错误文本、函数名优先于泛主题词。
2. **直接关联优先**：主文档正文链接、`关联主题`、同一项目索引中的直接条目优先。
3. **证据适用范围优先**：当前项目的项目实测优先补充当前项目；跨项目通用问题优先读通用 Raw；官方 API 仍需回到官方 Raw 复核。
4. **状态过滤**：`废弃`只用于解释历史行为；`推断`和`待查证`不能单独支撑确定性结论；`冲突`必须进入 L3 复核。
5. **排除弱相关命中**：只共享“UI”“Lua”“错误”等泛词、且没有主题或依赖关系的页面，不纳入当前读取集合。

可用一个简单评分辅助排序，但评分不能替代人工判断：

| 条件 | 分值 |
| :--- | :---: |
| 命中完整实体（API/资产/错误/函数名） | +5 |
| 命中主题且路径属于对应领域目录 | +3 |
| 被主文档直接链接或列入 `关联主题` | +3 |
| 与当前项目完全一致 | +2 |
| 有官方或可复核项目证据 | +1 |
| 只命中泛词且无直接关联 | -4 |

初始集合建议为 1 个主文档、必要的直接依赖和最多 3 个证据页，而不是固定截断所有结果。出现以下任一条件必须继续扩展，直到条件闭合：

- 主文档引用了尚未读取的 API、组件、事件、资源或错误码；
- 问题涉及初始化、生命周期、端侧、RPC、蓝图写入或配置表生效；
- 主文档存在 `待查证`、`推断` 或 `冲突`；
- 当前页面只描述通用规则，但用户需要项目具体路径、数值、截图或日志；
- 一个结论的前置条件来自另一个主题，且缺少该前置条件会改变操作结果。

满足以下条件时停止扩展：问题所需结论已由适用范围正确的证据覆盖；直接依赖已读取；没有未处理冲突或待查证项；继续命中的页面只包含弱相关泛词。

### 5.4 推荐检索命令

先查索引和目录，再查候选 Raw；不要默认对整个 `wiki` 与所有 `raw/docs` 做无边界全文读取：

```powershell
$kb = 'D:\知识库\和平精英绿洲起源'
$project = 'IslandAuctionKing'
$terms = 'CollectibleCodexUI|图鉴|Codex_TopBar|文字重叠'

# L0：总索引与通用领域目录
rg -n "$terms" "$kb\wiki\000_索引.md" "$kb\raw\知识\通用\UI与交互\000_目录.md" "$kb\raw\知识\通用\工具与流程\000_目录.md"

# L1/L2：只读命中的 Raw 领域与关联页
rg -n "$terms" "$kb\raw\知识\通用\UI与交互" "$kb\raw\知识\通用\工具与流程"

# 项目问题：只读取当前项目索引和子目录
rg -n "$terms" "$kb\raw\$project\000_项目索引.md" "$kb\raw\$project"

# L3：仅在 API/机制需要核验时，按精确符号查官方原始资料
rg -n "UGCGameSystem\.GetUGCResourcesFullPath|HasAuthority" "$kb\raw\docs\api" "$kb\raw\docs\wiki"
```

### 5.5 读取记录格式

需要审计或后续写回的任务，应在工作记录或回答中保留简短的检索轨迹：

```markdown
检索主文档：<Raw 正文路径>（命中：完整主题/实体）
补充依赖：<路径>（原因：API/生命周期/项目证据/错误码）
证据复核：<官方 Raw 或项目日志路径>（原因：冲突/写入前核验）
排除范围：<未读取的领域或项目>（原因：无直接关联）
知识库未覆盖：<仍缺失的事实>（下一步查证方式）
```

这个记录既用于证明“没有漏读必要依赖”，也用于证明“没有把无关资料当成依据”。

## 六、索引与链接规范

1. `wiki/000_索引.md` 只登记全局通用概念短索引、来源短索引和项目总览入口，不承载完整教程、代码、日志和大段证据。
2. `wiki/概念/` 与 `wiki/来源/` 页面只做导航：说明主题、适用范围、证据状态、Raw 正文位置和关联页面。
3. 详细正文统一位于 `raw/知识/通用/`、`raw/知识/项目` 或 `raw/<项目名>/`；`raw/docs/` 原始资料只读。
4. 新增页面必须形成至少一条双向关系：索引页 → Raw 正文，Raw 正文 → 索引页或相关页面。
5. 相关链接只写直接依赖或相邻工作流；若只是同一大类，不建立链接，避免关系图膨胀。
6. 目录页只列当前目录的正文和来源，不把全库文件复制到每个目录。

## 七、常见失误与修复

### 失误 1：为避免遗漏而整库全文读取

- **问题**：泛关键词命中大量无关 UI、Lua 或历史项目资料，增加冲突和误引用概率。
- **修复**：先 L0 索引定位主题，再按精确实体读取 L1；只在直接依赖、冲突或未覆盖时扩展 L2/L3。

### 失误 2：为控制上下文而固定只取前几条结果

- **问题**：可能漏掉主文档引用的 API、项目日志或冲突证据。
- **修复**：数量只用于初始集合排序，不用于最终截断；按“直接依赖、冲突、待查证、端侧/生命周期”条件闭合。

### 失误 3：把实测或推断写成官方结论

- **问题**：其他项目照做时会把项目偶然行为当成通用 API 保证。
- **修复**：强制写 `证据状态`、`适用范围`、`官方依据`；未确认内容单列“待查证”。

### 失误 4：同一主题新建多个近似页面

- **问题**：后续检索出现多个版本，无法判断哪一页是最新依据。
- **修复**：写回前先按精确实体和别名去重；同范围内容追加，范围不同才拆页，并建立互链。

### 失误 5：索引指向失效或错误层级

- **问题**：`wiki` 页面看似存在，实际正文已迁移或 Raw 路径错误。
- **修复**：写回后逐条验证链接与文件存在；索引只指向短索引或 Raw 正文，不保留旧的虚假正文链接。
