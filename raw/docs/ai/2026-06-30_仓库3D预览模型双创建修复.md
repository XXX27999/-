# 仓库3D预览模型双创建导致"一个可旋转一个不可旋转"问题修复

## 问题描述

打开仓库（Warehouse）时，3D预览模型被创建了两个实例：其中一个可以通过旋转按钮正常旋转，另一个则完全不可旋转。玩家在界面上会看到两个重叠的3D模型，操作旋转时只有其中一个跟随操作。

## 根因分析

### 两条独立的创建路径

代码中存在两条独立的3D预览模型创建路径，它们在打开仓库时都被执行，导致模型被创建两次：

#### 路径1：服务端 OnItemSelected 路径

在 [UGCPlayerController.lua](file:///d:\WeGameApps\rail_apps\OasisEraEditor(2001776)\ShadowTrackerExtra\UGCProjects\pet_paradise\Script\Blueprint\UGCPlayerController.lua#L1671-L1679) 的 `OnItemSelected` 函数中（步骤14），原本的代码如下：

```lua
-- 14. 管理3D展示预览模型（使用WarehouseData中的UI3D蓝图名）
local ui3dName = self.WarehouseData[Index].UI3D
ugcprint("【UGCPlayerController+OnItemSelected】UI3D=" .. tostring(ui3dName))
-- 先清理旧的3D展示模型（如果存在）
self:ServerRPC_DestroyPreviewModel()
-- 创建新的3D展示模型
self:ServerRPC_CreatePreviewModel(ui3dName)    -- <-- 冗余创建
-- 通知客户端更新UI3D Widget的RenderTarget
UnrealNetwork.CallUnrealRPC(self, self, "ClientUpdateUI3D", ui3dName)
```

这条路径在 **服务端** 的 `_G` 中创建了 **模型A**。

#### 路径2：客户端 ClientUpdateUI3D 路径

[ClientUpdateUI3D](file:///d:\WeGameApps\rail_apps\OasisEraEditor(2001776)\ShadowTrackerExtra\UGCProjects\pet_paradise\Script\Blueprint\UGCPlayerController.lua#L1938-L1961) 是服务端通过 `CallUnrealRPC` 调用的客户端RPC：

```lua
function UGCPlayerController:ClientUpdateUI3D(ui3dName)
    if self:HasAuthority() then
        return
    end
    -- ...
    local warehouseUI = UIUtils.LoadedUIWidgets["text1"]
    if warehouseUI and warehouseUI.UI3D and warehouseUI.UI3D.SetModelName then
        warehouseUI.UI3D:SetModelName(ui3dName)  -- <-- 创建模型B
    end
end
```

在 [UI3D.lua](file:///d:\WeGameApps\rail_apps\OasisEraEditor(2001776)\ShadowTrackerExtra\UGCProjects\pet_paradise\Script\Blueprint\Prefabs\UI\ChonWuFuHua\UI3D.lua#L54-L63) 的 `SetModelName` 函数中，直接调用 `ServerRPC_CreatePreviewModel` 在 **客户端** 的 `_G` 中创建了 **模型B**：

```lua
-- 创建3D展示模型（直接调用，在客户端本地执行）
local PlayerController = UGCGameSystem.GetLocalPlayerController()
if PlayerController then
    PlayerController:ServerRPC_CreatePreviewModel(modelName)
end
```

### 生产环境下的表现差异

在生产环境（双进程：独立的服务端 `_G` 和客户端 `_G`）中：

| 项目 | 模型A（服务端创建） | 模型B（客户端创建） |
|------|-------------------|-------------------|
| 创建者 | OnItemSelected 路径 | ClientUpdateUI3D 路径 |
| 存在于 | 服务端 _G | 客户端 _G |
| PreviewModelMap | 服务端 _G.PreviewModelMap 中 | 客户端 _G.PreviewModelMap 中 |
| 旋转时查找 | `ServerRPC_RotatePreviewModel` 查找的是当前进程 _G 中的模型 | 客户端旋转找到的是客户端 _G 中的模型 |
| 旋转结果 | 服务端 _G 的模型旋转了，但客户端看到的是通过复制同步的模型，旋转可能不同步或无效 | 客户端 _G 的模型可以正常旋转 |

核心问题在于 **`ServerRPC_RotatePreviewModel` 查找的是调用者所在进程的 `_G.PreviewModelMap`**：

```lua
-- ServerRPC_RotatePreviewModel (UGCPlayerController.lua 第816-831行)
local state = _G["_Pet3DDisplayManager"]
if not state then return end
local playerKey = UGCGameSystem.GetPlayerKeyByPlayerController(self)
local modelActor = state.PreviewModelMap[playerKey]
```

- 当客户端 UI3D 的 Tick 直接调用 `PlayerController:ServerRPC_RotatePreviewModel(stepAngle)` 时：
  - 该调用在客户端进程本地执行（不是通过网络RPC）
  - 查找的是**客户端 _G** 中的 `PreviewModelMap`
  - 只能找到 **模型B**，因为模型A存在服务端 _G 中
- **结果**：模型B可以旋转，模型A不能旋转，界面上显示两个模型，一个可转一个不可转

## 修复方案

删除 `OnItemSelected` 中冗余的 `ServerRPC_CreatePreviewModel` 调用，让模型只由 `ClientUpdateUI3D` --> `SetModelName` 路径创建。

### 修改后的代码

在 [UGCPlayerController.lua](file:///d:\WeGameApps\rail_apps\OasisEraEditor(2001776)\ShadowTrackerExtra\UGCProjects\pet_paradise\Script\Blueprint\UGCPlayerController.lua#L1671-L1679) 中，将步骤14修改为：

```lua
-- 14. 管理3D展示预览模型（使用WarehouseData中的UI3D蓝图名）
-- 注意：不在服务端创建模型，由ClientUpdateUI3D RPC在客户端统一创建
-- 避免服务端和客户端各创建一个模型导致"一个可旋转一个不可旋转"的问题
local ui3dName = self.WarehouseData[Index].UI3D
ugcprint("【UGCPlayerController+OnItemSelected】UI3D=" .. tostring(ui3dName))
-- 先销毁服务端旧的3D展示模型（如果存在）
self:ServerRPC_DestroyPreviewModel()
-- 通知客户端更新UI3D Widget的RenderTarget（客户端SetModelName内会创建新模型）
UnrealNetwork.CallUnrealRPC(self, self, "ClientUpdateUI3D", ui3dName)
```

### 修改要点

1. **移除** `self:ServerRPC_CreatePreviewModel(ui3dName)` 服务端创建调用
2. **保留** `self:ServerRPC_DestroyPreviewModel()` 用于清理服务端旧模型
3. **保留** `UnrealNetwork.CallUnrealRPC(self, self, "ClientUpdateUI3D", ui3dName)` 通知客户端

## 修复后的唯一创建路径

```
用户点击/打开仓库

      --> ServerRPC_DestroyPreviewModel()        ← 清理服务端旧模型

```

## UI3D 的 Construct 和 SetModelName

[UI3D.lua](file:///d:\WeGameApps\rail_apps\OasisEraEditor(2001776)\ShadowTrackerExtra\UGCProjects\pet_paradise\Script\Blueprint\Prefabs\UI\ChonWuFuHua\UI3D.lua#L11-L66) 是整个流程的关键入口：

- `Construct` 时：加载默认RT纹理到 Image_90，初始化旋转状态变量
- `SetModelName(modelName)` 时：加载对应宠物的 RT 纹理 --> 通过 MID 设置到 Image_90 --> 调用 `ServerRPC_CreatePreviewModel` 在本地创建3D模型
- `Tick` 时：检测旋转按钮按住状态，限频调用 `ServerRPC_RotatePreviewModel` 直接旋转

## 关键要点

1. **`_G` 隔离是问题的根源**：PIE单进程下服务端和客户端共享 `_G`，所以这个问题在PIE中不会复现；生产环境双进程各自独立的 `_G` 导致模型A（服务端）和模型B（客户端）互相不可见。

2. **旋转函数依赖本地 `_G`**：`ServerRPC_RotatePreviewModel` 直接通过 `_G["_Pet3DDisplayManager"]` 查找模型，不通过 require 或 RPC，因此只能在模型所在的进程正确工作。

3. **统一创建路径**：将所有模型的创建统一到客户端 `_G` 中（通过 `ClientUpdateUI3D` --> `SetModelName`），确保旋转函数能在客户端 `_G` 中找到正确的模型。

4. **销毁时的双端清理**：在 `text1:Destruct` 和 `text1:Close_OnClicked` 中，分别清理客户端和服务端的模型，确保资源正确释放。
