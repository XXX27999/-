# 人机名字随机与拟人出价道具

## 1. 需求

1. 人机角色、道具组随机
2. 道具使用逻辑与玩家一致：随机判定是否使用；使用时从道具组里随机取一件；整场拍卖不能重复使用同一件道具
3. 人机名字随机
4. 出价符合真人习惯，尾数尽量为 0（如 10000、15000、600、5555、1540000），少数可用 666、888 这类重复数字

## 2. 落地改动

### 2.1 脚本（`Script/Function/AuctionBotService.lua`）

新增模块级纯函数（无副作用，便于 lupa 单测）：

- `ParseStringList(text)`：解析逗号分隔文本，去首尾空白
- `GetBidStepForMagnitude(magnitude)`：按报价位数取整步长，>=7 位 10000、6 位 1000、5 位 100、4 位 100、其余 10
- `HumanizeBid(value, minimumBid, ceiling, player)`：先把报价收成真人习惯整数；以 `Bot.LuckyBidChance` 概率尝试重复数字（仅在重复位为 5/6/8 且相对偏离 ≤ `Bot.LuckyBidMaxDeviation` 且落在 `[minimumBid, ceiling]` 时采用），否则按量级取整并把结果夹回区间
- `BuildBotDisplayName(owner, seat, rng)`：从 `Bot.NamePool` 里排除当前对局已占用的显示名后随机取一个；池子用尽回退 `Bot.DisplayNamePrefix..席位号`

改造点：

- `SpawnOne`：用 `BuildBotDisplayName` 生成显示名，复用与出价同源的线性同余随机序列（`nameSeed = seedBase + seat * 97`），不再固定 `人机N`
- `ChooseLoadout`：角色与道具组由「按席位轮换」改为随机抽取（`NextUnit(player)`）
- `TryUseProp`：先按 `Bot.PropUseChance` 随机判定是否使用；命中后只在**未被 `IsPropUsed` 标记**的道具里随机抽一件，再走与真人完全相同的 `PropUseService.Execute` → `MarkPropUsed` → `AuctionPropRoundUsageService.MarkUsed` → 历史记录链路
- `DecideBid`：新增 `rawDesired` 中间值，最终报价经 `HumanizeBid` 收敛

### 2.2 结算/UI 显示名

- `AuctionGameService.ResolveSettlementPlayerIdentity`：显示名优先取 `player.DisplayName`（人机随机名），再回退 `player.Name`
- `AuctionTestUIService`：参赛席位副标题不再对 `IsBot` 显示「人机席位」，与真人统一为「竞拍席位 N」，避免在人名前暴露人机身份

## 3. 验证

### 3.1 静态与单测

- luaparser：`AuctionBotService` / `AuctionGameService` / `AuctionTestUIService` / `AuctionPlayerService` / `AuctionConfig` 全部通过
- lupa 直接加载工程内 `HumanizeBid` 实测：`700→666`、`600→555`、`900→888`（幸运分支）；`10000→10000`、`15400→15400`、`600→600`、`1540000→1540000`（取整分支）；`ceiling<minimum` 原样返回；低于下限抬到下限；高于上限夹到上限；超上限的幸运数字被拒绝
- lupa 直接加载工程内 `BuildBotDisplayName` 实测：5 人名字池下前 5 个席位 5/5 不重复，第 6/7 席位回退「人机6 / 人机7」
