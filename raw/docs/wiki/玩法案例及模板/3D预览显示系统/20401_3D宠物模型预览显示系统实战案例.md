# 3D宠物模型预览显示系统实战案例

## 概述

在 UGC 玩法中，需要在 2D UI 上显示 3D 宠物模型的旋转预览效果。核心方案是通过场景捕获（SceneCapture2D）将 3D 模型渲染到 RenderTarget，再将 RenderTarget 通过 MID（材质实例动态）显示在 UImage 上。

本文记录了从零构建该系统的完整技术历程，包含架构设计、所有踩过的坑及最终解决方案。

## 系统架构

## 关键技术点

### 1. Server RPC 机制

UGC 中客户端调用服务端函数的机制：

```lua
-- 1. 在 UGCPlayerController 中定义函数（必须以 ServerRPC_ 开头）
function UGCPlayerController:ServerRPC_CreatePreviewModel()
    -- 服务端执行逻辑
end

-- 2. 注册到 GetAvailableServerRPCs()
function UGCPlayerController:GetAvailableServerRPCs()
    return "...", "ServerRPC_CreatePreviewModel", "ServerRPC_DestroyPreviewModel", "ServerRPC_RotatePreviewModel"
end

-- 3. 客户端直接调用（引擎自动路由到服务端）
local PlayerController = UGCGameSystem.GetLocalPlayerController()
PlayerController:ServerRPC_CreatePreviewModel()
```

**注意事项**：
- RPC 函数名必须包含在 GetAvailableServerRPCs() 返回值中，否则引擎找不到
- RPC 函数不需要加 `if self:HasAuthority()` 守卫——引擎只在服务端执行
- 新增 RPC 后必须重启 PIE（热更新不会注册新 RPC）

### 2. 通过 RenderTarget 显示 3D 模型到 2D UI

```
NewBlueprint_C (Actor)
  └─ SceneCapture2D (摄像机)
       └─ TextureTarget → NewTextureRenderTarget2D (RenderTarget资产)
                              ↑
                          MID (材质实例动态)
                              ↑
                         UImage.Image_90 (UI上显示)
```

关键代码（OpenShop.lua 的 LuaInit）：

```lua
-- 加载 RenderTarget 纹理
local RT = UGCObjectUtility.LoadObject(RTPath)

-- 加载父材质，创建动态材质实例
local parentMaterial = UGCObjectUtility.LoadObject(ParentMaterialPath)
local MID = KismetMaterialLibrary.CreateDynamicMaterialInstance(self, parentMaterial)

-- 将 RenderTarget 设给材质的 MainTexture 参数
MID:SetTextureParameterValue("MainTexture", RT)

-- 将材质设给 UImage
self.Image_90:SetBrushFromMaterial(MID)
self.Image_90:SetColorAndOpacity({ R = 1.0, G = 1.0, B = 1.0, A = 1.0 })
```

**问题：不使用 MID 直接设置 RenderTarget 会导致 Alpha 半透明。MID 可以正确处理不透明度。**

### 3. 持续旋转控制（按住按钮不松开）

使用按钮 OnPressed/OnReleased 设置标志位，结合 Tick 限频发送 RPC：

```lua
-- 按钮按下
function ChonWuFuHua:Button_245_OnPressed()
    self.bRotatingRight = true  -- 设置标志
end

-- 按钮松开
function ChonWuFuHua:Button_245_OnReleased()
    self.bRotatingRight = false  -- 清除标志
end

-- Tick 中检测标志并限频
function ChonWuFuHua:Tick(MyGeometry, InDeltaTime)
    if not self.bRotatingRight and not self.bRotatingLeft then
        return  -- 没有按钮按住，跳过
    end

    self.RotateAccumulator = self.RotateAccumulator + InDeltaTime
    if self.RotateAccumulator >= self.RotateInterval then  -- 0.1秒
        local stepAngle = self.bRotatingRight and self.RotateStepAngle or -self.RotateStepAngle
        local PC = UGCGameSystem.GetLocalPlayerController()
        PC:ServerRPC_RotatePreviewModel(stepAngle)
        self.RotateAccumulator = self.RotateAccumulator - self.RotateInterval
    end
end
```

### 4. _G 全局表绕过 require 缓存

UGC 中 require 的模块会被缓存，热更新时修改 .lua 文件不会影响已 require 的旧模块。使用 _G 全局表作为运行时状态共享：

```lua
-- 定义全局键名
local GLOBAL_KEY = "_Pet3DDisplayManager"

-- 获取/初始化全局状态
local function GetGlobalState()
    if not _G[GLOBAL_KEY] then
        _G[GLOBAL_KEY] = {
            PreviewModelMap = {},
        }
    end
    return _G[GLOBAL_KEY]
end

-- 在其他文件中访问
local state = _G["_Pet3DDisplayManager"]
local modelActor = state.PreviewModelMap[playerKey]
```

## 踩坑记录

### 坑1：Pet3DDisplayManager 为 nil

**症状**：`尝试索引一个空值(global'Pet3DDisplayManager')`

**根因**：模块文件中缺少 local Pet3DDisplayManager = {} 声明

**修复**：
```lua
local Pet3DDisplayManager = {}
function Pet3DDisplayManager.SpawnPreviewModel(...) ... end
-- ... 其他函数
return Pet3DDisplayManager
```

---

### 坑2：Server RPC 未注册

**症状**：日志 `【ServerRPC_CreatePreviewModel】错误: 非服务端，跳过执行`

**根因**：新添加的 RPC 函数名不在 GetAvailableServerRPCs() 的返回列表中

**修复**：将所有新 RPC 函数名加入列表并重启 PIE

---

### 坑3：IsServer() 守卫导致 RPC 不执行（单进程PIE）

**症状**：单进程 PIE 模式下 RPC 内 `IsServer()` 返回 false，逻辑被跳过

**根因**：单进程模式下客户端和服务端运行在同一进程，`IsServer()` 反而返回 false

**修复**：RPC 函数中移除 IsServer() 守卫，引擎会自动路由

---

### 坑4：Destroy 不成功

**症状**：`Actor:Destroy()` 返回 false

**根因**：Actor 的 `Destroy()` 函数在 UGC Lua 绑定中可能失效

**修复**：改用 `UGCActorComponentUtility.DestroyActor(modelActor)`

---

### 坑5：PIE 多窗口模式位置冲突检测失效

**症状**：Player1 创建模型在 X=-36750，Player2 也创建在 X=-36750（未偏移）

**根因**：PIE 多窗口模式下每个玩家独立进程 + 独立 World 副本，扫描 "世界中所有 Actor" 只能看到自己的

**结论**：生产环境单服务端进程不会出现此问题，无需特殊修复

---

### 坑6：math.floor 取整做 key 导致错位

**症状**：`-36750/1000 = -36.75`，math.floor 得到 `-37`，但其他值取整后不匹配

**修复**：直接用原始 X 值的字符串做 key：`occupiedXSet[tostring(location.X)] = true`

---

### 坑7：持续旋转定时器不工作

**症状**：
```
StartRotate 创建定时器
→ 101ms 后 StopRotate
→ "没有运行中的定时器"
```

**根因**：`K2_SetTimer(self, "OnRotateTimerTick", ...)` 传入的 `"OnRotateTimerTick"` 是字符串函数名，C++ 侧找不到 Lua 方法

**修复**：放弃定时器方案，改用 UI Tick + 标志位 + 限频发送 RPC

---

### 坑8：Rotator 字段名错误

**症状**：使用 `{R=0, P=0, Y=yawDelta}` 引擎不识别，旋转不生效

**根因**：UGC Lua 中 Rotator 的正确字段名是 **`Pitch/Yaw/Roll`**，不是 `R/P/Y` 也不是 `X/Y/Z`

**修复**：
```lua
-- ❌ 错误
{ R = 0, P = 0, Y = 15.0 }
-- ❌ 错误（Actor API 读出的是 Pitch/Yaw/Roll，不是 X/Y/Z）
{ X = 0, Y = 15.0, Z = 0 }

-- ✅ 正确
{ Pitch = 0, Yaw = 15.0, Roll = 0 }
```

**验证日志**：
```
curRot=ud_struct[Rotator @...] X=nil Y=nil Z=nil Pitch=0.0 Yaw=0.0 Roll=0.0
```
K2_GetActorRotation() 返回的 Rotator 只有 `Pitch/Yaw/Roll` 有值，`X/Y/Z` 均为 nil。

---

### 坑9：require 缓存问题

**症状**：修改 Pet3DDisplayManager.lua 文件后，新代码不执行（从日志看到旧代码逻辑）

**根因**：UGC 中 require 的模块在编译时缓存，热更新只会更新主文件（如 UGCPlayerController.lua）不会更新被 require 的模块缓存

**修复策略**：
1. **`_G` 全局表**：将运行时状态存到 `_G["_Pet3DDisplayManager"]`，不依赖 require 读取配置
2. **内联关键逻辑**：旋转等核心逻辑直接写到 UGCPlayerController 的 RPC 函数中，通过 `_G` 获取模型引用

```lua
-- UGCPlayerController 中直接访问 _G，绕过 require
function UGCPlayerController:ServerRPC_RotatePreviewModel(yawDelta)
    local state = _G["_Pet3DDisplayManager"]
    local modelActor = state.PreviewModelMap[playerKey]
    -- 直接旋转...
end
```

---

### 坑10：GetComponentRotation() 不是 UGC 可用 API

**症状**：`skeletalMesh:GetComponentRotation()` 在 pcall 中返回 false/nil

**根因**：不带 `K2_` 前缀的 GetComponentRotation 不是 UGC Lua 绑定的 API

**修复**：
```lua
-- ❌ 不存在
skeletalMesh:GetComponentRotation()
-- ✅ 存在
skeletalMesh:K2_GetComponentRotation()
```

---

### 坑11：RelativeRotation 属性赋值不触发引擎更新

**症状**：日志输出 `原Yaw=15.0 -> 新Yaw=15.0`，每次读都是 15.0，写不进

**根因**：Lua 属性赋值 `skeletalMesh.RelativeRotation = {...}` 不会触发 UE 引擎的旋转更新（属性值被丢弃）

**修复**：使用函数调用来旋转，不能靠直接属性赋值

---

### 坑12：旋转整个 Actor 导致 SceneCapture 同步转

**症状**：`K2_GetActorRotation() + K2_SetActorRotation()` Yaw 累加正确（15→30→45），但 2D UI 中看不到宠物旋转

**根因**：旋转了整个 Actor，SceneCapture2D 是 Actor 的子组件，和 SkeletalMesh 一起转，摄像机看到的画面不变

**修复**：**只旋转 SkeletalMesh 组件，不碰 Actor 根节点和 SceneCapture2D**

```lua
-- ❌ 错误：旋转整个 Actor（SceneCapture跟着转）
modelActor:K2_SetActorRotation({ Pitch = 0, Yaw = newYaw, Roll = 0 }, true)

-- ✅ 正确：只旋转 SkeletalMesh 组件（SceneCapture固定不动）
skeletalMesh:K2_AddWorldRotation({ Pitch = 0, Yaw = yawDelta, Roll = 0 }, false, nil, true)
```

---

### 坑13：K2_AddWorldRotation 的 FHitResult& 参数

**症状**：`skeletalMesh:K2_AddWorldRotation(deltaRotation, false, nil, true)` 传 nil 给 FHitResult& 可能导致调用失败

**根因**：`K2_AddWorldRotation` 的第 4 个参数是 `FHitResult&`（输出引用），在 UGC Lua 绑定中传 nil 通常安全，但偶尔会出问题

**当前状态**：这是系统最后一个未完全验证的问题，备选方案见下文。

---

### 坑14：子Widget嵌入模式导致SceneCapture渲染管线不更新

**症状**：ChonWuFuHua 作为独立 Widget（通过 UIUtils:LoadUI 加载）时旋转功能工作正常，但嵌入到父Widget（蓝图中的子Widget面板）后，SceneCapture2D→RT→MID→UImage 渲染管线不更新，UI上看不到旋转效果

**根因**：子Widget的渲染上下文受父Widget生命周期影响，SceneCapture2D 依赖的每帧渲染更新在子Widget中不触发，导致RT画面停滞在初始帧

**修复**：将ChonWuFuHua作为独立UI打开（不是嵌入子Widget），两个UI通过 UIUtils:LoadUI 切换：
```lua
-- 父UI销毁自身，然后独立打开子UI
function OnTimerComplete()
    -- 先清理缓存
    UIUtils.LoadedUIWidgets["ParentUI"] = nil
    -- 独立打开3D预览UI
    local chonWuFuHuaUI = UIUtils:LoadUI(PlayerController, "ChonWuFuHua", "ChonWuFuHua", 1000)
    chonWuFuHuaUI:SetModelName(modelName)
    -- 最后销毁自身
    UGCWidgetManagerSystem.HideWidget(self)
    UGCWidgetManagerSystem.DestroyWidget(self)
end
```

---

### 坑15：DestroyWidget(self) 后代码不执行

**症状**：OnTimerComplete 中调用 DestroyWidget(self) 后，后续的 LoadUI("ChonWuFuHua") 代码从未执行（日志缺失）

**根因**：`UGCWidgetManagerSystem.DestroyWidget(self)` 会立即销毁当前 Widget 的 Lua 执行上下文，函数剩余的 Lua 指令被截断

**修复**：始终在 DestroyWidget 之前完成所有关键操作（打开新UI、清理缓存等）：
```lua
-- ❌ 错误：DestroyWidget 在前，后续代码永不执行
UGCWidgetManagerSystem.DestroyWidget(self)
UIUtils:LoadUI(...)   -- 永远不会执行

-- ✅ 正确：所有操作在 DestroyWidget 之前完成
UIUtils.LoadedUIWidgets["ParentUI"] = nil
local newUI = UIUtils:LoadUI(...)
UGCWidgetManagerSystem.DestroyWidget(self)
```

---

### 坑16：PIE 模式下服务端与客户端的 _G 表隔离

**症状**：日志输出：
```
【UGCPlayerController+ServerRPC_RotatePreviewModel】HasAuthority=false
【UGCPlayerController+ServerRPC_RotatePreviewModel】错误: 全局状态不存在
```
服务端通过 ServerRPC_CreatePreviewModel 创建了模型并存入了 `_G["_Pet3DDisplayManager"]`，但客户端调用 ServerRPC_RotatePreviewModel 时读不到

**根因**：PIE（Play In Editor）模式下，服务端进程和客户端进程各自有独立的 Lua 环境，`_G` 全局表**不共享**。服务端 `_G` 中的模型引用在客户端 `_G` 中为 nil

**尝试过的无效方案**：
- 通过 ClientRPC 将模型 Actor 引用发回客户端：Actor 引用无法通过 RPC 参数传输（`modelActor=nil`）

**修复**：不通过 CallUnrealRPC 路由到服务端，改为**客户端直接调用**：
- ServerRPC 函数移除 `if not self:HasAuthority()` 守卫
- 所有创建/销毁/旋转调用改为 `PlayerController:ServerRPC_xxx()` 直接调用
- 直接调用在客户端本地执行，模型 Actor 创建在客户端 _G 中
```lua
-- ❌ 错误：CallUnrealRPC 路由到服务端 → 模型在服务端 _G，客户端 _G 无引用
UnrealNetwork.CallUnrealRPC(PC, PC, "ServerRPC_CreatePreviewModel", modelName)

-- ✅ 正确：直接调用 → 模型在客户端本地 _G
PC:ServerRPC_CreatePreviewModel(modelName)
```

---

### 坑17：SkeletalMesh 组件变换不通过网络复制

**症状**：Tick 通过 CallUnrealRPC 把 ServerRPC_RotatePreviewModel 路由到服务端执行，服务端日志显示 `Mesh旋转成功: Delta=15.0`，但客户端画面无变化

**根因**：SkeletalMesh 组件的局部变换（RelativeRotation/RelativeLocation）是**非复制属性**，不通过网络同步。即使服务端成功调用了 `skeletalMesh:K2_AddWorldRotation()`，客户端不会收到该变换更新

**修复**：
1. 不在服务端旋转 SkeletalMesh，改为**客户端本地直接调用**旋转
2. ServerRPC_RotatePreviewModel 移除 HasAuthority 守卫，允许客户端本地执行
3. 通过 `_G` 访问客户端的模型引用

```lua
-- ❌ 错误：路由到服务端旋转，SkeletalMesh变换不复制到客户端
UnrealNetwork.CallUnrealRPC(PC, PC, "ServerRPC_RotatePreviewModel", 15.0)

-- ✅ 正确：客户端直接调用旋转，本地立即生效
PC:ServerRPC_RotatePreviewModel(15.0)
```

---

### 坑18：UIUtils.LoadedUIWidgets 缓存残留导致第二次打开UI失败

**症状**：第一次购买→打开抽取UI→销毁→第二次购买→LoadUI 返回了已销毁的旧Widget引用，UI操作无响应

**根因**：UIUtils.LoadedUIWidgets[UIName] 在 DestroyWidget 后未清理。LoadUI 发现缓存存在时直接返回旧引用（已销毁），不会创建新Widget

**修复**：在 DestroyWidget 之前手动清理 UIUtils 缓存：
```lua
UIUtils.LoadedUIWidgets["ChongWuChouQu"] = nil  -- 清除缓存
UGCWidgetManagerSystem.DestroyWidget(self)
```

## 最终代码（已验证部分）

### ServerRPC（UGCPlayerController.lua）—— 直接调用模式

> **设计说明**：SkeletalMesh 组件变换不通过网络复制（坑17），PIE 中 _G 表隔离（坑16），因此创建/销毁/旋转一律采用**客户端本地直接调用**。
> ServerRPC 函数名保留以便引擎识别 RPC 协议，但**移除 `HasAuthority` 守卫**使其能在客户端本地执行。

```lua
-- 【创建模型】客户端本地执行（不路由到服务端）
function UGCPlayerController:ServerRPC_CreatePreviewModel(modelName)
    -- 不检查 HasAuthority，允许客户端本地执行
    local ownerPawn = UGCGameSystem.GetPlayerPawnByPlayerController(self)
    local Pet3DDisplayManager = require("Script.Pet3D.Pet3DDisplayManager")
    local modelActor = Pet3DDisplayManager.SpawnPreviewModel(self, ownerPawn, modelName)
end

-- 【销毁模型】客户端本地执行
function UGCPlayerController:ServerRPC_DestroyPreviewModel()
    -- 不检查 HasAuthority
    local Pet3DDisplayManager = require("Script.Pet3D.Pet3DDisplayManager")
    Pet3DDisplayManager.DestroyPreviewModel(self)
end

-- 【旋转模型】客户端本地执行
-- 只旋转 SkeletalMesh 组件，SceneCapture2D 不动
function UGCPlayerController:ServerRPC_RotatePreviewModel(yawDelta)
    local state = _G["_Pet3DDisplayManager"]
    if not state then return end

    local playerKey = UGCGameSystem.GetPlayerKeyByPlayerController(self)
    local modelActor = state.PreviewModelMap[playerKey]
    if not modelActor then return end

    local skeletalMesh = modelActor.SkeletalMesh
    if not skeletalMesh then return end

    local deltaRotation = { Pitch = 0, Yaw = yawDelta, Roll = 0 }
    skeletalMesh:K2_AddWorldRotation(deltaRotation, false, nil, true)
end

-- RPC 注册：函数名仍需要包含在列表中
function UGCPlayerController:GetAvailableServerRPCs()
    return "...",
        "ServerRPC_CreatePreviewModel",
        "ServerRPC_DestroyPreviewModel",
        "ServerRPC_RotatePreviewModel"
end
```

### UI 侧调用（ChonWuFuHua.lua）—— 直接调用，不用 CallUnrealRPC

```lua
-- 创建：直接调用（不是 CallUnrealRPC）
function ChonWuFuHua:SetModelName(modelName)
    -- ... 加载RT到Image_90 ...
    local PC = UGCGameSystem.GetLocalPlayerController()
    PC:ServerRPC_CreatePreviewModel(modelName)  -- 直接调用
end

-- 持续旋转：Tick中直接调用
function ChonWuFuHua:Tick(MyGeometry, InDeltaTime)
    if not self.bRotatingRight and not self.bRotatingLeft then return end
    self.RotateAccumulator = self.RotateAccumulator + InDeltaTime
    if self.RotateAccumulator >= self.RotateInterval then
        local stepAngle = self.bRotatingRight and self.RotateStepAngle or -self.RotateStepAngle
        local PC = UGCGameSystem.GetLocalPlayerController()
        PC:ServerRPC_RotatePreviewModel(stepAngle)  -- 直接调用
        self.RotateAccumulator = self.RotateAccumulator - self.RotateInterval
    end
end

-- 销毁：直接调用
function ChonWuFuHua:Destruct()
    local PC = UGCGameSystem.GetLocalPlayerController()
    PC:ServerRPC_DestroyPreviewModel()  -- 直接调用
end
```

### 创建并设置 Actor（Pet3DDisplayManager.lua）

```lua
-- 生成 Actor
local modelActor = UGCActorComponentUtility.SpawnActor(
    playerController, modelClass,
    spawnLocation, spawnRotation, spawnScale

-- 设置 Owner

```

## 调试技巧

1. **日志过滤**：在 UE 输出日志中搜索 `【脚本名+函数名】` 格式快速定位，如 `【Pet3DDisplayManager+SpawnPreviewModel】`

2. **pcall 保护**：所有可能失败的关键调用都用 pcall 包裹，catch 中打印完整错误信息
   ```lua
   local ok, err = pcall(function()
       skeletalMesh:K2_AddWorldRotation(deltaRotation, false, nil, true)
   end)
   if not ok then
       ugcprint("【xxx】旋转失败: " .. tostring(err))
   end
   ```

3. **Rotator 字段探测**：不确定字段名时打印全部字段
   ```lua
   ugcprint("X=" .. tostring(curRot.X) .. " Y=" .. tostring(curRot.Y) .. " Z=" .. tostring(curRot.Z) ..
       " Pitch=" .. tostring(curRot.Pitch) .. " Yaw=" .. tostring(curRot.Yaw) .. " Roll=" .. tostring(curRot.Roll))
   ```

4. **require 缓存检验**：怀疑缓存问题时，用 `_G` 替代 require 读取运行时状态
