## 2. 根因：配置表行名的**点号路径前缀冲突**

`DressConfigTable` 里同时存在两行：

| 行名 | 值 |
|---|---|
| `Dress.SameName.ControlNames` | `""`（当日重构时加的**全局兜底行**） |
| `Dress.SameName.ControlNames.Hub` | `参考图,每日任务上方UI,帮助上方UI,保底金上方UI,服务器剩余时间,玩家名称,头像框,帮助,每日任务,金币,金币UI,顶部UI,保底金,Image_160` |

机制：`AuctionConfig` 把行名按 `.` 拆段写进嵌套表（`SetNestedConfigValue`），读取时 `AuctionConfig.Get`
同样按段下钻。前缀行把 `ControlNames` 这个节点写成**标量空串**，于是子树行 `…ControlNames.Hub`
所在的整棵子树被覆盖；`Get("Dress.SameName.ControlNames.Hub")` 下钻到 `Hub` 时
`current` 是字符串 → 「中间节点不是table」→ 清单读成 0 个控件 → 同名映射为空 → 一个画刷都不换。

**为什么难查**：`LoadOneDressTable` 用 `pairs` 遍历行，顺序不定。
前缀行在子树行**之后**被写入才覆盖，在**之前**则被子树行反过来覆盖成 table ——
表现随启动顺序时好时坏，且不报错、只「功能不生效」。

`SetNestedConfigValue` 原实现里 `if type(current[key]) ~= "table" then current[key] = {} end`
会把已存在的标量**静默替换**成空表，进一步掩盖了冲突。

## 5. 规律与工具

**配置表行名是点号嵌套路径，同一路径不能既是叶子又是中间节点。**
凡新增 `<前缀>.<子键>` 形式的新行，先确认不存在同名 `<前缀>` 行。

工具：`备份\IslandAuctionKing\20260920_DressSwitch\check_config_prefix_conflict.py`
吃 `dt.data_table_as_json()` 导出的 JSON，输出所有「前缀行 → 被遮蔽子树行」对；
无冲突退出码 0，有冲突退出码 1。导出方式：

```python
import unreal_engine as ue
from unreal_engine.classes import DataTable
dt = ue.load_object(DataTable, '/IslandAuctionKing/Asset/Data/Table/Customized/Dress/DressConfigTable.DressConfigTable')
open('<out>.json', 'w', encoding='utf-8').write(dt.data_table_as_json())
```
