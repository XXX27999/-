## 二、拖拽导入受阻：官方口径

`277_资源导入.md`「注意事项」原文（官方确认）：**若拖动资源导入到编辑器内出现禁止的图标，则需要调整系统权限**，分两步：

1. 控制面板内用户账户，**更改为「从不通知」**；
2. `cmd` 运行 `gpedit.msc`，**禁用图中标识的两项**。

官方页面只给截图、未给策略项名称。本次据本机策略项实测把两张图对应的注册表项名补齐（推断，非官方文字）：

| Wiki 步骤 | 策略项（gpedit 中文名） | 注册表项 | 「从不通知」目标值 |
| --- | --- | --- | --- |
| 步骤 1 用户账户 | 用户账户控制：提示提升时切换到安全桌面 | `PromptOnSecureDesktop` | 0 |
| 步骤 1 用户账户 | 用户账户控制：管理员批准模式中管理员的提升提示行为 | `ConsentPromptBehaviorAdmin` | 0（从不通知） |
| 步骤 2 两项之一 | 用户账户控制：以管理员批准模式运行所有管理员 | `EnableLUA` | 0 |
| 步骤 2 两项之一 | 用户账户控制：检测应用程序安装并提示提升 | `EnableInstallerDetection` | 0 |

位置：`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System`。

> 该对应关系为**依据策略项语义与默认值的推断**，官方 Wiki 未给文字说明；且关闭 UAC 属安全降级，是否执行须需求方决定。

## 三、本机实测（2026-09-14）

### 3.1 策略现状（均未处于 Wiki 要求的状态）

| 项 | 实测值 | Wiki 要求 | 判定 |
| --- | --- | --- | --- |
| `EnableLUA` | 1 | 0 | ✗ 未满足 |
| `ConsentPromptBehaviorAdmin` | 5（仅对非 Windows 二进制提示） | 0（从不通知） | ✗ 未满足 |
| `PromptOnSecureDesktop` | 1 | 0 | ✗ 未满足 |
| `EnableInstallerDetection` | 1 | 0 | ✗ 未满足 |
| `FilterAdministratorToken` | 1 | — | 管理员令牌被过滤（UAC 生效） |

### 3.2 进程完整性级别判定（关键证据）

判定方法：以中完整性级别（Medium IL）调用者身份查 `Win32_Process.ExecutablePath`，同用户同 IL 可读、更高 IL 读不到（返回空）。前提已排除「跨用户」解释：`whoami /user` = `bf-202603162046\administrator`，与交互桌面用户同一账号。

| 进程 | `ExecutablePath` | 推断 |
| --- | --- | --- |
| `explorer.exe`(10068) | 可读 | Medium IL（未提权） |
| `taskhostw.exe` / `conhost.exe` / `StartMenuExperienceHost.exe` | 可读 | Medium IL |
| `dwm.exe` / `csrss.exe` / `winlogon.exe` / `lsass.exe` / `WmiPrvSE.exe` | 空 | System/High IL |
| **`wegame.exe`(23468)** | **空** | **已提权** |
| **`ShadowTrackerExtraUGCEditor.exe`(12048 / 22064)** | **空** | **已提权（High IL）** |

进程链：`explorer.exe(10068)` → `wegame.exe(23468)` → `ShadowTrackerExtraUGCEditor.exe(12048)` → `...UGCEditor.exe(22064)`。

### 3.3 机制

Windows **UIPI（用户界面特权隔离）** 禁止低完整性级别进程向高完整性级别进程投递窗口消息与 OLE 拖放数据。资源管理器（Medium）向已提权的编辑器（High）拖文件时，拖放被系统在应用层之前拒绝，表现为**禁止光标**，且**编辑器日志中不产生任何记录**。

实测印证：当日 `Saved\Logs\ShadowTrackerExtra.log`（2.9 MB）中检索 `DragDrop` / `OnDrop` / `AssetImport` / `denied` / `elevat` / `UIPI` 均无命中 —— 与「拖放从未到达应用」一致。

### 3.4 排除的其它原因

| 假设 | 排查 | 结论 |
| --- | --- | --- |
| 目标目录无写权限 | `Asset\TuPian` ACL：`Authenticated Users` = `Modify` | 不成立 |
| 源文件格式不支持 | 官方支持 PNG/JPG/TGA，本次为 JPG | 不成立 |
| 工程内非法文件名（`-`/多点/非 ASCII）触发扫描中断 | 全工程扫描：仅 `.git` 内部有连字符，业务文件无违规；仅 2 个根目录中文 md/xlsx | 不成立 |
| 编辑器显式配置了 `RUNASADMIN` 兼容层 | `HKCU/HKLM AppCompatFlags\Layers` 无编辑器条目 | 不成立（提权来自 WeGame 启动链，非兼容层） |

## 四、可行修复路径（按安全性排序）

1. **最安全**：不改变系统安全策略，改用编辑器内的导入入口或 MCP `ue.import_asset`（本轮采用），或让编辑器**不提权**启动（绕开 WeGame 启动链，使其与资源管理器同为 Medium IL）。
2. **其次**：若必须拖拽，让**两侧同为相同完整性级别** —— 例如以相同权限启动资源管理器与编辑器。
3. **官方 Wiki 方案**（安全降级）：UAC 改「从不通知」+ 禁用上述两项策略。会使全机长期失去 UAC 保护，须需求方决定。

### 5.1 新发现：内置 Administrator 场景下存在代价更低的 B 档（推断，待重启后实测）

本机登录账户经核验为**内置 Administrator**：`whoami /user` = `S-1-5-21-2082072124-1165288802-2268317794-500`（RID 500），`net user administrator` 注释为「管理计算机(域)的内置帐户」。

因此除官方 A 档外存在 B 档：仅设 `FilterAdministratorToken = 0`，**`EnableLUA` 保持 1**。放开令牌过滤后，explorer 与编辑器令牌同为 High IL，UIPI 隔离消失 → 拖放可用；UAC 本体仍在，**Microsoft Store / UWP 应用不受影响**。

| 档位 | 改动 | Store/UWP | 是否需重启 | 备注 |
| --- | --- | --- | --- | --- |
| A（官方 Wiki，已执行） | `EnableLUA=0` 等 4 项 | **无法启动** | 是 | 安全降级，官方口径 |
| B（替代） | `FilterAdministratorToken=0` + 通知类 3 项 | 不受影响 | 是 | 仅对 RID 500 内置 Administrator 有效；官方 Wiki 未覆盖 |

> B 档的「拖放可用」结论为**基于 UIPI 机制的推断**，尚未在本机重启后实测验证；验证后须回来订正本条证据状态。两档不可叠加，切换前先 `RESTORE`。

### 5.2 A 档的确定性副作用

1. Microsoft Store / UWP 应用无法启动；
2. Windows 安全中心报告「UAC 已关闭」，合规扫描告警；
3. 依赖 IL 隔离的浏览器沙箱 / Windows 沙箱退化；
4. 若 WeGame 不再自动提权，需手动「以管理员身份运行」编辑器。

## 六、附带发现

1. `ue.objed_save_asset(assetName, editorType)` 要求该资产已在对应编辑器页签中打开；未打开时报 `Asset '<name>' not found in <Type> editor.`。未打开的资产用对象方法 `obj.save_package()` 保存。
2. `bp.save_package()` 返回的是 `UObject` 自身而非布尔，**不能当成功判据**；应以重新 `load_object` 回读 + `package_is_dirty()` + 磁盘 `mtime`/字节数三重确认。
3. MCP 反射读 `UObject` 的 `get_property('Brush').as_dict()` 是判断设计态画刷是否为空（`ResourceObject == None`）的可靠入口，优于 UAssetAPI JSON 的 import 索引映射。
