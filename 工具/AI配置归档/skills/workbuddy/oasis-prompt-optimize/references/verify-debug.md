# 验证与调试提示词

仅在任务涉及 PIE、热更新、文件名校验、崩溃或日志定位时读取本页。

## 生效方式

提示词必须指定且不得互相矛盾：

- 必须重新调试 PIE：初始化、`ReceiveBeginPlay`、事件绑定、蓝图/组件、资源路径、加载时机、脚本挂载、配置表
- 可热更新：仅已加载 Lua 的普通函数体
- 建议重新 PIE：无法确认时的保守选择

配置表在 PIE 运行中修改不生效。静态语法通过、蓝图 CDO 回读成功、API 文档命中，都不等于运行正确。

## PIE 与生产差异

PIE 单进程，服务端与客户端共享 `_G`；生产双进程各自独立。依赖 `_G` 做跨端查找的逻辑，提示词必须要求从架构上避免，不能把 PIE 通过写成上线保证。

## 文件名与工程卫生

PIE 上传会递归扫描工程。提示词必须禁止：

- 文件名不以英文字母开头
- 路径或文件名包含 `.` 或 `-`
- 工程内残留 `_tmp_*.py`、`_mcp_tmp`、`__pycache__`、`*.pyc`、下划线/点号/连字符开头的临时文件
- 把备份放进 UGC 工程，包括 Backup/、Saved/Backup、`_JsonOutput/Backup`

备份只放到 `D:\知识库\和平精英绿洲起源\备份\<项目名>\<YYYYMMDD>_<主题>\`。Python 辅助脚本也放那里，文件名以英文字母开头且只含字母数字下划线。一次性 `.py` 用完即删。

出现 `must begin with an alphabetic character`、`may contain the following characters`、`CheckUploadFileNameFailed` 时，先当文件名问题，不要立刻改 Lua。紧跟出现的 `lua file validation failed` 可能只是同一轮中断，不是语法证据。

含 `%` 的路径必须用绝对路径和 `-LiteralPath`，禁止让命令行展开 `%SystemDrive%`。

## 日志排查

崩溃、异常、PIE 失败、端侧差异、日志定位时，提示词应要求 `$ugc-log-bug-analyzer`：

- 已知脚本/函数时先用 `-ScriptFunction 'ScriptName+FunctionName'`
- 不要 `Get-Content -Raw` 或粘贴完整 FullLog
- 没找到匹配日志只能写成缺少执行证据，不能写成函数没跑
- 需要 API/生命周期/复制/端侧结论时，先官方查证再给修复建议

## 预估成功日志

改代码类提示词可要求给出预估成功日志，但必须逐条标注「预估成功日志」。格式保持：

```text
1. 【脚本名+函数名】=== 开始[功能名称] ===
2. 【脚本名+函数名】关键数据=xxx
3. 【脚本名+函数名】分支: xxx
4. 【脚本名+函数名】错误: xxx
5. 【脚本名+函数名】=== [功能名称]完毕：成功 ===
```

实际日志与预估不符时，以实际日志为准。
