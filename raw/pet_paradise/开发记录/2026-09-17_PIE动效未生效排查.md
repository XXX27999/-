# PIE 动效未生效排查（2026-09-17）

- **适用范围**：仅 `pet_paradise`（宠物乐园）
- **现象**：用户报告「在 PIE 模式下调试时，所有 UI 动效（UMG 动画、过渡、淡入淡出等）都未见，与之前一样」
- **结论分级**：日志落点 / 两个缺陷为**实测确证**；「Config 导致 Tween 不跑」为**实测证伪**

## 二、实测确证的两个缺陷

### 缺陷 1：`MakeKey` 调用 UMG 控件上不存在的 `GetName`（确证）

证据（14:25:34，旧会话 LuaLog L20196-L20230）：

```
LogTagLog: Error: [LuaException] LuaExtend_GetProp
  msg: LuaExtend::Lua_GetPropertyValue Failed:
       Object [Image ...TiShi_C_0.WidgetTree_94.Image_230] PropName [GetName]: property not exist
  stack: Script/Common/UI/UIMotionKit.lua:246: in upvalue 'MakeKey'
```

- 每次 `PlayFade` / `PlayScale` 都会刷两条，发生在 `__index` 元方法内部，
  **pcall 只能拦 Lua 层、拦不住引擎侧 LuaException 日志**。
- 该缺陷**不致死**：pcall 失败后回退 `tostring(Widget)`，key 仍有效。

### 缺陷 2：配置表用错读表接口（确证）

```
【MotionConfigLoader+Load】错误: 读表返回非表（userdata），保留内置默认值
  path=Data/Table/Customized/Motion/MotionConfigTable
```

- `UGCGameSystem.GetTableData(path)` 在本工程返回 **userdata（UDataTable 对象）**，
  不是「以 RowName 为键的内容表」，故原 `pairs` 遍历必然走进「非表」分支。
- 工程内 **8+ 处**已验证的读表写法是 `GetTableCount` + `GetTableDataByRowName`
  （见 `PetActorDic` / `UGCPlayerController` / `CF_KHDRPC` / `PetCharmConfig` 等），
  **没有任何一处**用 `GetTableData` 做全表读取。
- 路径格式本身合法：官方文档 `TablePath` 支持 `.../TableName`（相对 Asset 目录）。

## 三、真正的根因：`PlayScale` 漏传 `FromScale`（用户「看不到动效」的直接原因）

`PlayPanelOpen` 的实现是「先设起始值，再交给 `PlayScale` 做插值」：

```lua
SetScale("PlayPanelOpen", Panel, StartScale)   -- StartScale = 0.86
SetOpacity("PlayPanelOpen", Panel, 0)
UIMotionKit.PlayFade(Owner, Panel, 0, 1, "Base")
local Group = UIMotionKit.PlayScale(Owner, Panel, 1.0, "Base", "panel", function() ... end)
```

而 `PlayScale` 的签名与内部取值是：

```lua
function UIMotionKit.PlayScale(Owner, Widget, TargetScale, TokenName, ExtraKey, OnComplete, FromScale)
    local StartScale = tonumber(FromScale) or 1.0      -- 不传就是 1.0
    ...
    return UGCTweenSystem.TweenFloatValue(StartScale, TargetScale, ...)
```

调用点**没有传第 7 个参数** ⇒ 缩放 Tween 实际走的是 **1.0 → 1.0**。
上一行刚设的 `0.86` 在 Tween 第一帧回调里被立刻覆盖回 `1.0`，
于是**缩放动效在数学上不存在**——不是太细微，是恒等变换。

同理受影响的还有两处（同一错误模式：内部先设起始值，再调 `PlayScale` 却不传 `FromScale`）：

| 位置 | 表现 |
| --- | --- |
| `PlayPanelOpen`（弹窗入场） | 0.86 设完即被覆盖，缩放完全无变化 |
| `SetCardSelected`（选中对勾回弹） | 目标 1.0、起始默认 1.0 ⇒ 1.0→1.0 无回弹 |
| `PlayLoadingProgress`（进度条） | 先设 `StartScale` 再 1.0→`EndScale`，进度条从满格跳变 |

`PlaySlide` / `PlayListStagger` 不受影响：它们的 Tween 起点直接取入参 `FromX/FromY` 或显式 `0`，
与前置 `SetTranslation` / `SetOpacity` 的值一致。

**已修复**：三处均显式传 `FromScale`；对勾起始缩放新增量值 `SelectTickFromScale = 0.5`
（遵循「调用点禁写裸数字」，未写死在调用点）。

这个缺陷与第二节两个缺陷的区别：那两个只影响日志噪声与配置来源，
**这一个才直接决定「画面有没有变化」**，且静态即可证明，不依赖 PIE。

## 四、实测证伪的假设：Config 类型未注册导致 Tween 不跑

日志中出现过告警（时序上落在 `TweenFloatValue` 调用窗口内）：

```
ugc env:try to index /Script/UnrealTween.UnrealTweenConfig which does not exist in mt
```

据此推测「MakeConfig 产出的配置对象类型未注册 → Tween 不推进」。**实测证伪**。

对照实测（PIE client 内裸调 `UGCTweenSystem.TweenFloatValue`，0.5s）：

```
[DIAG] UGCTweenSystem=table   EEasingType=table   easing(QuadOut)=2
[DIAG] A(Repeat=0) ok=true h=ud_struct[TweenHandle ...]
[DIAG] B(Repeat=1) ok=true h=ud_struct[TweenHandle ...]
[DIAG] C(nilCfg)  ok=true h=ud_struct[TweenHandle ...]
[DIAG2] A(Repeat=0) ticks=60 | B(Repeat=1) ticks=60 | C(nilCfg) ticks=60
```

- **三档都跑满 60 ticks**，`RepeatCount=0` 照跑不误（此前担心的「0 = 播放 0 次」语义歧义不成立）。
- `EEasingType` 可用，`QuadOut = 2`。
- 结论：**Tween 系统完全正常**，动效看不见的原因不在 Tween 创建层。
