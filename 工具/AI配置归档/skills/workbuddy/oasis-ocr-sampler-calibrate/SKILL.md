# 绿洲启元 OCR 采样器 · 大厅识别标定流程

工具目录：`D:\知识库\和平精英绿洲起源\工具\OasisOcrSampler\`
知识正文：`D:\知识库\和平精英绿洲起源\raw\知识\通用\工具与流程\绿洲启元地图数据OCR采样工具.md`

## 铁律（先看这条，全部有实测依据）

1. **一律用 `round()` 换算像素，禁止 `int()`**。`int(108.6)=108`，这 1px 会让顶部那行淡字整块读不出来。`find_cards` 和 `field_rect` 两处都要改。
2. **热度绝不能加预处理**（`FIELD_PREP` 里只能有 `评分`）。加自动对比度会把 `111万` 读成 `川1万`，差 100 倍。
3. **评分框左边界必须留在星标右侧，且星标与数字之间「没有间隙可切」**（当前真机 **126@1920 ≡ 视图 71.0**，2026-09-20 v4 修订）。星标墨迹与评分数字**紧贴**：想完整覆盖数字，框必然带进一小条星标；星标是**实心**图形，右弧会被 OCR 认成 `7`、整体被认成 `?`，于是 `4.3 → 74.3`、`2.9 → ?2.9`。**判据：误读字符恒在真值左侧**（`7` / `?` 都长在真值左边）—— 看到这个形状就断定为星标污染，不要去调 OCR 倍率或预处理。
   - ⚠ 旧的「左边界固定 112」**已作废**：那是按 1920×864 单张图定的，按比例换算到 2400×1080 后正好覆盖星标右半（相对卡左 140..165）。**换分辨率后旧框可能仍然「看起来对」，但已经踩进相邻图形。**
   - 也别把框收得太狠：收窄会切掉数字左半。判据是「框内只剩数字、没有星标实心块」。
4. **字段框高度宁可给足**。收窄的失败是静默的（只少一个字符不报错）：热度要真机 44px 才带得上「万」，入口按钮要 45px 才读全「下载」。
5. **改任何 `LOBBY` 几何（卡片顶/行距/卡高/字段偏移）、或改卡片网格语义（行数/列数/步长的含义），都必须 `GEOM_VERSION += 1`**，否则旧配置里的错误几何/已变语义的旧参数会被静默复活。守卫要丢的键已扩到 `rects / row_step / card_h / ncol / card_count / card_step / col_step`（当前 **v4** = 评分框右移）。
6. **一页网格固定是「2 行 × 3 列 = 6 张」。任何只按行距纵向复制的写法都是 bug** —— 曾同时存在于 `draw_all_rects`（画面只画一列）与 `card_boxes`（识别时右边两列整列丢失），合起来就是用户看到的「一页 2 行 3 列却只能框选一列」。`col` 绝不能硬编码 0。
7. **字段可用性不要用 `self.rects` 判断**，要按模式判定。旧版 `recognize_card` 用 `self.rects.get(f)`，用户在大厅模式下存过几个手工框后，「入口按钮」这类没有手工框的字段会被无条件留空。
8. **`FIELD_PAGE_UNAVAILABLE`（评论数）是本页属性，只在 `layout_mode == "lobby"` 生效**，不要无差别套到自选模式，否则用户亲手拖的框被静默忽略。
9. **`wm size` 有两个值时取最后一个**（`Override size` 才是生效分辨率；本机 1440×3200 vs 1080×2400）。取错会让滑动坐标与截屏尺寸不匹配。
10. **纯色截屏不等于「界面禁截屏」**。`is_blank()` 只判「是不是纯色」，**判不出成因**。真机实测：手机 `mWakefulness=Dozing`（熄屏/锁屏）时 `screencap` 会**成功**返回一张合法但整幅纯色的 PNG（1080×2400，仅 7,935 B）。只有屏幕**亮着**却纯色才是 FLAG_SECURE。**一律走 `explain_blank(adb)`**，不要自己拼黑屏文案（旧文案把熄屏说成禁截屏，让用户去拍照导入，是错建议）。
11. **`input` 与 `screencap` 不同命**：截屏（读帧缓冲）**不需要**注入权限，熄屏也能成功返回；只有 `input swipe|tap` 这类注入被 ROM 拦。所以「上滑失败」时截屏取数仍然通 —— 只是要人手点亮屏幕 + 手滑翻页。
12. **`input swipe` 报 `INJECT_EVENTS` 时先排除 ROM 限制，别去改代码**：这是手机侧安全策略，不是工具 bug。三条只读排查顺序见下方「上滑失败的排查顺序」。**本工具不使用 root / `sendevent` / `monkey -f` / 注入框架**（无条件，不分场合）—— 它们属绕过 ROM 安全策略，与工具红线冲突。
13. **评分解析走 `FIELD_PARSERS` 按字段分发的形态匹配，不要退回通用 `parse_number`**。`parse_score()` 取 `(\d)\.(\d)` 的**最后一个**匹配（真值在星标右侧、误读字符恒在左侧），`10.0` 单独特判，**没有小数点返回 `None` 不猜**。框是「不让它进来」，解析器是「万一进来也读对」——**两条都要保住**，改评分逻辑时任一条掉了自检 G 段会 FAIL。
14. **连续滚动列表的上滑参数：位移小 + 时长长 = 拖动（惯性小），位移大 + 时长短 = 甩动（惯性大）**。当前默认 **35% 屏高 + 800ms**（旧 55%/350ms 是 fling，抬手后惯性带着列表继续滚 → 一次跨过一页多）。大厅列表底部常露出半个第三行，**一屏不是一个固定单位**，不存在通用值 —— 给保守默认 + 界面可调（「上滑幅度(屏高比) / 时长(ms)」两个 Spinbox，存配置）。参数构造走纯函数 `swipe_args()`，不要在调用点手拼数组。
15. **凡「参数需要现场标定」的自检，必须输出可比较的量化结果，不能停在布尔值**。`test_swipe` 旧版只判 `input swipe` 退出码、成功就打一句「允许输入注入」——用户看到「通过」却不知道滑了多少，无法据此调幅度，反馈成了「测试滑动好像没实际滑动」（2026-09-20）。现在必须走「截前帧 → 滑 → **等惯性停下** → 截后帧 → `measure_scroll()` 量位移 → `swipe_advice()` 给判定与建议幅度」。
    - **量位移前必须等惯性停下**（`SWIPE_SETTLE_SEC=1.0s`）：甩动手势抬手后列表还会继续滚，立刻截屏量到的是中间态，会低估位移。
    - **`measure_scroll()` 测不出时返回 `None`，不要硬给个数**：最佳匹配不显著优于次优（阈值 0.80）即判 `None`。宁可说「量不出」，也不要给一个看起来合理的错数 —— 那会直接误导调参。
    - **`_gray_small()` 必须「按高度缩放 + 轻度模糊」，两条缺一不可**（2026-09-20 合成图 + 真机双验证）：
      - 按**宽度**缩到 420 → 横屏 2400×1080 只剩 **189px 高**，模板块仅 22px，真机两帧根本匹配不上（报「找不到稳定匹配」）。改按**高度 400** 后同一张图是 889×400。
      - 缩放后必须 `ImageFilter.GaussianBlur(1.2)`：真机位移换算到缩略图上常**不是整数**（520px / 2.25 = 231.1），高频细节（噪点 / 细字 / 封面纹理）对**半像素错位**极敏感，正确位移处的残差会涨到与错误位移同量级（纯噪声 520px 实测：正确 17.9 vs 次优 20.0，比值 0.89 > 0.80 → 被判 `None`）。加模糊后降到 2.5 vs 6.3（比值 0.39），而块位置判定依旧精确（仍命中 232，真值 231.1）。
    - **`measure_scroll()` 必须「逐块投票 + 排除顶部固定区」，不能求全局最优位移**（2026-09-21 重写，用户「只滚一页也测不出」的真因）：旧版对所有块求「同一位移下的中位残差」，隐含假设**整屏一起动**。但大厅顶部有一条约占屏高 **19.4% 的固定区**（页签/标题，`LOBBY` 卡顶 168/864），不随列表滚动 —— 位移一大，列表块被拿去跟**固定区**比，残差整体抬高，最佳与次优几乎并列（真机失败样本比值 **0.96 / 0.98**）→ 一律判「测不出」。现在：
      - 常量 `LIST_TOP_RATIO = 0.20`：块只取自列表区，且候选位移受它约束（`y - s` 落进固定区即弃）——那些内容在第二帧里**根本不存在**。
      - 每个块自己投一票 → 按位移聚类（±4px）→ 取票数最多的簇（固定区投 0、列表区投真值，多数胜出）。
      - **范围截断裂权**：上方块够不到大位移（`smax = y - y0`），它的「最佳」只是被截断后的边界值 → 弃权（不加这条，卡片列表 520px 会被假票拉成「投票分裂」）。
      - **同票比残差**：卡片列表有固定行距，`真值` 与 `真值 ± 行距` 都能对上（周期别名），票数会打平（实测 4:4）；别名对上的是**别的卡片**，残差更高（4.72 vs 6.73）——按残差把真值挑出来。
      - **质量闸门**：`残差 / 该块失配基线 > 0.55` 判 `None`。真机正常滑动约 0.03；相隔 76s、封面重绘的两帧是 0.60 → 拦下是对的，宁可说测不出。
    - **等滚停的超时必须在「比对之后」判定**：只在循环头判 `elapsed < timeout` 的话，截屏 + `measure_scroll` 每次要 0.3~1s，实测一路跑到 **4.9~5.1s** 才停，日志里全是「仍未停稳」的假警报。改成每轮比对完再判硬截止；「停稳」判定给 2px 容差（`shift <= 2`）。
    - **测量必须「等滚停」，不能固定 `sleep`**（2026-09-21 用户反馈「每次距离都不一」）：`time.sleep(SWIPE_SETTLE_SEC)` 是**中间态测量**——惯性衰减时长每次都不同（系统负载 + 抬手瞬间的速度估计），固定等待必然量出不同数。改为 `wait_scroll_stop(adb)`：**轮询截屏直到连续两帧 `measure_scroll()==0`**（上限 `SCROLL_STOP_TIMEOUT=4s` 兜底，不靠死等）。**采样循环里同样要等**：原来只靠「间隔」兜底，间隔调小（0.5s）时下一帧是在滚动途中截的，表现为「翻页忽多忽少 / 同一页被截两次」。
    - **连测取中位数，并把离散度报出去**（同一反馈的另一半）：fling 落点本身是随机变量，**单次值不能拿来调参**。默认连测 `SWIPE_RUNS_DEFAULT=3` 次（界面「连测次数」Spinbox 1~5，存 `swipe_runs`），走 `summarize_runs()` 输出中位数 + 极差 + 稳定性判定（极差比 ≤15% 稳定 / ≤35% 一般 / 否则**不稳定**）。**「不稳定」档必须明说「单次测量不可信」并给出「拉长时长到 1200ms+」的对策**，不能只丢一个中位数给用户。量不出的那次（None）从统计里剔除，不能拉低中位数。
16. **按钮回调里的异常必须自己接住**。GUI 程序没有控制台，回调里抛出的异常只打到 stderr，用户看到的就是**「点了没反应」** —— 2026-09-20「结果无法导出为表格」就是这么来的（导出时目标 CSV 正被 Excel 打开 → `PermissionError`，谁都没看见）。按钮方法只做外壳，统一 `try/except`：空表提示、`PermissionError` 提示先关文件、`ImportError` 给出安装命令、其它异常打印 `type(e).__name__ + str(e)`，并同时写日志和 `messagebox`。
17. **写文件的逻辑抽成模块级纯函数，别写在按钮回调里**。按钮回调直接写文件的话，自检一调用就会弹 `messagebox` 把进程卡住。现在 `export_rows / write_csv / write_json / write_xlsx` 都是模块级纯函数（不弹窗、不碰控件），按钮方法只负责拼路径 + 调纯函数 + 提示。**新增导出格式时照抄这个分层。**
    - ⚠ **类体里的 `COLS = EXPORT_COLS` 是类加载时求值的**：导出列常量必须定义在 `class App` **之前**，放文件末尾会 `NameError: name 'EXPORT_COLS' is not defined`（2026-09-20 实测踩到）。写文件的函数可以放末尾（运行时才调用），**常量不行**。
18. 临时脚本只能放 `D:\知识库\和平精英绿洲起源\备份\OasisOcrSampler\<YYYYMMDD>_<主题>\`，文件名以英文字母开头、只含字母数字下划线。**用完清现场**（含 `py_compile` 会生成的顶层 `__pycache__`）。
19. **Tk 界面「各区域可滚动 + 可调大小」的定式**（2026-09-20 用户要求；起因是右栏在横屏/小屏下底部按钮点不到）：
    - **可调大小 = `ttk.PanedWindow` 两层**：外层 `VERTICAL`（主体 / 日志 → 拖分隔条改日志高度），内层 `HORIZONTAL`（画布 / 右栏）。**必须先建外层再建内层**：把 `body = ttk.PanedWindow(vpan, ...)` 写在 `vpan = ...` 之上会 `UnboundLocalError: cannot access local variable 'vpan'`（2026-09-20 实测踩到，自检 C 段直接挂掉）。
    - **可滚动 = `Canvas + Scrollbar + create_window(holder)`**：`holder` 的 `<Configure>` 里 `scrollregion=canvas.bbox("all")`；`create_window` 返回的窗口 id 要在 `<Configure>` 里 `itemconfigure(width=e.width)` 跟随，**否则右栏宽度不跟着分栏走**。横向再挂一根 `HORIZONTAL` Scrollbar 兜底。
    - **滚轮绑定必须给滚动容器本身开后门**：`bind_all("<MouseWheel>")` 里若只按 `isinstance(wdg, tk.Canvas)` 一律 `return`，右栏**大部分面积就是这个 Canvas**，结果是「滚轮在右栏没反应，只有指到按钮/标签上才滚」。先判 `wdg is rcanvas` 再滚，然后才走 `Text/Treeview/Combobox/Spinbox` 的放行规则。
    - 日志区同样补一根 Scrollbar（`Text(yscrollcommand=...)` 与 `Scrollbar(command=...)` 双向绑）。
    - **结构改动要在自检 C 段断言**（`len(app.vpan.panes())==2`、`len(app.body.panes())==2`、`app.rcanvas is not None`、`app.log_scroll is not None`）—— 布局是肉眼在日志里看不出来的改动，不断言就会静默回归。
20. **方差要显式暴露，不能替用户抹掉**（2026-09-21「测试的滑动每次距离都不一」）：任何「测量—调参」闭环里，若被测对象本身随机（Android fling 的落点就是），**单次测量不是事实**。
    - 先分清两类成因再动手：**测量时机错**（惯性没停就截 → 修 `wait_scroll_stop`）vs **对象本身随机**（fling 方差 → 只能连测取中位数并报离散度）。前者是可修的 bug，后者只能如实呈现，**不要用「取平均」「四舍五入」把方差藏起来**。
    - 判定阈值要有出处并写进自检：极差/中位数 ≤15% 稳定、≤35% 一般、>35% 不稳定（**K 段**逐档断言，含 `[None, 500, 520]` 这类「混着量不出的一次」）。
21. **合成测试样张必须有纵向结构**：纯色 / 近纯色的图在任何位移下 `measure_scroll()` 残差都是 0，直接返回 0。用它测「等滚停」会得到「2 次截屏就停稳」的**假通过**（2026-09-21 自踩：样张只有一行文字，等停测试提前退出却全绿）。凡给 `measure_scroll` / `wait_scroll_stop` 造 fixture，必须先断言「已知位移量得出来」（如 50px → 50），再跑真正的用例。
22. **「精确滑动」只能靠闭环，开环调参调不出精确**（2026-09-21 用户问「有什么能精确滑动的方法吗」）：`input swipe` 是**开环**的 —— 抬手瞬间的速度估计、列表阻尼、惯性衰减都不可控，同一组参数必然给出不同落点，**不存在**「算准一次就准」的参数。
    - 三条路，按推荐度：① **闭环补齐**（已实现，默认开，「精确滚动」复选框）：滑一次 → 等停 → 量实际 → 按本轮实测增益 `gain = 实际/手指` 反推再补，最多 3 轮，误差收敛到 ±12%（纯计算在 `plan_next_swipe()`，自检 **L 段**断言六种情形，含「上轮没动 / 增益离谱」时夹回 1.0 的除零保护）；② **拖动模式**（开环里最准）：时长拉到 1200~2000ms、幅度调小，实际≈手指位移，方差最小；③ **不要求精确 —— 这才是采样场景的正解**：只要「每次 ≤ 一页」，重叠部分由「按地图名去重」吸收，末尾由「连续两帧一致」判定。**宁可少滚，不要跳过**，所以调参目标应是「略小于一页」而不是「正好一页」。
    - 增益**只记内存不落盘**（`save_cfg` 里显式 `pop("swipe_gain")`）：它是本次运行实测出来的，换页面 / 换机型就失效，写进配置会拿过期系数去反推。
    - 明确不做：root / `sendevent` / `monkey -f` / minitouch 等注入方案属红线（与铁律 12 同源）。用户问「有没有更精确的办法」时不要往这个方向引。
23. **要根治「测不准」，靠实时流 + 帧链积分，不是继续调两帧比对**（2026-09-21 用户问「能实时监测手机屏幕吗」；答案是能，且这是正解）：

    - 首帧延迟实测 2.7s（起流 + ffmpeg 缓冲），其中约 2s 是同步 `screencap` 取尺寸 —— 主画布已有帧时直接复用可省掉。窗口上必须写「首次出画面约 2~5 秒」，否则用户以为卡死。

25. **「顶行贴红线」对齐（`align_to_grid`）的真机实测结论（2026-09-21 首版；2026-09-22 用户实测纠错后收敛为两条可证判据）**：
    - **锚点是行间亮缝，不是封面边缘**：行与行之间约 12px（视图）的亮缝在**三列上同时**「亮+平」（`detect_row_bounds`：横梯度中位数 <3.5 且亮占比 >85%，取三列 max/min）。封面内容边缘做不到三列同齐。视口内第一张**完整**卡顶与 `first_row_y` 之差就是 `drift`（纯计算拆在 `grid_drift()`，自检 **N 段**）。
    - 🔴 **`spacing_ok` 不再是「不符就停」的闸门（2026-09-22 订正）**：缝距不符有两种成因 —— (a) 停在了非大厅页面（QQ 聊天列表，拦下是对的）；(b) **缝落在封面内部的浅色平坦区**（真机实测：卡片确在大厅页，缝 `(300,325)` 落在封面天空/云雾上）。旧行为一律停会让 (b) 永久无法收敛。现改为**记录「缝可能落在封面浅色平坦区」并继续补滚**，由终局复测决定结果。
    - 🔴 **「顶部滑出屏幕却报已对齐」= 假缝，不是首行滑出（2026-09-22 用户实测纠错，最重要）**：用户原话「有时候滑动到红线识别也不准，地图顶部都滑上去超出屏幕了，还报顶行已对齐红线」。逐像素剖面证明视口上沿之上是「**页面背景空档 + 3px 暗色分隔线（「全部」筛选行下缘）+ 又一截背景空档**」（真机 2400×1080：y=192..208 mean≈190 flat≈2.0；y=209..211 mean=85 flat=0.0；y=212..219 亮平；y=220 flat 跳 58；y=221+ flat≈117 = 真卡顶）。亮缝检测只看「亮+平」不看色调 → 三段**被合并成一个 11px 假缝** `gaps[0]=(210,220)`，而 `g1+1=221` **恰好等于真实卡顶** → 算出 `drift=+11`（整行偏下），用户观感是「明明没对齐却报已对齐」。**用户说的「地图顶部滑上去了」其实是把红线以上的背景/分隔线误当成地图卡。**
    - 🔴 **「首行已整行滑出（`scrolled_past`）+ 回退一行距反推首行卡顶」是被证伪的错误方向，不要再实现（2026-09-22 自我纠错）**：曾按用户字面描述新增 `scrolled_past` 状态 + `implied_top = g1+1-R` 反推 + 允许负 drift 反向回滚。**三重证据全部否证**：① 合成帧回归 S=157 档反推得 `drift=-157`，正解 `+157`；② `shot_20260922_141831_002` 放大目视首行封面/标题/标签/下载按钮**全部完整可见**；③ 全量 43 帧扫描，修前 4 个负 drift **全是误判**。物理依据：视口上沿之上是页面背景/筛选行，**不存在「还能反推出上一行」的结构**。→ 判据只留三条，**`drift` 恒 ≥ 0**：
      ```python
      if g0 <= y0 + 2:                      state = "top_in_gap"  # first_top = g1 + 1
      elif (g0 - y0) >= cover_h - tol:      state = "aligned"     # first_top = y0（红线）
      else:                                 state = "cut"         # first_top = g1 + 1（下一行卡顶）
      ```
      原则与热度/评分同源：**宁可如实报「有偏差」也不给假值。**
    - **cut 状态下补滚过冲会「追行界死循环」**：cut 时检测器指向**下一行**的行界，补滚过冲哪怕 30px 就越过那条例行界，目标跳到再下一行（实测 156→333→329→357）。对策：越界量 `s_past = 行距 - drift` ≤ max(80, 25%行距) 时**反向滚回当前行**（`swipe_down`）。⚠ 这个保护仍保留 —— 它拦的是「正向补滚过冲」，与被删除的「负 drift 反向回滚」是两回事。
    - **位移测量必须带方向**：`measure_scroll` / `measure_scroll_total` / `measure_scroll_fast` 都有 `direction` 参数，回滚返回**负值**。不做双向搜索（候选集翻倍会放大周期别名），方向由调用方给（滑动指令是自己发的）。`precise_scroll` 里回滚进度取绝对值入账。⚠ 改这段时**缩进层级千万不能动错**：`tpl`~`while` 必须留在 `for x` 内层循环里（错一行缩进 = 每行只投一票，周期别名簇抢票，I 段立刻 FAIL——2026-09-21 自踩）。
    - **小位移补滚会撞触控 slop**（真机：21~31px 手指只滚 3px），学习增益跌到 0.1 反推出巨型手指位移（370px+，fling 几百 px）。对策：手指位移夹到 `3×缺口+30px`；**增益按方向隔离**（回滚只在本次调用内学习，不写回 `self.swipe_gain`）。对齐用慢速滑动（≥1200ms）压制 fling。容差 = max(5, 2%行距) ≈ 8px@1080；终局 ±20px 内可能要多点一次（工具会如实报「未收敛」），这是 `input swipe` 执行器的物理极限，不是 bug。
    - **文案要让用户按「偏差正负」理解，而不是「滑出屏幕」**：`_align_worker` / `sample_worker` 统一写「**偏差 >0 表示整行仍偏在红线下方，继续点「对齐」可再收敛一轮**」。
    - **排查方法论（值得复用）**：用户对现象的**描述可能是错的**（「已滑出屏幕」），必须自己取原图做逐像素剖面 + 放大目视 + 合成帧回归三重取证，不要照描述直接改代码。本轮照描述改的那一版就是错的，三重证据一起才把它否掉。

## ADB 上滑通路（「上滑失败 / 模拟点击被拒 / 滑过头」走这里）

### 「滑过头」不是步长算错，是惯性

大厅列表是**连续滚动**（底部常露出半个第三行），一屏不是一个固定单位。Android 手势语义：

```
位移大 + 时长短 = fling（甩动）→ 抬手后惯性继续滚 → 实际位移 >> 手指位移 → 跨过一页多
位移小 + 时长长 = drag（拖动）→ 惯性项衰减        → 落点可控
```

真机 2400×1080 换算：

```
旧: shell input swipe 1200 842 1200 248 350   (594px / 350ms)   ← 甩动，滑过头
新: shell input swipe 1200 842 1200 464 800   (378px / 800ms)   ← 拖动，当前默认
```

不同机型 / 不同列表的滚动阻尼不一样，**没有通用值**。工具里两个 Spinbox 现场调：**滑过头就调小「上滑幅度」、拉长「时长」**。

### 幅度怎么标定（不要靠猜，量出来）

1. **优先点「实时测滑动（录整段）」**（或勾上「用实时流测位移」后点「测滑动」）：录下整段滑动（含惯性尾巴）→ 沿帧链逐段积分 → 得到真实位移。真机实测极差比 0.13（判「稳定」）。
2. 没有 ffmpeg 时才退回「测滑动（连测取中位数）」：截前帧 → 真滑一次 → 等滚停 → 截后帧 → `measure_scroll()` 量实际滚动像素 → `swipe_advice()` 给「没滑够 / 合适 / 滑过头」+ **建议幅度**。两帧比对实测极差比 0.91，**单次值不可信，必须连测 ≥3 次取中位数**。
3. 把「上滑幅度」改成建议值，再点一次复测。惯性是非线性的，**复测 1~2 次收敛**即可。
4. 本机 `input swipe` 被 ROM 拦掉时，点「**测手动滑动**」：不用输入注入，等 5s 让你手滑一次，量出**人手翻一页实际滚了多少**，作为自动上滑的目标值。
5. 想要「看着调」就点「**实时监视…**」：≈26fps 连续画面 + 实时「累计滚动」读数，停稳后数字不再跳动 —— 那个数就是这次的真实位移。

「一页」= 2 行卡片，`row_px = INT_ROW_STEP × 屏高 / 864`，`page_px = 2 × row_px`。判据：实际滚动 / 页高 `<0.7` 没滑够、`0.7~1.3` 合适、`>1.3` 滑过头。

> 写「测量/判定」类函数时照抄这套：**测不出返回 `None`**，不要给默认值兜底。硬给的数会直接误导调参，比不测更糟。

### 上滑失败的排查顺序（全部只读，不要动代码）

真机实测定案（2026-09-20，Redmi K60 至尊版 / HyperOS OS3.0.304.0.WNMCNXM）：

```
adb devices                                  # 必须有 <serial>  device；unauthorized 就先重新授权
adb shell am get-current-user                # 必须是 0；不是 0 = 在分身/隐私空间/副用户下，切回主用户
adb shell settings get global adb_enabled    # 必须是 1
adb shell wm size                            # 有 Override 就取最后一个（生效分辨率）
adb shell input swipe 540 1872 540 552 350   # exit 0 且无输出 = 通；exit 255 = 被 ROM 拦
```

**同一条链上顺手把截屏也验掉**（这两件事经常被混为「adb 不通」）：

```
adb shell screencap -p > probe.png           # 或工具里直接点「ADB 截屏」
adb shell dumpsys power | findstr mWakefulness   # Awake / Dozing / Asleep
```

真机实测（Redmi K60 至尊版 / HyperOS）：`screencap` **可用**并返回合法 PNG，尺寸 **1080×2400 与 `wm size` 的 Override 一致** —— 截屏分辨率 = Override 分辨率，滑动坐标与截图同源。**`input` 被拦不影响 `screencap`**。若截屏整幅纯色，先看 `mWakefulness`：非 `Awake` 就是**熄屏**（点亮重截），只有 `Awake` 却纯色才是 FLAG_SECURE。

前四项都正常、第五项 `exit 255` 且 stderr 含 `java.lang.SecurityException: ... INJECT_EVENTS permission`（栈顶 `InputShellCommand.sendSwipe`）→ **定案为 ROM 安全策略拦截**：

- 小米/红米（MIUI / HyperOS）：开发者选项打开「**USB 调试（安全设置）**」（与「USB 调试」是两个独立开关；小米 13/14/15/17、红米 K60/K70/K80 系列开启时要求插 SIM 卡 + 登录小米账号 + 联网，提示「网络异常」时改移动数据）。
- 华为/荣耀：「允许模拟点击」。
- **该开关的状态无法通过 adb 只读读取**（`settings list global|secure`、`getprop` 都不暴露）→ 属待查证，**不要凭猜测断言用户已开**；唯一可靠确认方式是看 `input swipe` 的退出码（工具里的「测试滑动」按钮即此）。
- 报错栈在 `InputShellCommand.sendSwipe`，说明命令**已经正确下发到 system shell**。这可以直接用来反驳「是不是 adb 路径/参数写错了」。

### 工具侧已有的处理（改代码前先确认这些还在）

- `diagnose_adb_error()` → 4 类：`inject_denied` / `unauthorized` / `offline` / `other`，各给一句人话 + 可执行对策。**分类匹配要覆盖真机真实文案**：`device 'xxx' not found`、`no devices/emulators found`、`device offline` 三种都算 `offline`（早期只匹配 `device not found` 带空格形式，实测漏判，自检 E 段抓出）。
- `Adb.screen_size()` 取 `wm size` 的**最后一个**匹配。
- `Adb.swipe_up()` 返回 `(ok, 分类, 说明)`；调用方是 `sample_worker`（返回值解包要跟着改）。
- 「测试滑动」按钮 = 采样前一键自检；失败时自动取消勾选「自动上滑」。
- 采样线程遇 `inject_denied` 必须 `break` + `msgq.put(("swipe_off", None))` 让主线程关复选框 —— 旧行为是继续空转、反复截同一页，去重后表现为「明明有数据却没用」。
- **黑屏必须走 `explain_blank(adb)`**：`Adb.screen_awake()` 读 `dumpsys power` 的 `mWakefulness`，返回 `(True/False/None, 原始值)`，`None` = 读不出（不猜）。三处调用点已统一：`shot_from_adb()`（「ADB 截屏」按钮）、`detect_page_state()`、`grab_with_retry()`。**新增黑屏提示时不要绕开它自己拼字符串。**

### 合规替代路径（不依赖注入权限）

不勾「自动上滑」，把「间隔」调到 8~15s（够人手滑一页），开始采样后人工每轮滑一页。**这条路径下必须同时取消勾选「检测到列表末尾自动停止」**，否则手速慢于间隔时会连拍两帧同一页、命中「连续两帧一致」被误判到底而提前停止。

## 本工具的「静默失效」陷阱

- **自选模式**：`field_rect` 曾经无条件优先取 `LOBBY` 偏移，用户亲手拖的框完全不生效却不报错。任何新增的「大厅专属」逻辑都要按 `layout_mode` 分支。
- **大厅网格模式下的拖框**：旧版把框存进 `self.rects` 但识别取的是 `LOBBY` 几何 → 拖了没反应也不报错。现已改为「折算成相对卡片左上角的偏移」并覆盖整页，日志打印折算结果；「清空框选」可撤销。
- **列数被设成 2**：`ncol` 早期只属大厅网格，被设成 2 时大厅模式真的只认两列，界面上毫无提示。现在列数两模式共用、默认 3，且 `GEOM_VERSION` v3 会清掉旧存档里的错值。
- **接口漂移**：改主程序公开接口（`FIELDS` 扩容、`recognize_frame` 返回值改签名、`field_rect` 加参数、`swipe_up` 返回值从 bool 改三元组等）后，两个验证脚本会断裂 —— 已实测出现过 `KeyError`、`AttributeError`。**改完必须重跑**。
- **手动上滑 + 「检测到列表末尾自动停止」互相打架**：该开关靠「连续两帧内容几乎一致」判到底。手滑路径下，若手速慢于「间隔」，会连拍到两帧同一页而被判到底、**提前停止**（表现像「翻页失败」）。手滑前把「间隔」调到 8~15s 并取消勾选该项。
- **报错分类器的「漏判」是静默的**：分类器不报错、只是落到 `other`，用户看到的是「给了一句没用的原始报错」。新增/修改匹配串后，必须用真机真实文案（`device 'xxx' not found` 这类带具体值的）当测试向量 —— 只测理想文案（`device not found`）会漏。
- **黑屏文案的「错归因」也是静默的**：文案照常弹出、用户照做，只是做错事（熄屏被说成禁截屏 → 去拍照导入，白折腾）。凡「纯色/黑屏」相关提示，必须经 `explain_blank()`；判据与对策要能在同一句里看出成因。
- **`wm size` 取错值**：`Physical size` 与 `Override size` 同时存在时，取 Physical 会让滑动坐标与截屏尺寸差 1.33 倍。必须取最后一个。
- **`py_compile` 会生成顶层 `__pycache__`**：语法校验后必须删掉并 `Get-ChildItem` 复核，否则工具目录留缓存。`.venv\Lib\site-packages` 下的 `__pycache__` 属正常，不用清。

## 环境要点

- 必须用 `.venv\Scripts\python.exe`（Python 3.12.10 + tkinter + Pillow + rapidocr-onnxruntime + **openpyxl 3.1.5** + **imageio-ffmpeg 0.6.0**，后者提供实时流解码用的 ffmpeg 静态二进制）。托管 Python 3.13 无 tkinter。缺 openpyxl 时补装：`.venv\Scripts\python.exe -m pip install openpyxl -i https://pypi.tuna.tsinghua.edu.cn/simple`。
- Git Bash 缺 coreutils（`dirname: command not found`），**Bash 工具整体不可用**（连 `cd` 都失败，见 `shell-runtime-bash-env.sh: line 3`），一律走 PowerShell 工具。
- **命令回显干脆不要指望**：PowerShell 工具的 stdout 会整段丢失（连小命令也可能只回 `Command completed with exit code 0`）。固定套路 = 把结果写文件（用 `[System.IO.File]::WriteAllLines(path, lines, UTF8Encoding($false))`）再用 Read 工具读。**不要用 `Out-File` / `Tee-Object` / 重定向 `>` / `*>`**：PS 5.1 下它们写 UTF-16（Read 工具会判为 binary 或读出乱码），`-Append` 混两种编码还会把文件彻底搞坏。
- **`cmd /c` 被 PowerShell 工具的安全策略直接拦掉**（`cmd.exe cannot be used from the PowerShell tool`），不要试图用它做重定向。
- **捕获 Python 输出会踩 TerminatingError**：`& $py -u x.py 2>&1` 在 `$ErrorActionPreference='Stop'`（默认可能继承）下，stderr 一到就终止，结果是「只有第一行输出、后面全丢」。**必须先在脚本开头设 `$ErrorActionPreference='Continue'`**。
- **别把「命令回显」当测试结果**：`test_pipeline.py` 的报告写在 `_selftest.txt`，`test_regress.py` 写在 `_regress.txt`，标准输出只有一个 `done`。**回显里只有 `done` 不代表测试没跑**，要去读那两个文件。
- **两个验证脚本都约跑 1 分钟**（含 OCR 引擎初始化）。后台跑完后**先按 mtime 复核再读文件**，否则会读到上一次的旧内容（`_selftest.txt` 时间戳没变 = 这次还没写完）。
- **不要用 PowerShell 重定向去接脚本自己要写的文件**：`& python test_regress.py *> _regress.txt` 会让 PS 独占文件句柄，脚本侧写同一个文件直接 `PermissionError`。让脚本自己写，别接管它的输出。
- safe-delete 钩子对 `D:\知识库\...` 的 `Remove-Item` 有两种表现：报 `trash-failed` 但**文件其实已删**（假警报），以及**不报可见错误但确实没删**（真失败，2026-09-20 实测）。**两种都得用 `Get-ChildItem` 复核**，不能只看报错，也不能假定一定删成功。
- 自检脚本末尾用 `print(..., flush=True)` + `os._exit(0)` 硬退出，否则 Tk/onnxruntime 的本地线程会吊住进程数分钟。
- adb 路径：`D:\知识库\和平精英绿洲起源\工具\platform-tools\adb.exe`（未加 PATH，调用一律写绝对路径）。
