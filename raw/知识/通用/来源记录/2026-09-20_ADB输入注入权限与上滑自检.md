## 1. 结论

`adb shell input swipe` 在本机返回 **exit code 255**，stderr 为 `SecurityException: ... INJECT_EVENTS permission`，栈顶为 `InputShellCommand.sendSwipe`。命令**已正确下发到系统 shell**，是被 Android 框架层注入权限检查拦下 —— **不是工具 bug、不是 adb 路径或参数问题**。

结合取证排除两类常见诱因后（详见第 2 节），剩余唯一诱因是小米/红米特有的「USB 调试（安全设置）」未开启。

**合规解法只有两条**：
1. 开发者选项 → 打开「USB 调试（安全设置）」（华为/荣耀为「允许模拟点击」）；
2. 不勾「自动上滑」，改用「按间隔截屏 + 手动上滑一页」。

**本工具不使用 root / `sendevent` / `monkey -f` 事件脚本 / 任何注入框架**（无条件，不分场合）—— 它们属绕过 ROM 安全策略，与本工具红线冲突。

## 2.5 真机截屏通路与黑屏成因（同日实测）

`screencap` 通路**可用**：`Adb.screencap()` 返回合法 PNG，尺寸 **1080×2400**，与 `wm size` 的 **Override 生效值一致** → 截屏分辨率 = Override 分辨率，滑动坐标与截图同源，不存在取 `Physical 1440×3200` 造成的 1.33 倍错配。

同时刻截屏**整幅纯色**（PNG 仅 7,935 B、中心区灰度极差 0）。取证：

| 命令 | 结果 | 含义 |
|---|---|---|
| `dumpsys power` | `mWakefulness=Dozing` | 屏幕处于休眠（未点亮） |
| `dumpsys window` | `mCurrentFocus=Window{… NotificationShade}` | 停在锁屏/通知层 |
| `dumpsys activity` | `ResumedActivity=com.dragon.read/…` | 后台是别的应用，不在绿洲 |

→ **黑屏成因 = 屏幕熄灭/锁屏**，不是 FLAG_SECURE、不是工具缺陷。

**据此修掉一处误导性文案**：旧版只要纯色就一律提示「界面可能禁止截屏（FLAG_SECURE），请改用拍照导入」；而熄屏场景下「拍照导入」是**错误建议**，正确做法是点亮屏幕后重截。改动：

- 新增 `Adb.screen_awake()` → 读 `dumpsys power` 的 `mWakefulness`，返回 `(True/False/None, 原始值)`，`None` = 读不出（不猜）。
- 新增 `explain_blank(adb)` → 三成因三对策（熄屏→点亮屏幕；亮屏纯色→FLAG_SECURE 改拍照；读不出→先确认亮屏）。
- 三处调用点改走它：`shot_from_adb()`（「ADB 截屏」按钮）、`detect_page_state()`、`grab_with_retry()`。
- **自检新增 F 段**：`is_blank` 纯色/有内容断言 + `explain_blank` 三输入给三套不同对策 + 交叉断言（「熄屏」文案不得出现 `FLAG_SECURE`，「亮屏」文案不得出现「点亮屏幕」）。

**真机端到端**：`screen_awake()`→`False / Dozing`；`screencap`→`(1080,2400) RGB`；`is_blank`→`True`；`explain_blank()`→「…手机屏幕当前未点亮（mWakefulness=Dozing）——先点亮屏幕并解锁，再重新截屏。」**全部符合预期。** 截屏存证 `screencap_probe.png`（7,935 B，纯色）。

**回归**：自检 A/A2/B/C/D/E/**F** 全通过；`test_regress.py` 仍 **26/30**、卡片定位 6/6，无退化。
