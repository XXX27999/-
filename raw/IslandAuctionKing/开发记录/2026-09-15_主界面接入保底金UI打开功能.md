## 一、结论

主界面「保底金」按钮原本只弹「保底金尚未开放」提示。本轮把它的点击回调接到
`AuctionGuaranteeGoldUIService.CreateAndShow`，点击后即弹出已修好的保底金面板；失败时才回落提示，
失败文案走配置表而非硬编码。

| 项 | 改前 | 改后 |
| --- | --- | --- |
| `OpenGuaranteeButton` 回调 | `OpenUnavailable(widget, "GuaranteeText")` → `ShowTipsUI("保底金尚未开放")` | `OpenGuaranteeGold(widget)` → `AuctionGuaranteeGoldUIService.CreateAndShow(widget)` |
| 失败文案 | 无（按钮本身就不给二级反馈） | `UI.Hub.GuaranteeFailedText`（新增配置行，缺省回退「保底金暂时无法打开」） |
| 端侧守卫 | 同其他 Open* 函数 | 服务端直接返回并打 `detail=WrongAuthority` |

## 二、改动清单

### 2.1 Lua：`Script/Function/AuctionHubUIService.lua`

绝对路径：`D:\WeGameApps\rail_apps\OasisEraEditor(2001776)\ShadowTrackerExtra\UGCProjects\IslandAuctionKing\Script\Function\AuctionHubUIService.lua`

1. **新增** `AuctionHubUIService.OpenGuaranteeGold(widget)`（第 493–517 行），写法对齐 `OpenDress`：
   - `GetContext` 取端侧，`hasAuthority` 为真直接返回并打印原因（遵守「退则必印原因」）；
   - `AuctionUIMotionService.PlayPress(widget.OpenGuaranteeButton)` 与其余入口一致；
   - 函数内 `UGCRequire("Script.Function.AuctionGuaranteeGoldUIService")`，不在模块加载期 require；
   - `pcall(CreateAndShow, widget)` 取三值：`openOK / openResult(是否成功) / openDetail(错误码或 widget)`；
   - `not openOK or openResult ~= true` 时 `ShowTip(AuctionConfig.GetString("UI.Hub.GuaranteeFailedText", "保底金暂时无法打开"))`。

2. **切换** `BindEvents` 中 `widget.AuctionHubGuaranteeCallback` 的实现体。

`BindEvents` 的 `optionalBinds` 与 `Shutdown` 的 `binds` 两侧都已含 `OpenGuaranteeButton`，
回调函数名与存放位置未变，**不需要改绑定/解绑表**。

### 2.2 DataTable：`Asset/Data/Table/Customized/UI/UIConfigTable`

新增一行（四列规范 `配置类型 / 配置值 / 配置说明 / 修改注意事项`）：

| 行名 | ValueType | Value | Description | ModificationNotes |
| --- | --- | --- | --- | --- |
| `UI.Hub.GuaranteeFailedText` | string | 保底金暂时无法打开 | 保底金面板打开失败提示。 | 修改边界：单行短文本。依赖：OpenGuaranteeButton→AuctionHubUIService.OpenGuaranteeGold。生效：重新 PIE。 |

写入路径：`Resolve → Plan → Execute`（plan_id `plan_16800751_50c3e13a`），写入后 `save_package` 并 `data_table_find_row` 回读通过。

> `AuctionUIConfigTableService.LoadAndApplyConfig` 对 UI 表**全量遍历**并按点号路径写入 `AuctionConfig`，
