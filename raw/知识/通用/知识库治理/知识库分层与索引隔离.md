## 一、核心结论

知识库分两层，物理隔离、索引隔离：

| 层 | 位置 | 定义 | 索引方式 |
| --- | --- | --- | --- |
| 全局通用层 | `raw/docs/`、`raw/知识/通用/` | `raw/docs/` 保存官方 API/Wiki 原始资料；`raw/知识/通用/` 保存通用开发规范、工具链说明和从项目实战中**提炼后与项目无关**的结论 | `wiki/000_索引.md` 只登记对应短索引和 Raw 导航 |
| 项目专属层 | `raw/<项目名>/` | 单一地图项目的数据、参数、配置表快照、蓝图/UI 回读产物、资产清单、日志证据 | **不进全局索引**，只在 `raw/<项目名>/000_项目索引.md` 内做局部索引，由 [项目资料总览](../../../../wiki/项目/000_项目资料总览.md) 单点登记 |
| 调试备份层 | `备份/<项目名>/` | 写前 `.uasset` 副本、临时脚本、非法文件名隔离文件 | **不进全局索引**；禁止放回 UGC 工程 |

三条硬规则：

1. **原始资料保持原样**：`raw/docs/api`、`raw/docs/wiki`、`raw/docs/ai`、`raw/docs/skills` 的路径与结构不变，禁止把整理正文写回这些原始目录。`wiki/` 现有页面路径保持稳定，但页面只承担索引和导航职责；通用整理正文写入 `raw/知识/通用/`。
2. **项目专属数据必须落到 `raw/<项目名>/`**，严禁散落在 `wiki/概念/` 或 `raw/docs/` 根下。
3. **全局索引只收通用页**。`wiki/000_索引.md` 对项目层只保留一条指向 [项目资料总览](../../../../wiki/项目/000_项目资料总览.md) 的链接，项目数量增长不会膨胀全局索引。

4. **按运行属性分流 Codex 创建文件**。蓝图、Lua、项目运行所需的导入资产属于项目运行文件，按项目运行流程处理；网页预览、Python 辅助脚本、Markdown/报告、截图及其他与地图运行无关的文件必须存放在知识库，不得进入 UGC 工程。

## 二、项目同名文件夹规范

路径：`D:\知识库\和平精英绿洲起源\raw\<项目名>\`

项目名合法化：必须匹配 `^[A-Za-z][A-Za-z0-9_]*$`。转换规则：

| 原始形态 | 处理 | 结果 |
| --- | --- | --- |
| 空格、`-`、`.`、`（）` 等非法字符 | 替换为 `_` | `Island V2` → `Island_V2` |
| 中文项目名 | 用编辑器工程目录里的英文目录名，中文写进「中文别名」 | 海岛竞拍王 → `IslandAuctionKing` |
| 首字符为数字 | 前缀补 `P` | `2dot5` → `P2dot5` |
| 连续下划线 | 折叠为单个 | `A__B` → `A_B` |

固定子目录（六个，缺哪个建哪个）：

```
raw/<项目名>/
  000_项目索引.md      # 局部索引，必须有
  开发记录/            # 功能实现、问题排查、修复记录
  数据参数/            # 玩法数值、时长、容量、概率、坐标
  配置表/              # DataTable 行名/类型/值导出
  蓝图与UI/            # 蓝图结构、控件树、画刷基线（MCP 回读产物）
  资产清单/            # 贴图/模型/音频命名与导入属性
  日志证据/            # PIE、DS、客户端日志摘录
```

## 三、可执行步骤

### 1. 新资料分流判定

按下表判定，命中任一「项目专属」特征即入项目层：

| 特征 | 归属 |
| --- | --- |
| 出现 `/<项目名>/Asset/...`、`UGCProjects/<项目名>` 等项目路径 | 项目层 |
| 具体数值：时长、容量、概率、坐标、Yaw、金币、补偿系数 | 项目层 |
| 具体资产名、DataTable 行名与行值 | 项目层 |
| PIE / DS / 客户端日志原文 | 项目层 |
| API 是否存在、参数、返回值、端侧生效范围 | 全局层（`raw/docs/api` 为真源） |
| 编辑器机制、操作流程、错误码 | 全局层（`raw/docs/wiki` 为真源） |
| 换到别的地图项目仍成立的做法、规范、陷阱 | 全局层（提炼进 `wiki/概念/`） |

### 2. 建目录并写入（PowerShell，UTF-8 无 BOM）

```powershell
$root = 'D:\知识库\和平精英绿洲起源\raw'
$name = 'Island_V2'   # 已合法化的项目名
foreach ($s in @('开发记录','数据参数','配置表','蓝图与UI','资产清单','日志证据')) {
    $dir = Join-Path (Join-Path $root $name) $s
    if (-not (Test-Path -LiteralPath $dir)) { New-Item -ItemType Directory -Path $dir -Force | Out-Null }
}

# 写文件必须 UTF-8 无 BOM
$path = Join-Path (Join-Path $root $name) '开发记录\2026-08-26_示例.md'
[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))
```

### 3. 混合内容拆分

单次更新同时含通用与项目内容时必须拆两份写：

- 通用部分 → 追加/新建 `raw/知识/通用/<领域>/<主题>.md`，再在 `wiki/概念/<主题>.md` 建短索引并登记进 `wiki/000_索引.md`
- 项目部分 → 写 `raw/<项目名>/<子目录>/YYYY-MM-DD_<主题>.md`，登记进该项目的 `000_项目索引.md`
- 两份互加链接：概念页写「项目侧证据见 …」，项目页写「已提炼到全局的通用结论见 …」

## 四、常见错误

1. **把项目数值写进概念页**：`UI.InfoCard.Width=677`、座椅 Yaw 实测值这类数字属于某个工程，写进概念页会让通用结论不可移植。概念页只写「必须配置表化、不得硬编码」。
2. **搬迁 `raw/docs/ai`**：`raw/docs/ai/*` 已被 23 个 wiki 页面按路径引用，物理搬迁会批量断链。归属通过项目索引页登记，不移动文件。
3. **给每个项目在全局索引里开一节**：这正是「索引过多」的成因。全局索引只留一条指向项目总览的链接。
4. **项目名直接用中文或带空格**：违反 `^[A-Za-z][A-Za-z0-9_]*$`，且与编辑器工程目录名不对应，后续脚本按路径匹配会失败。
5. **在项目层重复抄一份通用规范**：项目页只放证据与差异，通用规范引用概念页链接。
6. **把网页、Python、Markdown、报告或截图放进 UGC 工程**：这些是非项目运行文件，应放在知识库；蓝图、Lua 和项目运行所需的导入资产不适用本条，按项目运行流程处理。
