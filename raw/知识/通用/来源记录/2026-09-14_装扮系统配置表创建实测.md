## 一、任务

为装扮系统生成两个独立配置表：

1. **装扮控件配置表**：每个 UI 控件选项的中文名 + 对应需要改材质的控件名
2. **装扮材质配置表**：材质中文名 + 对应图片素材

覆盖范围：主界面（3 区域）、竞拍界面（8 区域）、结算界面（1 区域，整体处理），共 12 项。

## 二、交付

| 资产 | 类型 | 行数 |
| --- | --- | --- |
| `Asset/Data/Table/Customized/Dress/DressControlTable` | DataTable | 18 |
| `Asset/Data/Table/Customized/Dress/UGCTemplateRowStruct_DressControlTable` | UserDefinedStruct | 4 列 |
| `Asset/Data/Table/Customized/Dress/DressMaterialTable` | DataTable | 16 |
| `Asset/Data/Table/Customized/Dress/UGCTemplateRowStruct_DressMaterialTable` | UserDefinedStruct | 4 列 |

列结构（两表一致）：`ValueType / Value / Description / ModificationNotes`，四列均 string。

行设计：

- 表一：每行 = 一个控件选项。`Value` = 目标控件名，`Description` = 选项中文名，`ModificationNotes` = 界面归属与核验状态。另各界面各带 `Name`（界面中文名）与 `WidgetPath`（蓝图相对路径）两行，供脚本定位蓝图。
- 表二：每行 = 一个材质。`Value` = 素材相对路径，`Description` = 材质中文名。

## 四、创建过程中解决的问题

### 1. `objed_create_asset` 报 `Cannot get asset handler`

未先 `objed_open_editor('DataTable')` 导致。打开编辑器后两张表连续创建成功。

### 2. 空表格模板给的是单列结构

新建表行为 `MemberVar_0_<GUID>`（单列），不是四列。需 `struct_remove_variable(FGuid)` 删除后 `struct_add_variable(克隆描述体)` 补 4 列。

- 删列入参**必须是 FGuid**，传索引或字符串报 `object is not a FGuid`。
- 用 `v.as_dict()['VarGuid']` 取 `{A,B,C,D}`，再以 `ue.find_struct('Guid')` 实例化构造入参。
- 加列用 `tpl[key].clone()`（克隆现有结构体的变量描述）比手工 `set_field` 更稳。

### 3. `data_table_add_row` 返回 `None`

首轮把返回值当成功判据，误判 18 行全部失败；实际**全部写入成功**。改用 `data_table_as_dict()` 回读确认。此点在知识库《配置表与结构体的 MCP 编辑》中已有记载，本轮因未先回查知识库而重复踩坑。

### 4. 空串在 JSON 里表现为 `None`

未定项 `Value = ''`：MCP 回读为 `''`，UAssetGUI JSON 因零值不序列化读出 `None`。核对脚本需先归一化，否则误报。

### 5. `ue.save_package` 不存在

用对象方法 `dt.save_package()` / `st.save_package()`，或 `ue.objed_save_asset('表名','DataTable')`。
