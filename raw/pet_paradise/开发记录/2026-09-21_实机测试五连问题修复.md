## 二、问题 1 — 房间服务器时间挂满后显示「断开链接」退出游戏，未换房

**现象**：进入玩法挂机约 30 分钟后客户端提示断开链接并退出游戏，未进入新房间。

**根因（代码取证 + 官方依据）**：
- `CF_FWDRPC.ClientDisconnectForGameEnd`（内部调 `UGCGameSystem.DisconnectClient()`）**早已实现，但全工程无任何调用点**。
- `UGCGameState:HandleDSCloseNotify` 只做存档 + `UGCGameSystem.GameOver()`，漏了官方 Wiki `272` 第 4 步要求的客户端 `DisconnectClient`。
- 实机表现为「断开链接」，与官方文档描述的「不调用 `DisconnectClient` 会弹无法连接到服务器」一致。

**修改**：`Script/Blueprint/UGCGameState.lua` → `HandleDSCloseNotify` 在调用 `GameOver()` **之前**，遍历在线控制器并下发 `UnrealNetwork.CallUnrealRPC(notifyController, notifyController, "FWDRPC_Call", "ClientDisconnectForGameEnd", closeReason)`；每个控制器做有效性校验，成功/失败均打印日志。

**未解决部分（需官方确认）**：官方无换房接口，DS 时长由平台控制。本修复只保证客户端干净返回大厅；「DS 到期自动重新匹配」需向官方生态经理申请/确认。

## 三、问题 2【偶现】— 匹配加载后闪退回和平大厅，再次匹配显示「在游戏中」

**现象**：两台设备匹配，加载后闪退回大厅；再次匹配提示已在游戏中。

**根因（推断，尚无日志证实）**：
- `UGCGameState:BroadcastServerRemainingTime` 旧逻辑为「`remainingSeconds <= 0` 即 `HandleDSCloseNotify(0)`」→ 存档 + `GameOver()` 踢人。
- `ReceiveBeginPlay` 在服务端**开局第一帧**就调用了一次该函数（无 override，直接读 `UGCGameSystem.GetDSRemainingTime()`）。若开局瞬时读到 0（剩余时间信息未就绪），开局阶段就立刻结束对局并踢人 → 表现即「加载后闪退回大厅」，偶现符合竞态特征。

**修改**：新增关服判定门槛，避免开局零值误清服。
- 模块级常量 `DS_ZERO_STREAK_BEFORE_CLOSE = 2`。
- `BroadcastServerRemainingTime` 累计 `self._dsZeroRemainingStreak`；只有满足「**曾读到过正数剩余时间**（证明接口可用）+ **连续两次**读到非正数」才调 `HandleDSCloseNotify`。
- 官方 `DSCloseNotify` **事件来源是权威信号，不受门槛限制**（`HandleDSCloseNotify(remainingTimeData, fromEvent)`，事件监听处传 `true`，并置 `self._dsCloseNotifiedByEvent=true`）。
- `ReceiveBeginPlay` 服务端分支初始化 `_dsRemainingTimeEverPositive=false`、`_dsZeroRemainingStreak=0`、`_dsCloseNotifiedByEvent=false`。

**待验证**：若修复后仍复现，则「再次匹配显示在游戏中」属平台侧匹配状态未释放，需官方核查。取证看 `【UGCGameState+BroadcastServerRemainingTime】` 与 `【UGCGameState+HandleDSCloseNotify】` 日志。

## 四、问题 3 — 宠物清理卡使用不扣除道具，可重复使用

**现象**：使用宠物清理卡后数量不减，可无限重复使用。

**根因（项目实测 + 官方依据）**：
- `UGCBattleItem` 行 8310014 的 `ItemHandlePath = HelpLienCard_C`，其 `OnUseV2` 只调 `ActivateShitAutoCleanCard`（限时权益续期），**全程没有任何扣除调用**。
- 该行 `Consumable=false`，引擎不会自动扣（与 2026-09-17 已证伪的「双扣」结论同口径）→ 必然可无限复用。

**修改（仅 `Script/Blueprint/Prefabs/Items/WorkItems/WorkRewardItem/HelpLienCard.lua`）**：
- 新增 `PET_CLEAN_CARD_ITEM_ID = 8310014` 与 `ResolveCleanCardItemID(itemHandle)`（取 `DefineID.TypeSpecificID`，异常回退 8310014）。
- 新增 `ConsumeCleanCard(itemHandle)`：服务端 `HasAuthority` 校验 → 扣除前 `UGCBackpackSystemV2.GetItemCountV2` 读库存 → `UGCBackpackSystemV2.RemoveItemV2(controller, itemId, 1)` → **扣除后回读确认 `removedCount >= 1`**。
- 新增 `function WorkRewardCard:UGC_OnStartUse()` 重置 `self._CleanCardUseSettled = false`（保证一次使用只结算一次）。
- `OnUseV2` 改为**先扣后效**：`_CleanCardUseSettled == true` 则跳过；否则置 true → 扣道具 → 扣失败提示 `PET_CLEAN_CARD_FAIL_TIP` 并 `return false`；扣成功才 `ActivateShitAutoCleanCard`；激活失败则尽力 `AddItemV2` 补回并提示失败。

**回归口径**：使用 1 次后背包数量恰好 -1。

## 五、问题 4 — 开启新对局时排行榜匿名状态重置为关闭

**现象**：设置匿名上榜 → 退出游戏 → 重进，匿名开关回到关闭。

**根因（推断 + 代码证据）**：
- 匿名配置只存在排行榜模板的全局 Actor（`UGCGamePartSystem.GetGamePartGlobalActor("RankingListManager")` 的 `GetRankListPrivacyByUID` / `SetRankListPrivacy`）内。
- 该 Actor 随 DS 重建，新对局读回默认值 0（官方模板文档：默认非匿名）。

**修改**：新增 `Script/Common/Utils/RankPrivacyHelper.lua` 做 UID 级持久化。
- 常量：`ARCHIVE_KEY = "RankListPrivacyState"`、`GAME_PART_NAME = "RankingListManager"`、`RESTORE_RETRY_DELAY_SECONDS = 1`、`RESTORE_MAX_RETRY_COUNT = 8`。
- `GetGlobalActor()`：容错取全局 Actor（`UGCGamePartSystem.IsGamePartLoaded` / `GetGamePartGlobalActor` + `UE.IsValid`）。
- `CaptureIntoArchive(playerData, playerController)`：在最终存档时把全局 Actor 的**实际生效值**写入 `playerData["RankListPrivacyState"]`。
- `ReadArchiveState(playerData)` / `RestoreToGlobalActor(playerController, retryCount)`：登录后回填；全局 Actor 未就绪时 1 秒 × 最多 8 次重试；`playerController._RankPrivacyRestored` 保证幂等。
- 存档侧钩子：`Script/gamemode/ControllerExitGame.lua` → `SaveAllPlayerArchive` 在提交 `savedPlayerAttributes` 之前调 `RankPrivacyHelper.CaptureIntoArchive(PlayerData, Controller)`。
- 登录侧钩子：`Script/gamemode/PlayerLogin.lua` → `Execute` 中 `local contextExitTime = tonumber(self.PreciseExitTime)` 之前调 `RankPrivacyHelper.RestoreToGlobalActor(playerController)`。

**边界**：未改 `ExtendResource` 官方排行榜包（避免被资源覆盖）。若后续发现客户端侧全局 Actor 与 DS 侧不同步，再评估在官方包内做最小钩子。

**回归口径**：设置匿名 → 退出 → 重进后仍为匿名。

## 六、问题 5 — 礼包在背包点击「使用」无响应，且与「打开礼包」重复

**现象**：礼包物品的「使用」按钮点击无响应；「使用」与「打开礼包」功能重复。

**根因（代码证据）**：`BP_BackpackUIComponentV2_Custom:CheckUse` 只对 `Fragment` 返回 `false`，`GiftPackage` 仍返回 `true`，于是礼包同时显示「使用」（无实现）与「打开礼包」（`OnClickGiftButton` → `GiftPackManager:OpenGiftPack`）两个按钮。

**修改**：`CheckUse` 对 `CustomType == "GiftPackage"` 返回 `false`（隐藏「使用」按钮），保留 `Fragment → false`、其余 `true`，并补分支日志。只保留「打开礼包」单一入口。
