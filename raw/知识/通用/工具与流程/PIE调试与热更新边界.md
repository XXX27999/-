## 一、三种生效方式

| 生效方式 | 适用场景 |
| --- | --- |
| **必须重新调试 PIE** | 初始化逻辑、`ReceiveBeginPlay`、事件绑定、蓝图 JSON、组件引用、资源路径、加载时机、脚本挂载关系、蓝图结构、配置表 |
| **可尝试热更新** | 仅修改已加载 Lua 脚本中的普通函数体逻辑 |
| **建议重新调试 PIE** | 无法确认热更新是否可靠时的保守选择 |

配置表修改后必须重新 PIE，运行中修改不生效。

---

## 二、PIE 与生产环境的关键差异

**`_G` 隔离**：PIE 是单进程，服务端与客户端共享 `_G`；生产环境双进程各自独立 `_G`。

后果：依赖 `_G` 做跨端查找的逻辑在 PIE 完全正常，上线后表现异常（仓库 3D 预览模型双创建就是这类问题）。这类 bug **无法靠 PIE 复现**，只能靠架构上避免跨端 `_G` 依赖。

## 三、PIE 失败排查

`raw/docs/wiki/常见问题/20391_PIE调试失败原因与解决方案.md` 按九个阶段列出错误码原文：

1. 入口阶段：调试次数耗尽、前置检查失败、非法资产类型、DS 线程创建失败、SubModeID 不存在、拷贝工程失败、文件名校验失败、Lua 文件校验失败、Survive/WinServer 目录或 exe 无效。
2. 权限与版本：人脸验证未通过、账号无调试权限、编辑器版本过低。
3. 压缩与上传：缺 umap/ugcproj、文件夹只读、7z 进程或返回码错误、zip 完整性校验失败。
4. 上传凭证：频率过快、日上传上限、Ticket 仍有效、申请次数上限、无开发权限、版本不匹配。
5. 上传流程：分片上传、读文件、列举分片、完成分片失败。
6. DS 启动与下载：下载启动失败、`DS Failed!`、启动调试请求失败。
7. 调试状态查询：**Lua 中存在非法 API 调用**、工程含非法文件类型。
8. 账号限制：账号封禁、无法调试。
9. Job 任务：错误码与提取上传信息失败。

其中第 7 类（非法 API、非法文件类型）与代码直接相关，出现时需按提示删除对应调用或文件。

## 四、证据分级

- 静态语法通过 ≠ 运行正确。
- 蓝图 CDO 回读成功 ≠ 运行行为正确。
- API 文档命中 ≠ 当前场景可用。
- 新增生命周期函数、Tick、复制属性响应或伤害覆写后，必须重新 PIE，不能把热更新当可靠验证。
- 最终结论需 PIE 验收 + 客户端与 DS 日志共同支撑；未捕获到定向日志时，不能声称「日志已确认」。
