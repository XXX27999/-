## 二、官方通道与硬约束（已核实）

- **唯一推荐通道**：客户端 Lua `UGCTweenSystem`（1.36 新增）。不再自建逐帧 Tick。
- **仅客户端**：Wiki 明确「Tween动画只在客户端生效」。服务端金币/仓库/出价仍走权威逻辑，禁止用 Tween 改权威数据。
- 可用函数：`TweenFloatValue` / `TweenVectorValue` / `TweenColorValue` / `TweenRotatorValue` / `TweenActorLocation` / `TweenActorRotation` / `MakeConfig` / `ConfigureTween` / `ChainTween` / `PauseTween` / `ResumeTween` / `KillTween` / `IsTweenValid` / `BindCompletedDelegate`。
- `MakeConfig(Delay, RepeatCount, bYoyo, RepeatDelay)`；`RepeatCount` 必须显式传（0=一次，-1=无限），默认 1 不可依赖。
- 回调签名固定 `function(Object, Value)`，当前值在**第二个**参数。
- **缓动枚举按 API 名写**：`Linear/QuadIn/QuadOut/QuadInOut/Cubic*/Quart*/Quint*/Sine*/Expo*/Circ*/Elastic*/Back*/Bounce*`（共 31 值）。
  官方 Wiki 示例里的 `EEasingType.EaseOutQuad` / `EaseInQuad` / `EaseInOutQuad` **与 API 枚举名冲突**，代码一律用 `QuadOut` / `QuadIn` / `QuadInOut`。
- **旋转**：用 `UWidget.SetRenderAngle(float)`（官方确认）。本地 API 中**查无 `SetRenderTransformAngle`**，而现有 `UIAnimationManager.EffectStrategies.Rotate` 正调用后者 —— 该策略当前无人使用故未暴露；启用前须先改正。
- `SetRenderScale(FVector2D)` / `SetRenderTranslation(FVector2D)` / `SetRenderTransformPivot(FVector2D)` / `SetRenderOpacity(number)` 均官方确认。
- `UGCMathUtility.MakeVector2D(X, Y)` 官方确认。
- `UButton` 具备 `OnClicked` / `OnPressed` / `OnReleased` / `OnHovered` / `OnUnhovered` / `OnPressedParam` / `OnReleasedParam` 事件。

### 致命陷阱：一个句柄只允许 KillTween 一次

- 第 2 次 `KillTween` 触发 `Map.h:586` 断言 `Pair != nullptr` → 客户端弹 Assert 卡住数秒 → `appError` 闪退。项目群已实测（见通用知识页）。
- `IsTweenValid` **不能**当唯一防线（句柄已销毁后仍可能返回 true），必须自建「已销毁」标记。
- 不在完成回调里 Kill 自己；回调内只做视觉复位与清引用。
- 共享句柄写法：挂在「组对象」`{ Handle=H, Killed=false }`，销毁先判组，持有者只置 nil。

内置的工程防护（对应本项目已实测的坑）：

1. **句柄组防二次 Kill**：所有 `FTweenHandle` 包在 `{ Handle, Killed, Finished }` 里，`KillGroup` 先判 `Killed`；完成回调内只置空引用、绝不自 Kill，从结构上规避 `Map.h:586` 断言。
2. **同属性不并行**：按 `owner + 控件 + 属性` 分键，起新动画前先 `KillByKey`，避免同一属性多 Tween 冲突。
3. **缓动名冲突兼容**：`ResolveEasing` 同时尝试 `QuadOut` 与 Wiki 写法 `EaseOutQuad`，命中即缓存；全部未命中才印错并放弃该动效，不传 nil 进引擎。
4. **服务端拦截**：每个公开 API 首行判 `Owner:HasAuthority()`，服务端调用**印错后返回**，不做静默退出。
5. **降级通道**：`SetReducedMotion(true)` 直接把终值写入（不插值）；`PlayAttention` 受 `LoopMaxActive=8` 限流，默认只往返 2 次。
6. **接口缺失逐项降级**：`OnHovered/OnUnhovered/OnPressed/OnReleased` 缺哪个就印哪条警告，其余状态照常工作（为 `UImage + OnMouseButtonDownEvent` 类控件预留）。

### 接入示例（以 `ShanDian_*` 顶栏三页签为例）

```lua
local UIMotionKit = require('Script.Common.UI.UIMotionKit')

function ShanDian_FL:Construct()
    -- 既有业务绑定保持不变
    self.ChonWuButton_173.OnClicked:Add(self.ChonWuButton_173_OnClicked, self);
    self.DaoJuButton_174.OnClicked:Add(self.DaoJuButton_174_OnClicked, self);
    self.FuLiButton_175.OnClicked:Add(self.FuLiButton_175_OnClicked, self);

    -- 仅新增动效绑定：三页签共用同一套令牌与状态矩阵
    UIMotionKit.BindButton(self, self.ChonWuButton_173, { ExtraKey = "tab-cw" })
    UIMotionKit.BindButton(self, self.DaoJuButton_174, { ExtraKey = "tab-dj" })
    UIMotionKit.BindButton(self, self.FuLiButton_175, { ExtraKey = "tab-fl" })
end

function ShanDian_FL:Destruct()
    -- 控件销毁前必须停掉本宿主下的全部 Tween，避免句柄悬挂
    UIMotionKit.Release(self)
end
```

### 12.4 本批发现并修复的两处库缺陷

1. **入退场缩放键不一致（并发缺陷）**：`PlayPanelOpen` 用 `scale:panel-open`、`PlayPanelClose` 用 `scale:panel-close`，两者键不同 → 退场不会被 `StartTween` 的 `KillByKey` 预先杀掉入场缩放，同一属性可能出现两个 Tween 同时写 `SetRenderScale`，绕开了「同属性不并行」防线。已统一为 `scale:panel`。已核实 `KillGroup` **不触发**完成回调，因此该改动不会导致回调提前触发。
2. **缩放枢轴**：渲染缩放默认绕控件**左上角**发生，弹窗会「自左上角放大」而非方案描述的从中心放大。已按官方 `UWidget.md#SetRenderTransformPivot` 在入/退场前设枢轴 `(0.5, 0.5)`，并可用 `Options.CenterPivot = false` 关闭；动画结束缩放必回 `1.0`，此时枢轴不残留观感影响，故不复位。
