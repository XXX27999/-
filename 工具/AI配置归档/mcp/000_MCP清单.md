**已删除的重复注册（2026-09-16）**：`~\.workbuddy\connectors\default\mcp.json` 中原本也有一条 `ugcaskq`，类型为 **stdio**（`mcp-remote.cmd` 桥接，`timeout=120000`、`disabled=false`）——与第 1 条**端点相同但传输方式不同**。判定为重复并删除，依据三条：

### 1.3 端口与连通性排障

端口固定为 `12463`，因此排障只需**确认服务在线**，不需要每次重新发现端口；但若 `ue_py`、`ue_read` 等工具不可用，仍按 `oasis-mcp-port-discover` 技能的只读复核流程走一遍（`netstat` 定位监听 + Python 直连 SSE 完成 JSON-RPC 握手）。

```powershell
# 确认 12463 是否在监听，以及监听进程
Get-NetTCPConnection -LocalPort 12463 -State Listen -ErrorAction SilentlyContinue |
  Select-Object LocalAddress,LocalPort,OwningProcess
```

> **注意**：端口虽是固定值，但仍以**编辑器 MCP Server 控制面板实际显示的 Port** 为准；若面板值被改动，**两处配置**（`~\.workbuddy\mcp.json`、`~\.codex\config.toml`）需同步改（`connectors\default\mcp.json` 里的那条已于 2026-09-16 去重删除）。`oasis-mcp-port-discover` 技能原文中「实际端口随编辑器实例分配」的表述已于 2026-09-16 订正。

## 五、恢复步骤

1. 先备份现网配置：`Copy-Item ~\.workbuddy\mcp.json ~\.workbuddy\mcp.json.bak-<日期>`。
2. 按需还原：
   - WorkBuddy MCP 主配置 → `Copy-Item .\workbuddy\01_workbuddy_mcp.json "$env:USERPROFILE\.workbuddy\mcp.json" -Force`
   - Codex MCP/模型 → 手工合并 `.\codex\01_codex_config.toml` 的 `[mcp_servers.ugcaskq]` 段到现网 `config.toml`（**不要整文件覆盖**，现网还含 `[projects.*]` 信任列表与 `[windows]` 段）。
3. 重启对应客户端。
4. 用 `oasis-mcp-port-discover` 只读复核服务在线（端口固定为 `12463`），`ue_read` 可正常返回即视为恢复成功。
