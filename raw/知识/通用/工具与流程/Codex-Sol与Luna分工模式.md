# Codex Sol 与 Luna 分工模式

> 内容层：Codex 主线程与子代理的任务边界和复核流程
> 来源：本次会话（2026-08-27）；本机全局规则、配置和第三方经验记录。
> 官方依据：本次未取得可直接引用的 OpenAI 官方页面；第三方文章中的性能、成本、默认参数和内置 Agent 陈述不得作为官方事实。

## 核心结论

1. 主线程负责需求理解、任务拆解、风险判断、证据复核、冲突处理和最终汇总。
2. 子代理只处理边界清晰、可独立验证的任务，例如定向搜索、只读调用链梳理、测试、日志整理和文档摘录。
3. 推荐闭环为：主线程规划 -> 子代理执行 -> 返回绝对路径和验证证据 -> 主线程复核并答复。
4. 多代理并行适合只读任务；多个代理不得同时修改同一 Lua、蓝图或配置表。
5. 当前全局规则要求子代理继承父线程模型；只有用户明确要求 Sol + Luna、点名 Luna 或授权模型分工时，才允许使用 Luna 模型。
6. 第三方文章中的成本、排行榜、套餐倍数、并发数和配置字段均须保留为待查证信息。

## 可执行步骤

1. 先由主线程检索知识库、官方资料和项目上下文，确定任务边界。
2. 委派时明确输入、允许修改的路径、禁止事项、输出格式和验证命令。
3. 子代理返回完成结果、绝对路径、关键符号或行号、验证输出、未解决问题和风险。
4. 主线程检查文件状态、差异和验证证据；失败时只下发最小范围返工指令。
5. 蓝图、组件和配置表写入仍必须由主线程遵守 Resolve -> Plan -> Execute 和回读规则，不能用子代理绕过。

## 常见错误

- 让子代理自行扩大范围或未经复核直接采纳结果。
- 并行修改同一文件、蓝图或 DataTable。
- 把第三方文章当作官方模型性能或价格保证。
- 让子代理绕过知识库检索、官方 API 查证、MCP PRV 或端侧安全规则。
- 未明确模型继承规则就私自切换模型。
