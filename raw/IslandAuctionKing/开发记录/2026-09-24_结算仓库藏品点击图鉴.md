## 一、需求

结算界面右侧仓库已经逐件展示藏品图片。点击某件已展示藏品时，应打开藏品图鉴，并自动按该藏品的条件筛选，复用竞拍阶段「点击右侧仓库已知藏品打开图鉴」的逻辑。

## 二、现有可复用链路

| 位置 | 作用 |
| --- | --- |
| `Script\Function\AuctionCollectibleCodexFilterService.lua` 的 `OpenForWarehouseItem(widget, itemIndex)` | 按仓库藏品索引构造已知条件，调用 `CollectibleCodexUIService.CreateAndShow` 打开图鉴并筛选 |
| `Script\Function\AuctionTestUIService.lua` 的 `OnCollectibleClicked` | 竞拍阶段参考实现：取显示槽对应索引，写入选中态后调用上述服务 |
| `CollectibleCodexItemUI` | 结算覆盖层复用的单格控件，内部已有 `ItemButton` 可作为点击层 |

## 三、实现

### 结算图鉴筛选上下文

新增 `BindCodexFilterContext(widget, playerController, settlementItems)`：

- 读取 `GameState.AuctionPublicState` 与 `PlayerController.AuctionPrivateState`。
- 结算阶段强制筛选上下文使用公开终局阶段 `AuctionConfig.Phase.Ended`，使 `AuctionCollectibleCodexFilterService.BuildKnownInfoFilter` 走公开完整信息分支。
- 先以结算藏品 `Index` 建立 `AuctionItemByIndex`，再用公共仓库 `Warehouse.Items` 覆盖同索引项。
- 绑定 `AuctionPlayerController`、`AuctionGameState`、`AuctionPublicState`、`AuctionPrivateState`、`AuctionItemByIndex`。
- 在 `StartShowcase` 完成 `widget.WarehouseItems` 排序后调用。

### 结算覆盖层点击

新增 `OpenCodexForSettlementItem(widget, item)`：

- 从结算藏品取 `Index` 与 `ID`。
- 索引缺失时按 `ID` 反查公开索引；仍缺失时使用结算 RPC 携带的公开藏品对象兜底。
- 调用 `AuctionCollectibleCodexFilterService.OpenForWarehouseItem(widget, itemIndex)`。

筛选边界（项目代码核对）：`AuctionWarehouseService.BuildRevealedPublicWarehouse` 为控制 RPC 体积，只下发 `Index / ID / Name / Quality / Valuation / Cells`，不下发 `Type / Shape / SlotCount`。因此结算点击走公开分支时，筛选服务从公开对象中最多能复制 `ID / Name / Quality / Valuation` 与由 `Cells` 推导的 `SlotCount`；`Type / Shape` 不会作为自动筛选条件。若后续要求结算点击必须按类型和形状筛选，需要先单独评估 RPC 体积与分片方案，不能在本轮 Lua 改动中假设字段存在。

调整 `ConfigureImageOnlyWidget(displayWidget, width, height, allowClick)`：

- 藏品覆盖层：根控件与 `ItemButton` 使用 `ESlateVisibility.Visible`，`ItemButton` 背景全透明，`ItemImage` 保持 `HitTestInvisible`。
- 揭示动画层：根控件与 `ItemButton` 保持 `HitTestInvisible`，不参与点击。

`CreateOverlayWidgetForItem` 绑定 `ItemButton.OnClicked`，回调保存到 `overlayWidget.SettlementClickCallback`。新增 `DestroySettlementOverlay`，在重建、启动、关闭流程中统一解绑回调并移除控件，避免重复构建后残留点击回调。
