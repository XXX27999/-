## 1. 现象

- 客户端 LuaLog 由上一轮的 ~5.7 MB 暴涨到 **33.9 MB + 32.5 MB（约 11 倍）**。

## 2. 根因

**结算网格「总行数」被配成 6，而竞拍仓库真实网格是 6 列 × 14 行。**

配置表权威回读（UGCAskQ MCP `ue_py`，2026-09-22）：

| 表 | 行名 | 值 | 表内描述 |
|---|---|---|---|
| `Customized/Gameplay/GameplayConfigTable` | `Gameplay.Warehouse.GridColumns` | **6** | 竞拍仓库网格列数，与结算仓库共用 |
| `Customized/Gameplay/GameplayConfigTable` | `Gameplay.Warehouse.GridRows` | **14** | 竞拍仓库网格行数，**与结算仓库共用** |
| `Customized/AuctionGlobalConfigTable` | `UI.SettlementWarehouse.GridRows` | **6**（错） | 结算仓库行数 |
| `Customized/UI/UIConfigTable` | `UI.SettlementWarehouse.VisibleRows` | 6 | 滚动视口一次可见行数；**小于网格总行数时出现纵向滚动条** |

即：填表时把「可见行数 6」误填进了「总行数」。`UI.SettlementWarehouse.VisibleRows=6` 已独立承担可见行数语义，`GridRows` 应为总行数 14。

代码回退值本身是对的 —— `AuctionSettlementUIService.lua:47`：

```lua
local rows = math.max(1, math.floor(AuctionConfig.GetNumber("UI.SettlementWarehouse.GridRows", AuctionConfig.GetGridHeight())))
```

`AuctionConfig.GetGridHeight()` 读 `Gameplay.Warehouse.GridRows` = 14；但表里显式写了 6，覆盖了正确回退值。

### 2.1 数据链路证据

服务端（DS 日志，权威）：

```

【AuctionConfig+LoadGameplayConfigTable】关键数据 rowName=Gameplay.Warehouse.GridColumns valueType=int value=6
【AuctionConfig+LoadGameplayConfigTable】关键数据 rowName=Gameplay.Warehouse.GridRows    valueType=int value=14
```

→ 藏品占位按 **6 × 14** 生成，Y 坐标可达 13。

【AuctionSettlementUIService+ResolveSettlementOverlayLayout】关键数据 ... gridSize={X=728,Y=728} ...
```

→ 结算网格只建 **36 格**，只认 `0 <= Y < 6`。

### 2.3 失败放大链

```
部分藏品占格全在 Y>=6
  → CreateOverlayWidgetForItem「藏品没有有效格」→ 出口 success=false
  → BuildSettlementOverlays「错误 覆盖层创建不完整 createdCount=16 itemCount=26」→ 出口 success=false

## 3. 修复方案

### P0 配置（根因）— 已落地

1. `Asset/Data/Table/Customized/AuctionGlobalConfigTable`
   - `UI.SettlementWarehouse.GridRows`：`6` → **`14`**（回读确认 `['int','14']`）。
   - `Description` / `ModificationNotes` 改写，显式写明「必须等于 `Gameplay.Warehouse.GridRows`；可见行数走 `UIConfigTable` 的 `VisibleRows`，不要填可见行数」。
   - `GridSlots`：`36` → **`84`**（回读确认 `['int','84']`）。
   - 回读 `totalRows=150`，无行丢失。
2. `Asset/Data/Table/Customized/UI/UIConfigTable`
   - 新增 `UI.SettlementWarehouse.MaxOverlayBuildAttempts = 3`（回读确认 `['int','3']`，`totalRows` 331→332）。
   - 注：`data_table_add_row` 返回 `None` 而非 `True`，**必须靠回读确认**，不能信返回值。

### P1 代码健壮性（`Script/Function/AuctionSettlementUIService.lua`）— 已落地

改动后 1860 行 / 113,358 B（改前 1808 行 / 107,932 B）。

1. `CreateOverlayWidgetForItem`（原 L1038-1055）：越界格不再导致整件丢弃。
   先收集有效格；若**全部**越界，则把坐标 `clamp` 回 `[0, columns-1] / [0, rows-1]` 再建层，并打印
   `分支 全部占格越界已裁剪进网格 clampedCount=N`；部分越界则按有效格建层并打印
   `分支 部分占格越界已按有效格建层 invalidCellCount=N`。仅当 `Cells` 完全没有可解析数字时才返回 false。
2. `BuildSettlementOverlays`：不再无限重试。
   入口 `widget.OverlayBuildAttempts = (widget.OverlayBuildAttempts or 0) + 1`；失败时若
   `attempts >= maxAttempts`（配置 `UI.SettlementWarehouse.MaxOverlayBuildAttempts`，回退 3），
   **保留已建成的覆盖层**、`PendingOverlayBuild = false`、打印 `分支 已达重试上限，按已建成覆盖层降级展示`
   并返回 `true`；未达上限才回滚重试。成功时 `OverlayBuildAttempts` 归零。
3. `ShowNextItem`：覆盖层降级展示时若某件没有 `OverlayWidget`，只累加数值不再 `error`，
   避免展示流程整条卡死（原路径会走 `ApplyLeaderFollowerLayout` 返回 false → `error("ShowcasingLayoutApplyFailed")`）。
4. `GetSettlementMetrics`：新增一次性告警（`SETTLEMENT_METRICS_WARNED` 守卫，避免每帧刷屏）——
   `rows < VisibleRows` 与 `rows ~= AuctionConfig.GetGridHeight()` 时各打一条错误日志，并打印
   `关键数据 grid=CxR visibleRows=N`。
5. 常量注释订正：`DEFAULT_SETTLEMENT_GRID_COLUMNS/ROWS` 标注为「仅供 layout 字段缺失兜底，
   总行数以 `GetGridHeight()` 为准」，消除把 6 当行数配置的误导。
