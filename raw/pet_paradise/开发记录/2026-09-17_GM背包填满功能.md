## 二、填充算法（关键设计）

官方依据（`UGCBackpackSystemV2.md`）：

- `AddItemV2(Player, ItemID, Count)`：服务器，返回**成功添加的物品数量**与新建分堆实例 ID；优先合并已有堆叠，堆叠超过上限才分堆占新格。
- `IsCellCapacityFull(Player)`：服务器&客户端，背包格子是否已满（客户端数据可能滞后）。
- `GetCellItemCount` / `GetCellCapacity` / `GetMaxCellCapacity`：占格数、已解锁容量、容量上限。
- 货币类物品与 attach/装备类物品**不占背包格子**。

因此「只加一个道具 ID」无法填满（会持续合并到同一堆叠），实现采用：

1. 轮换道具 ID 列表投放，单个 ID 堆叠用尽后自动换下一个继续占格；
2. 每轮投放量 = `剩余空格数 × 20`，上限 400、下限 1，一次调用即可把堆叠填满并分堆；
3. 每次添加前查 `IsCellCapacityFull`，为 true 立即停止；
4. 终止兜底：某轮所有道具 `AddItemV2` 返回 0（判定无法继续）、累计调用上限 600、最大轮换轮数 60；
5. 全程 pcall 保护，接口查询失败只打警告日志不中断。

默认道具池（工程内已确认存在的占格道具）：8310044/8310045/8310046（基础清理/喂食/互动）、8310052/8310053/8310054（高级喂食/清理/互动）、8310012（打工翻倍卡）、8310013（完美打工卡）。

## 三、GM 面板入口

「自定义GM / 道具调试 / 背包填满测试」：

| 控件 | 命令 | 说明 |
| --- | --- | --- |
| 按钮 | `S_FillBackpack` | 默认道具池填满背包格子 |
| 文本输入 | `S_FillBackpackByItem` | 参数：道具ID（多个用逗号分隔，如 `8310044,8310045`）；先用指定道具占格，堆叠用尽后自动用默认池补齐 |
| 按钮 | `S_PrintBackpackCells` | 打印已占格子/已解锁容量/容量上限/是否已满 |

## 五、待查证 / 未覆盖

1. 各道具的堆叠上限未从官方 API 查到获取接口，投放量用「剩余空格 × 20」估算；若某道具堆叠上限极大，填满所需轮数会增加（有 600 次调用上限兜底）。
2. 本轮未实现「清空背包」配套指令，测试满包后需手动清理或再补 GM 指令。
3. `IsCellCapacityFull` 在客户端数据可能滞后，本实现全部走服务端，未验证 DS 环境下多玩家并发的表现。
