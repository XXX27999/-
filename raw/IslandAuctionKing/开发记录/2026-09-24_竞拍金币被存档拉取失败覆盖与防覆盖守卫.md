## 一、现象

用户反馈：竞拍获取与扣除的金币不会影响玩家金币数据。表现是局内可能显示金币变化，但重开或下一局后金币仍回到默认值或没有变化。

## 二、根因

同日两次 PIE/DS 日志与本地存档对照后确认，结算公式本身不是根因，根因在存档读取时序：

1. 失败局 `2026.09.24-14.19.43_ds__dkck7psp70fmo9_realtime.log`：
   - 启动早期出现 `Failed to read chunk data ... RetryCount 1/3、2/3、3/3`，随后 `Max retry count reached`。
   - `GetPlayerArchiveData` 读到的总存档为空。
   - `NormalizeArchiveData ... sourceVersion=0` 使用默认 `InitialGold=30000`。
   - `LoadOrReconnectPlayer ... Gold=30000`，之后 `SavePlayer` 又把 30000 写回存档。
2. 成功局 `2026.09.24-14.21.19_ds__dkck7psp70fmoa_realtime.log`：
   - 启动早期 `Stored legacy data for UID:10001`，读到 `Gold=29500`。
   - 落盘文件 `Saved\ArchiveData\IslandAuctionKing\10001.json` 实际也是 `Gold=29500`。

因此“金币不会影响玩家金币数据”的真实链路是：真实存档 29500 → 分块拉取失败 → 读表为空 → 默认 30000 → 本局以 30000 结算 → 保存 30000 覆盖真实值。

## 三、修复

文件：`Script/Function/AuctionPlayerService.lua`

### 3.1 读档状态判定

新增模块级辅助：

- `HasGameArchive(totalArchive)`：判断总存档中本玩法键 `IslandAuctionKing` 是否存在且非空。
- `GetArchiveByteSize(numberUID)`：用官方 `UGCPlayerStateSystem.GetPlayerDataSize(uid)` 读取服务端存档总字节数，异常返回 `nil`。

`LoadOrReconnectPlayer` 增加判定：

```lua
local hasGameArchive = HasGameArchive(totalArchive)
local hasAnyArchiveData = next(totalArchive) ~= nil
local archiveByteSize = GetArchiveByteSize(numberUID)
local archiveReadFailed = not hasGameArchive and not hasAnyArchiveData and archiveByteSize ~= nil and archiveByteSize > 0
local archiveStateUnknown = not hasGameArchive and not hasAnyArchiveData and archiveByteSize == nil
local archiveMayCreate = not hasGameArchive and (archiveByteSize == 0 or hasAnyArchiveData)
if archiveReadFailed or archiveStateUnknown then
    return nil, archiveReadFailed and "ArchiveReadFailedWithServerData" or "ArchiveStateUnknown"
end
```

语义：

- `archiveByteSize == 0`：服务端明确无存档，允许新玩家创建。
- `archiveByteSize > 0` 但整表读空：判为拉取失败，拒绝进入本局，避免以 30000 继续结算。
- `GetPlayerDataSize` 异常：状态未知，保守拒绝。
- 总存档已有其他玩法键但本玩法键缺失：按首次创建本玩法存档处理。

### 3.2 保存层防线

`SavePlayer` 增加：

- 运行时字段 `ArchiveReadValid` / `ArchiveMayCreate` 记录本玩家是否允许首次创建。
- 读档状态不可信时直接返回 `ArchiveNotLoaded`，不调用 `SavePlayerArchiveData`。
- 保存前重新读取总存档；若本玩法键仍缺失且玩家不允许创建，拒绝覆盖。
- 写入前把运行时金币规范化为非负整数，并记录 `archiveGoldBefore`、`runtimeGold`、`archiveGoldAfter`。
- 首次创建成功后把 `ArchiveMayCreate` 置 `false`，后续只走正常合并保存。

### 3.3 结算日志

保留并增强金币变化日志，便于后续核对：

- `ApplyWarehouseSettlement`：`goldBefore`、`paidPrice`、`reward`、`goldAfter`、`delta`。
- `ApplyLossCompensation`：`compensation`、`goldBefore`、`Gold`、`delta`。
