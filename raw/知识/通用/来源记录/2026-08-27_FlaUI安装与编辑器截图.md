## 2026-08-27 路径驱动截图能力实现

在 `C:\Users\Administrator\.codex\skills\oasis-ui-screenshot` 中扩展 FlaUI helper，新增 `--capture-file` 流程。实现代码位于 `tools/FlaUiCapture/Program.cs`，接口说明位于 `references/file-capture.md`，Schema 位于 `references/file-capture.schema.json`。

- `AssetPath.Parse` 接受 `/<ProjectName>/Asset/<folder>/.../<file>`，兼容 Windows 分隔符、`.uasset` 和常见 `Asset.Asset` 后缀。
- `FileHierarchyNavigator` 按路径自顶向下查找每个父级目录，优先读取 `ExpandCollapsePattern`，其次读取 `TogglePattern`；已展开目录不重复点击；没有可验证状态时返回失败，不盲点。
- 目标文件使用 `ScrollItemPattern` 滚入视图，优先使用 `SelectionItemPattern` 选中，再按实时边界双击激活。
- `RenderWaiter` 在总超时内轮询加载标记，并对新捕获帧的高信号像素指纹计算 SHA-256，忽略低对比度动态水印后要求连续稳定帧才截图。
- `PngVerification` 检查文件、PNG 签名、尺寸和非单色像素；命令以 JSON 返回状态码、输出路径、验证结果和执行日志。

验证结果：`dotnet build -c Release --no-restore` 通过（0 警告、0 错误）；`quick_validate.py` 通过；旧整窗截图入口回归通过（1936x1056 PNG）；无效路径返回 `StatusCode=10` 且不生成文件；语义 UIA 树仍按状态安全展开，自绘资产页由截图验证的 FlaUI 交互兜底；无法从当前自绘页得到唯一结果时返回 `StatusCode=13`，不会盲点。

## 能力边界

语义路径驱动依赖目标编辑器把文件夹、文件及展开状态暴露给 Windows UI Automation；这部分支持任意深度、状态判断和安全展开。当前绿洲编辑器的资产面板部分自绘，未暴露这些节点，因此 helper 对当前可见资产页增加了截图验证的 FlaUI 搜索、单击和双击兜底；当请求路径对应的隐藏父级无法由 UIA 或当前页验证时，仍会失败并记录原因。这不是已确认的 Oasis 原生文件定位 API。
