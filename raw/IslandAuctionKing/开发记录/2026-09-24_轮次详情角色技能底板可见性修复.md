## 一、问题现象

轮次详情弹窗中，左侧「角色技能」橙色标题框正常显示，但其下方承载技能说明文字的深色底板不可见，文字直接透出弹窗背景。用户截图红框处即该缺失底板。

## 二、根因定位

### 2.1 技能说明底板控件

通过 UGCAskQ MCP 读取 `/IslandAuctionKing/Asset/Blueprint/Prefabs/UI/AuctionTestUI` 控件树，确认 `Image_3` 与技能文本 `RoundDetailSecurityText` 同坐标，是技能说明底板：

| 控件 | 类型 | Pos/Size | 设计态 Visibility | ZOrder |
| --- | --- | --- | --- | --- |
| `Image_0`（「选择角色」标题框） | Image | 66,318 146x50 | 4 SelfHitTestInvisible | -5 |
| `Image_1`（角色名底板） | Image | 42,355 204x72 | 3 HitTestInvisible | -10 |
| `Image_2`（「角色技能」标题框） | Image | 66,432 144x50 | 4 SelfHitTestInvisible | -5 |
| **`Image_3`（技能说明底板）** | Image | 42,481 204x88 | **2 Hidden** ← 问题 | -10 |
| `RoundDetailSecurityText`（技能文本） | TextBlock | 45,481 198x83 | 3 HitTestInvisible | 2 |

### 2.2 为什么画刷绑定成功却看不见

`Script/Function/AuctionUITextureReplacementService.lua` 的 `IMAGE_BINDINGS` 已包含 `{widgetName = "Image_3", textureKey = "RoundDetailInfoFrame"}`，运行时日志显示 `ApplyImageTexture widgetName=Image_3 textureKey=AuctionRoundDetailInfoFrame brushOK=true tintOK=true`。

但 `ApplyImageTexture` 只调用 `SetBrushFromTexture` + `SetColorAndOpacity`，**不修改 Visibility**；`Script/Function/AuctionRoundHistoryUIService.lua` 的 `OpenRoundDetail` 也只把 `RoundDetailSecurityText` 设为 `HitTestInvisible`，全程没有任何 Lua 代码改 `Image_3` 的可见性。因此设计态的 `Hidden` 一直保留到运行时，画刷虽然绑上了，控件仍不渲染。

### 3.3 PIE 调试报错（本次修复过程中暴露并一并解决）

第一次重跑 PIE 时上传校验失败：

```
LogUGCKeyLog: Content=$null may contain the following characters: $ , please rename the file or path
LogUGCUpload: CheckName, Operation: CheckUploadFileNameFailed, Result: 10001
LogUGCPIEFlowLog: Error: PIE 调试失败：上传文件名验证失败
LogUGCUpload: CheckLua, Operation: CheckUploadLuaFileValidationFailed, Result: 10001, Parent: CancelDebug
LogUGCPIEFlowLog: Error: PIE debug failed: lua file validation failed, debug interrupted
```

- 根因：PIE 上传目录 `D:\WeGameApps\rail_apps\OasisEraEditor(2001776)\ShadowTrackerExtra\Saved\UGCLinuxDebug\IslandAuctionKing\$null` 残留 0 字节非法名文件（`$` 开头），上传会递归扫描该副本目录，命中非法字符即中断。
- 关键判据：`CheckLua` 失败的 `Parent=CancelDebug`，且 luacheck `ReturnCode: 0`，说明 Lua 本身没有语法错误，只是文件名校验失败后的连锁取消。
- 处理：删除工程根与上传目录两处 `$null`；工程内（排除 `.git`）复扫后仅剩两个既有中文名文件 `海岛竞拍王_绿洲策划案.xlsx`、`全局状态同步档案.md`，二者非本轮产生且此前不阻断 PIE，未改动。

#### 复现来源（后续必须规避）

`$null` 是 PowerShell 下 `... 2>$null` 这类重定向被当成文件名时产生的 0 字节文件，本轮在工程根复现两次（11:49、11:56:53）。注意：在本机工具链里，`exec_command` 用 `bash` 跑含 `2>$null` 的命令时不会重定向，而用 PowerShell 且 `$null` 未被正确解析时就会落成真实文件。规避做法：丢弃输出统一用 `2>&1 | Out-Null` 或 `| Select-Object`，禁止在任何会落到工程根的命令里写 `>$null` / `2>$null`；每次任务收尾用

```powershell
Get-ChildItem -Recurse -Force -File | Where-Object { $_.FullName -notmatch '\\\.git\\' -and $_.Name -match '^[^A-Za-z]' }
```

复扫工程，命中 `$null` 立即删除。
