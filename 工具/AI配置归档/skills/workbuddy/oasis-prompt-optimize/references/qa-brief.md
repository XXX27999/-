# 问答与只读任务精简改写

纯问答、官方 API 查询、日志分析、截图、导图、开发记录先读本页。不要套完整工程改写合同。改写默认在内部完成，再按改写结果调用对应技能并作答。

## 内部精简模板

```markdown
# <一句话问题>

## 目标
<用户真正要的结论、操作或产物；追问时写清相对上一轮是补充、收窄还是改方向>

## 上文继承
- 仍有效：<项目 / 路径 / API / 约束 / 未决项>
- 本轮覆盖：<被当前消息改掉的点>
- 已完成勿重复：<上一轮已经做完的事>

## 检索实体
- 精确符号 / 资产路径 / 错误原文 / 配置行名
- 待补：<缺什么就写什么，不要编造>

## 必读与技能
- L0/L1 入口
- 对应技能：`$oasis-official-docs` / `$sq-skill` / `$ugc-log-bug-analyzer` / `$oasis-ui-screenshot` / `$oasis-image-import` / `$oasis-dev-record`

## 硬约束
- 结论带证据状态；知识库未覆盖必须写明
- 只读任务不改工程、不备份、不写 PIE 成功
- 官方 API 先 verify-api；社区经验标成社区经验

## 验证
- 引用实际命中的本地路径
- 截图/导图/记录类任务写清产出绝对路径
```

## 裁剪规则

- 只答题：不要写备份、MCP Execute、预估成功日志、热更新。
- API 查询：必须带完整符号，禁止用「这个接口」代替函数名。
- 日志分析：保留错误原文和脚本名+函数名；要求 `$ugc-log-bug-analyzer`，禁止粘贴完整 FullLog。
- 截图：只产出 PNG，不改资产。
- 导图：只处理 PNG/JPG/TGA，文件名英文开头。
- 开发记录：仅在用户含 `（记录）` 或明确要求时走 `$oasis-dev-record`。
- 一旦改写后发现其实要改 Lua/蓝图/表，改读对应工程 reference，不要继续用本页。

## 禁止

- 把问答改写成一次大工程改造
- 编造未检索到的 API、路径或日志
- 把项目实测升格为官方确认
- 为了走流程把完整改写合同贴进用户回复
- 追问时丢掉上文已确认的项目、路径、API 或未决项
