1. 知识库根目录固定为 `{{KB_ROOT}}`，入口为 `wiki\000_索引.md`。回答前先检索知识库，但「先检索」不等于读取整库。

### 3.8 RPC 分发标准

1. `CF_KHDRPC` / `CF_FWDRPC` 架构。`UGCPlayerController.lua` 仅留分发器及非 RPC 业务，固定分发器：

   ```lua
   function UGCPlayerController:KHDRPC_Call(f, ...) CF_KHDRPC(f, self, ...) end
   function UGCPlayerController:FWDRPC_Call(f, ...) CF_FWDRPC(f, self, ...) end
   ```

   固定返回值：`GetAvailableServerRPCs()` 返回 `"KHDRPC_Call"`，`GetAvailableClientRPCs()` 返回 `"FWDRPC_Call"`。
2. 互调：`UnrealNetwork.CallUnrealRPC(pc, pc, "KHDRPC_Call", "ServerRPC_XXX", args)` 与 `"FWDRPC_Call"` / `"ClientXXX"`。
3. 严禁 Controller 新增其他 RPC 属性、直接调 `pc:RPC`、在 `KHDRPC` 调 client 专用 API、在 `FWDRPC` 调 server 专用 API。
4. RPC 需用 `self:HasAuthority()` 校验：`KHDRPC` 校验期望为 `true`，`FWDRPC` 校验期望为 `false`，异常端必报错。

### 3.13 配置表驱动开发（项目级规范：`IslandAuctionKing`）

> 启用条件：目标项目为 `IslandAuctionKing`。其他项目按该项目自有规范替换本节。

**按功能分类创建文件夹与配置表（全局强制）**

1. **禁止全部堆放在同一个表中**：后续所有功能脚本变量存入编辑器表中时，必须按功能模块/领域创建独立子文件夹与专用配置表（DataTable）存放，严禁把所有变量都塞在同一个大表（如 `AuctionGlobalConfigTable`）中。
2. **存放目录与命名**：路径规则 `Asset/Data/Table/Customized/<功能模块名>/<功能模块名>ConfigTable`。常用目录：UI `…/UI/UIConfigTable`、玩法与时长 `…/Gameplay/GameplayConfigTable`、结算与补偿 `…/Settlement/SettlementConfigTable`、角色机制 `…/Character/CharacterConfigTable`、情报系统 `…/Intel/IntelConfigTable`、测试与调试 `…/Test/TestConfigTable`。
3. **表结构模版（统一 4 列，全部字符串类型）**：
   - 列 1 `配置类型`（`ValueType`）：`配置值类型：int、float、bool 或 string。`
   - 列 2 `配置值`（`Value`）：`运行时由 AuctionConfig 读取的具体配置值。`
   - 列 3 `配置说明`（`Description`）：`说明配置用途、默认值和修改注意事项。`
   - 列 4 `修改注意事项`（`ModificationNotes`）：`保存配置修改边界、关联依赖和生效方式。`
4. **统一读取与注册**：新建功能配置表后必须在 `AuctionConfig`（或配置加载管理器）中注册读取路径；行名使用稳定英文点号路径（如 `UI.CharacterSlotCount`、`Settlement.LossCompensationRate`）；脚本通过 `AuctionConfig.Get*` 读取，必须提供默认回退值并记录读取日志。
5. **扫描与展开要求**：新增或修改功能脚本时先扫描该脚本内所有可调变量；任何玩法数值、时长、容量、概率、测试开关、UI 尺寸坐标、提示持续时间或资源路径都必须登记到对应功能的 DataTable 中，不得硬编码。Lua 嵌套表和数组必须展开成标量行（如 `Duration.Preparing`、`BidThresholds.1`；数组字符串用逗号分隔）。

**统一读取接口**

```lua
local AuctionConfig = UGCGameSystem.UGCRequire("Script.Function.AuctionConfig")

local slotCount    = AuctionConfig.GetNumber("UI.CharacterSlotCount", 6)   -- 数值配置
local autoRestart  = AuctionConfig.GetBoolean("Test.AutoRestartEnabled", false) -- 布尔配置
local triggerRounds= AuctionConfig.GetString("Intel.PublicTriggerRounds", "1,3") -- 字符串配置
```

**生命周期要求**

```lua
-- ❌ 错误：模块加载时读取，表格系统未就绪，GetNumber 恒返回默认值
local SLOT_COUNT = AuctionConfig.GetNumber("UI.PropSlotCount", 8)

-- ✅ 正确：函数内动态读取
local function GetSlotCount()
    return AuctionConfig.GetNumber("UI.PropSlotCount", 8)
end

function SomeService.Initialize()
    local slotCount = GetSlotCount()
    ugcprint("【SomeService+Initialize】关键数据 slotCount=" .. tostring(slotCount))
end
```

**生命周期与端侧**

1. 配置表在 `UGCGameState:ReceiveBeginPlay` 表格系统准备完成后由 `AuctionConfig.LoadFromTable`（或对应模块加载器）显式加载；模块加载阶段不得提前读取运行时表格。
2. 服务端和客户端各自从本地表格加载配置，不需要 RPC 同步。
3. 服务端逻辑必须保留 `HasAuthority` 校验；客户端只读取配置，不得通过配置表修改服务端权威数据（金币、仓库、出价）。
4. 配置读取失败时必须打印以【脚本名+函数名】开头的错误日志，并使用默认值或明确失败，不得静默吞错。

**常见错误**

- ❌ 将所有功能配置堆在同一个大表（`AuctionGlobalConfigTable`）；✅ 按功能域在 `Asset/Data/Table/Customized/<Domain>/` 建专用表并注册。
- ❌ 模块加载时读取配置；✅ 函数内读取。
- ❌ 硬编码 UI 布局常量（`local INFO_CARD_WIDTH = 677`）；✅ `AuctionConfig.GetNumber("UI.InfoCard.Width", 677)`。
- ❌ 对纯算法常量（如 PI、UTF-8 掩码）、不影响玩法/布局/测试行为的固定值使用配置表。

**验证**：修改普通 Lua 函数体后可热更新；涉及配置表、初始化、组件、事件或蓝图结构时必须重新调试 PIE；配置表修改后必须重新调试 PIE，PIE 运行中的修改不会生效；提交前执行 Lua 语法检查并核对配置行名与 `AuctionConfig.Get*` 路径一致。

**详细规范**参见 `Script/Function/CONFIG_STANDARDS.md`。

### 3.14 模型与子智能体调用规范

1. 默认始终使用用户当前选择的模型，严禁私自切换或调用其他模型。
2. 派生子智能体时必须继承当前选择的模型，不得显式覆盖模型。
3. **模型名必须运行时查询，禁止硬编码**：源提示词中出现过的具体模型名只是历史样本，不是当前值；派发前先读客户端实际生效的模型配置，再原样传递。
4. 若客户端具备多开线程派发能力：派发新任务必须显式传 `model`（继承父级）与思考档位；等待任务用批量等待并注意超时上限；派发后须划清文件边界，并周期性检查子任务状态，全部完成后由主对话汇总改动路径、验证结果与生效方式。多任务改同一工程 `.uasset` 时需提示用户编辑器可能被并发连接，冲突时改串行或错开执行。
