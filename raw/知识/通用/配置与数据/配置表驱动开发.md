# 配置表驱动开发

> 来源：`raw/docs/ai/20260824_图鉴UI素材批量导入与视觉优化.md`（IslandAuctionKing 实践）  
> 官方参考：`raw/docs/wiki/绿洲编辑器基础内容/20414_UGCAskQ MCP 使用说明.md`（数据表能力）

---

## 一、目标

玩法数值、时长、容量、概率、测试开关、UI 尺寸坐标、提示时长、资源路径一律进配置表，脚本里不留硬编码。

---

## 二、按功能域分表

严禁所有配置堆在同一张大表。路径规则：

```
Asset/Data/Table/Customized/<功能模块名>/<功能模块名>ConfigTable
```

常用分域：`UI/`、`Gameplay/`、`Settlement/`、`Character/`、`Intel/`、`Test/`。

行名使用稳定的英文点号分层，如 `UI.InfoCard.Width`、`UI.Codex.ItemWidth`、`Settlement.LossCompensationRate`、`Intel.PublicTriggerRounds`、`Test.AutoRestartEnabled`。Lua 嵌套表与数组要展开成标量行（`Duration.Preparing`、`BidThresholds.1`；数组值用逗号分隔）。

---

## 三、统一 4 列结构（全部字符串类型）

| 列名 | 内部字段 | 含义 |
| --- | --- | --- |
| 配置类型 | `ValueType` | `int` / `float` / `bool` / `string` |
| 配置值 | `Value` | 运行时读取的具体值 |
| 配置说明 | `Description` | 用途、默认值、修改注意 |
| 修改注意事项 | `ModificationNotes` | 修改边界、关联依赖、生效方式 |

新表建好后必须在配置加载管理器（如 `AuctionConfig`）中注册读取路径。

---

## 四、生命周期铁律：函数内读取

配置表在 `UGCGameState:ReceiveBeginPlay` 表格系统就绪后才由加载器显式加载。模块加载阶段读取只会拿到默认值。

```lua
-- ❌ 模块加载时读取，永远是默认值
local SLOT_COUNT = AuctionConfig.GetNumber("UI.PropSlotCount", 8)

-- ✅ 模块级辅助函数，运行时才读
local function GetSlotCount()
    return AuctionConfig.GetNumber("UI.PropSlotCount", 8)
end

function SomeService.Initialize()
    local slotCount = GetSlotCount()
    ugcprint("【SomeService+Initialize】关键数据 slotCount=" .. tostring(slotCount))
end
```

读取接口按类型区分：`GetNumber` / `GetBoolean` / `GetString`，每次都要给默认回退值，并打印读取日志。

---

## 五、端侧规则

- 服务端与客户端各自从本地表格加载，不需要 RPC 同步。
- 服务端逻辑保留 `HasAuthority` 校验，见 [端侧权威与 HasAuthority](../程序与网络/端侧权威与HasAuthority.md)。
- 客户端只读配置，不得通过配置表修改服务端权威数据（金币、仓库、出价）。
- 读取失败必须打印 `【脚本名+函数名】` 开头的错误日志，再走默认值，不得静默吞错。

## 六、写入方式

配置表属于资产，修改前备份到知识库备份目录，走 UGCAskQ MCP 的 Resolve → Plan → Execute，写后立即回读表结构、行名、类型与值。示例：

```python
import unreal_engine as ue
from unreal_engine.classes import DataTable

table_obj = ue.load_object(DataTable, "/IslandAuctionKing/Asset/Data/Table/Customized/UI/UIConfigTable")
new_row = table_obj.data_table_empty_row()
new_row.ValueType = "int"
new_row.Value = "10"
new_row.Description = "新功能的数量上限"
new_row.ModificationNotes = "边界：整数 >= 1。生效：重新 PIE。"
table_obj.data_table_add_row("UI.NewFeature.MaxCount", new_row)
table_obj.save_package()
```

实测补充（2026-08-26）：`set_field(字段名, 值)` 是已验证的赋值形式；`data_table_add_row` 成功时返回 `None`，不能用返回值判定成功，必须重新 `load_object` 回读。新建表还需先 `objed_open_editor('DataTable')`，并把默认 bool 列换成 4 列结构。

详见 [蓝图与 MCP 写入流程](../工具与流程/蓝图与MCP写入流程.md)、[配置表与结构体的 MCP 编辑](../工具与流程/配置表与结构体的MCP编辑.md)。

## 七、不适合进配置表的值

- 纯算法常量（PI、UTF-8 掩码）
- 不影响玩法平衡、UI 布局、测试行为的固定值
- 后续不可能调整的值

---

## 八、实战示例：图鉴 UI

`20260824` 记录中，9 张贴图的资源路径全部登记为 `UI.Codex.Texture.*` 配置项，卡片尺寸登记为 `UI.Codex.ItemWidth` / `ItemHeight`；脚本用辅助函数 `GetCodexTexture(key, fallbackPath)` 优先读配置、失败回退，再由 `ApplyVisualTheme` 统一绑定贴图。

## 九、验证

配置表修改后必须**重新调试 PIE**，PIE 运行中的修改不生效。观察加载日志与功能脚本日志确认读到正确值，见 [PIE 调试与热更新边界](../工具与流程/PIE调试与热更新边界.md)。
